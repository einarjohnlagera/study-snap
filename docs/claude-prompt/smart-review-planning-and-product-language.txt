# Product Philosophy

NoteLib is **not** trying to become "another AI app."

We want to become:

> **The smartest study platform.**

Students don't open NoteLib because they want AI.

They open NoteLib because they want to:

- Pass their board exam
- Understand difficult concepts
- Build confidence
- Study more efficiently

Therefore our guiding philosophy is:

> **Sell outcomes, not AI.**

AI should quietly power the experience behind the scenes.

The product should feel intelligent without constantly reminding users that AI is involved.

The student should feel like:

> "This app understands how I study."

—not—

> "This app has AI."

# Current Product

Users can currently:

- Create Notes
- Generate Study Packs
- Practice Quizzes
- Review Key Concepts
- Copy Public Notes
- Copy entire Study Packs
- Join Official Review Sets
- Create personal Review Sets

The Public Library continues to grow every day.

Official Review Sets are currently curated manually.

---

# Current Manual Admin Workflow

Today our workflow is extremely manual.

1. Generate Public Notes for a course/program.
2. Publish those notes.
3. Create a Review Set.
4. Create Subject Plans manually.
5. Find and attach Notes to each Subject Plan.
6. Generate missing Notes if needed.
7. Publish.

For a large licensure exam this easily becomes:

- 50+
- 100+
- sometimes 200+

notes.

Whenever a required topic doesn't exist, the workflow stops until that note is manually created.

This process doesn't scale.

---

# New Vision

Instead of manually assembling Review Sets...

We want NoteLib to intelligently assemble them.

Example:

User requests:

> Civil Engineering Review

↓

System determines the recommended curriculum.

↓

Searches the Public Library.

↓

Already available

82 concepts

↓

Missing

18 concepts

↓

Generate only the missing concepts.

↓

Assemble Review Set.

↓

Ready to study.

The philosophy becomes:

> **Reuse first. Generate second.**

# Two Different Intelligence Systems

We believe these should become two completely different experiences.

---

## 1. Internal Curator (Admin)

Used only by NoteLib admins.

Responsibilities:

- Create Official Review Sets
- Detect curriculum gaps
- Recommend missing notes
- Generate missing notes
- Improve Public Library coverage
- Suggest subject plans
- Maintain official learning paths

This is an internal productivity tool.

---

## 2. Learning Assistant (Student)

Used by learners.

Responsibilities:

- Organize Review Sets
- Recommend existing notes
- Build personalized study journeys
- Reuse existing Study Packs
- Generate only what is missing
- Adapt to the learner

The learner never thinks about AI.

They simply experience an intelligent study platform.

---

# Knowledge Reuse Philosophy

We've already discovered something valuable.

Instead of copying only Public Notes...

Users can copy the entire Study Pack.

Meaning:

Generated once.

↓

Reused forever.

↓

Huge LLM savings.

We believe Review Sets should follow the exact same philosophy.

The more knowledge exists...

the smarter and cheaper the platform becomes.

We intentionally want to avoid calling features "AI."

Students don't buy AI.

# Reconciliation note (added by Claude Code, not part of the original brief)

This vision's "Learning Assistant" auto-assembly flow (student types a goal, system assembles a
Review Set) sits directly against a locked anti-drift rule already in the codebase:
**"Curation, never generation" — a learner never receives an auto-generated plan** (see
`docs/product/ROADMAP.md`, v0.31.0 and reaffirmed through v0.43.1). This brief's own
"Two Different Intelligence Systems" split (Internal Curator vs. Learning Assistant) is the
resolution: auto-assembly/generation stays admin-facing with mandatory human review before
publish; the student-facing side stays recommend/reuse-only. Any plan produced from this brief
must preserve that split rather than re-litigate it.

Also relevant, already established and not something this brief needs to re-derive from scratch:
- `docs/product/ROADMAP.md`, "Future, gated — AI-generated Review Sets" — an earlier, smaller-scope
  seed of this same idea (public notes → suggest Subject Plans → map notes → generate Companion →
  human review → publish), gated on the v0.42.0 authoring-assist pipeline proving out.
- `docs/product/ROADMAP.md`, "Monetization philosophy" — already draws a FREE-static /
  PLUS-interaction / PRO-personalization line that this brief's Q7 (Subscription Strategy) should
  extend, not contradict.
