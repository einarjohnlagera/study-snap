# Retention Root-Cause Diagnosis — Consumer Psychology / Behavioral Economics Lens (Fable)

Source: Fable session, 2026-07-15, role-framed as a consumer psychology / behavioral economics expert (Hook Model, Fogg Behavior Model, loss aversion, implementation intentions). Same production data as the growth-diagnostician session (W1→W2 retention: 2.4%, 3/127; prior read 5.6%, 2/36), independently sourced — no shared context between the two sessions.

---

## Diagnosis: the product ends where the habit would need to begin

Before the five questions, one framing observation that everything else hangs on: **the first session terminates in a state of psychological completion.** The user came with a job ("turn my notes into something study-able"), the product did the job instantly and well, they took a quiz, they got a score. Loop closed. The Zeigarnik effect — the tendency for *unfinished* tasks to intrude on memory and finished ones to be released from it — is working against retention: a completed Study Pack plus a completed quiz is a *finished* task, and finished tasks are forgotten. The 69% activation → 59% first-loop numbers aren't a retention asset; they're evidence the product delivers a clean, satisfying *ending*. Everything below is a variation on that theme.

One measurement caveat first, as honesty demands: 3/127 vs. 5.6% weeks earlier is within noise at these cohort sizes. Don't conclude the retention releases *hurt*. Do conclude they didn't help — and they couldn't have, structurally: streaks, mastery trackers, pacing, and opt-in digests are all **behind the door**. They can only reinforce a return that has already happened. The product shipped in-session mechanics to fix an out-of-session problem.

---

### 1. Trigger analysis: necessary but not sufficient

Yes, the trigger layer is close to nonexistent. In Fogg's terms, behavior requires Motivation × Ability × **Prompt** converging in a moment — and in week 2 users receive exactly one prompt: a generic "you've been inactive" email. That email is the weakest possible trigger class: sender-framed (about the product's metric, not the user's state), content-free (references nothing they own), and timed by *absence* rather than by anything happening in their life. The emails that would work — "3 concepts from *Pharmacology Week 4* are due" — are opt-in and default-off, which means they're gated behind engagement, which is the exact thing that's missing. That's a bootstrapping paradox: the trigger requires the habit that the trigger is supposed to build.

But fixing triggers alone won't reach healthy retention, because of the completion problem above. A trigger pulls on an **open loop**. If the user's mental model is "I used that tool and it worked," a reminder lands as *marketing*, not as a cue to resume something. Trigger absence explains why retention is near-zero instead of merely bad; the closed-loop first session explains why it would still be bad even with triggers.

### 2. Motivation analysis: "due concepts" is the system's obligation, not the user's

"You have 3 due concepts" is a claim generated by the model, about an abstraction (*concepts*) the user never explicitly committed to, with no felt cost of ignoring it. Spaced repetition is epistemically correct and motivationally inert — Anki's retention problem is legendary for exactly this reason. It becomes motivating only when anchored to one of two things:

- **A loss frame on something the user built.** The user *earned* 74% mastery on a concept in session one. That's an endowment. "Your mastery on Fluid & Electrolytes has dropped from 74% to 58% — the forgetting curve is real" converts abstract "due-ness" into concrete loss of owned progress. Loss aversion says this is roughly twice as motivating as the equivalent gain frame ("review to improve"). Loss-aversion-*via-others* (social comparison) is explicitly excluded by the product team — fine, and probably right for this audience — but loss aversion **against the user's own past self** is available and unused. This is the variable-reward gap solved a different way: no slot machines needed; the mastery number just needs to be *alive* (it can go down), which makes checking it inherently uncertain.
- **Identity + date.** The best-fit users aren't generic "students" — they're *reviewees* and *takers*, with a fixed, high-stakes, publicly-known exam date and an identity built around preparing for it. "Your exam is coming" as generic copy is weak; "you are 34 days from the ALE and behind your own plan on 12 concepts" is strong — but only if a *plan* exists to be behind on. A user cannot be behind on a pace they never committed to. The countdown mechanic currently displays a fact; it doesn't reference a promise.

So: "due concepts" is not strong enough on its own, and it needs anchoring — specifically to endowed progress (loss frame) and to a user-made commitment (see #5).

### 3. Ability analysis: the return visit is a decision, not an action

Separate from UI polish: what does a week-2 return *cognitively require*? (a) Remember the app exists — no home-screen presence beyond an optional PWA icon, no notification channel. (b) Reconstruct context — "what was I studying, which note, which pack?" (c) **Choose** — among 5 quiz modes, review sets, a study plan, a companion, a mastery tracker. For a returning user that's a decision tree, and decisions are the expensive part of Fogg's Ability axis. First-session users didn't face this: their path was linear (paste → generate → quiz). Returning users face an open-world menu.

There's also an *input-side* ability problem: the core loop's fuel is *new notes*. If nothing new happened in class this week, the return proposition silently degrades to "self-direct a review of old material," which is higher effort and lower salience than the first session was. The product's easiest action requires an ingredient the user may not have on hand.

The fix-shaped implication (not a spec): the return action must be pre-decided — a single resumable object ("today's 5-minute review, already built") rather than a workspace to re-enter. Any trigger should deep-link into the *doing*, never onto a dashboard.

### 4. Single-serving-utility risk: real, but not a full ceiling

Yes, the shape is currently experienced as single-serving: input → artifact → score → done. That's the PDF-converter pattern, and PDF converters famously have great activation and no retention — *and there's nothing wrong with them*, their job is single-serving. The risk is that NoteLib's *transactional layer* (note → pack) is what users enroll in, while its *longitudinal layer* (mastery, spacing, pacing) is a second product they never psychologically sign up for.

Is it a structural ceiling? **Split verdict:**

- For **exam-dated users** (nurses, teachers, board reviewees): no ceiling. Their underlying job — "be ready on date X" — is inherently longitudinal, multi-week, and high-stakes. The failure is a *conversion* failure: the product never converts "tool user" into "program enrollee." That's specific and fixable.
- For **anchor-less students** who dumped one lecture's notes with no exam date: yes, a partial structural ceiling. Their motivation is episodic (spikes before each test) and no habit mechanic will make weekly use rational for them. The right psychological goal for that segment is **resurrection at the next motivation peak** ("midterms coming? your October notes are still here, pre-quizzed"), not weekly habit. Trying to habit-loop them will just depress the metrics and the morale.

Calibration: 2.4% is far below what this category supports — study tools with real habit loops (Anki, Quizlet during term) see W2 in the 10–25%+ range for activated users. Most of the gap is mechanism-shaped, not category-shaped.

### 5. The single highest-leverage missing lever: **implementation intentions as a commitment device, made at the peak-motivation moment**

Not variable reward, not streaks, not social. The mechanism: Gollwitzer's implementation-intentions research shows that converting a goal ("I'll study for the boards") into an *if-then plan* ("I will review due concepts at 8pm on Mon/Wed/Fri until my exam") roughly doubles follow-through versus goal intention alone (meta-analytic d ≈ 0.65) — one of the most robust effects in behavior science. Commitment/consistency means a schedule the *user authored* creates self-imposed obligation that a system-generated "due" flag never will.

Why this lever, for this audience specifically:

- **The moment exists.** End of session one — pack generated, quiz taken, competence just demonstrated — is the highest-motivation moment this user will ever have in the product. It's currently spent on... a score screen. That's where the commitment ask belongs.
- **The deadline is real.** Commitment devices fail when the commitment feels arbitrary. A board-exam date is not arbitrary; a plan backing off from it (N concepts ÷ days remaining = pace) is *arithmetic*, not nagging.
- **It's culturally native.** Board reviewees in this market already live inside review-center schedules; scheduled review is the expected norm of their identity, not an imposition. This isn't creating a behavior, it's claiming a slot in an existing one.
- **It solves three diagnoses at once:** it manufactures consented, specific, user-timed triggers (fixes #1 without feeling like spam); it creates the promise that loss-framed pacing can reference (fixes #2 — the user can now be *behind*); and it reframes the product from tool to program at the moment of enrollment (fixes #4).

## Testable hypotheses (mechanism-grounded, not a build spec)

- **H1 — Commitment at peak motivation:** users asked at end of session one to set exam date + review days/times (with consented email at those times, content = named due concepts) will show materially higher W2 than the 3-day inactivity email. Secondary read: the opt-in *rate* at this moment vs. Settings-buried opt-in tells you how much of the digest problem was placement.
- **H2 — Default-on, specific, well-timed digest:** flipping the due-concepts digest to default-on for new users (easy opt-out), with content naming their own material ("3 concepts from *Pharma Week 4* are fading — 4 min"), beats generic inactivity email on open→session conversion. Cheapest test on this list; run it first.
- **H3 — Visible forgetting / loss-framed decay:** messaging built on endowment loss ("mastery dropped 74% → 58%") outperforms gain-framed equivalents ("review to strengthen"). Constraint: decay shown must reflect the actual model — manufactured loss will be smelled and will poison trust with an exam-anxious audience.
- **H4 — Open-loop session endings (Zeigarnik):** ending session one on an explicitly *incomplete* state ("2 of 9 concepts secured; the next 3 are best reviewed tomorrow") rather than a terminal score raises unprompted return. Tests whether the completion-framing diagnosis is right independent of any email.
- **H5 — Pre-decided return action:** all triggers deep-link into an already-assembled 5-question due-review session (one tap to first question) vs. linking to the dashboard. Measures the Ability tax directly as trigger→first-answer conversion.
- **H6 — Segmentation falsification test:** split cohorts by has-exam-date vs. not. If exam-dated users *don't* retain meaningfully better even under H1–H3, the motivation story above is wrong and there's a purer trigger/product-shape problem than argued here. This is the cheapest way to check the whole diagnosis against real data.

**Bottom line:** this is not a retention feature gap; it's a *narrative* gap. The product currently tells the user a complete story in one sitting — problem, solution, score, the end. Retention requires the first session to end in the *middle* of a story the user has committed to finishing, with a scheduled next chapter and something already-earned at stake. For the exam-dated core, that's fully achievable with the mechanisms above. For anchor-less note-dumpers, accept the episodic ceiling and design for resurrection, not habit — and stop letting that segment drag the read on whether the product works.
