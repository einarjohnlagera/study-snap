# v0.71.0 — signoff pressure test findings

**Run 2026-08-09** against `releases/v0.71.0` at `fd406163` (36 non-merge commits ahead of `main`), after all
release scope had merged. Four independent cold-context agents: `RELEASES.md` completeness, backend, frontend,
documentation accuracy. Synthesised and challenged via `advisor`; every finding acted on below was
**re-verified against the code by the synthesising session** rather than accepted from the report.

**This is the second pressure test.** The first (`v0.71.0-pre-signoff-pressure-test.md`) ran against
`b75c49c8`, which five slices, two migrations and a flow restructure ago. It is retained; this one covers the
state that actually ships.

## Why this run existed, and what it justifies

It found a **shipping migration bug** (F1) that the release's own migration self-check could not detect, plus
five defects in code written during the same week. That is the case for the whole-release view: none of these
were visible in the diff of the change that introduced them.

## Deferred to `v0.71.1` — these need a decision, not a patch

- **F5 — `NoteApplicableProgramsService.replace` reopens F1's class post-deploy.** An admin can set catalog
  programs on any learner's note, and `NoteService.update`'s learner branch never clears them — the same
  permanent override, by ordinary admin action. Architectural: fixing V108 alone does not close the class.
- **Frontend #5 — a learner sees inherited programs on their own note that they cannot edit.** The applicable
  programs fetch is gated on `note?.id`, not on `canEditAuthoringMetadata`, and the endpoints allow
  `ROLE_USER`. The learner is forced to fill a required Course / Program whose value then has no visible
  effect, because discovery still reads the inherited join rows. **Touches the ratified "do not expose
  Applicable Programs to learners" ruling** — needs a product answer, not a patch.
- **F3 — `NoteBulkGenerationService.normalizeAndValidate` still uses the bare curator predicate**, unlike the
  two fixed in `adfa797f`. Not reachable through the UI (`requireAuthenticatedOnboardedUser` redirects
  mid-onboarding users away from bulk generate and the editor), so the inconsistency survives regardless of
  current reachability.
- **F4 — AI-suggestion apply dead-ends on a copy of a curated note.** `applySuggestions` sends
  `courseProgramText` from stored state, not a form field, so a learner with a null profile program hits
  `CourseProgramSelectionRequiredException` with no field on that surface to fix it. Narrow population.

Also carried, from the frontend agent:

- **Frontend #4 — the deferred-completion marker is never retried, and the comment says it is.** Nothing
  re-POSTs `completeOnboarding`; the marker only suppresses the redirect. Pre-existing, but
  `completeOnboardingAndLeave` is a new call site, so this release increases exposure. Its amplifier:
  that exit is the only terminal one that does not `clearOnboardingDraft`. **The comment claiming a retry is
  corrected in #1014; the retry itself is deferred.** Verified not to affect the Diagnostic Read, which keys
  on the analytics event (fired in `finally` on every path), not on `onboardingCompletedAt`.

## The pattern worth carrying forward

**Three findings in this release were "a change increases exposure to pre-existing code"** — the exam hub
(B3c), the adopt path's missing qualifying predicate, and KaTeX's `aria-hidden` output going from working
solutions to every question in the app. A diff-scoped review structurally cannot see this class. Point future
pressure tests at it explicitly.

**Six tests were found asserting a defect as the contract** — B0's payload, C1's `never().replace()`, C7's
"restores the saved selection", the `listPublicStudyPlans`-never-called assertion, the explore-URL raw value,
and V108's "a row on a copy must survive". The last two were written by the session fixing the very findings
they then encoded. A passing test is a question.

**The LaTeX completeness claim was falsified three times.** The failure was never the grep. It was inheriting
a scope boundary from the finding instead of deriving it from where the content comes from — `buildFlashcardDeck`
reads `item.explanation` off the quiz array, so "cards, not quiz content" was simply untrue. Named here because,
unnamed, it predicts a fourth occurrence.
