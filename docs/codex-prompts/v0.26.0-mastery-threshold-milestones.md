## TASK

Add mastery-threshold milestone markers to the `/progress` goal view so learners can see discrete checkpoints on their path from zero to goal mastery.

## GOAL

The current goal summary shows a single mastery percentage (e.g. "42% mastered") but no sense of progression or next target. Milestones give the learner a visible trail of achievable checkpoints — "you've passed 25%, your next target is 50%" — making the goal feel actionable and trackable across sessions.

## CONTEXT

The `/progress` page already has a `GoalSummaryHeader` card that renders the goal name, mastery %, and concept counts. The `GoalSummaryResponse` is already returned from `GET /me/progress` and includes `masteryPercentage`, `masteredConcepts`, and `totalConcepts`. The `ProgressReportService` already computes `ConceptCounts` (which includes `notPracticedConcepts`) for the goal — it's just not exposed in the DTO.

**Milestone design (6 fixed checkpoints in order):**
1. First concept mastered — `masteredConcepts >= 1`
2. 25% mastered — `masteryPercentage >= 25`
3. All concepts reviewed at least once — `notPracticedConcepts === 0 && totalConcepts > 0`
4. 50% mastered — `masteryPercentage >= 50`
5. 70% mastered — `masteryPercentage >= 70`
6. All concepts mastered — `masteryPercentage >= 100`

Milestones are computed entirely from `GoalSummaryResponse` fields — no new endpoint, no new service method, no new DB query. The only backend change is surfacing `notPracticedConcepts` in the existing DTO.

**Anti-drift (locked from v0.24.0/v0.25.0):** milestones must be derived from ConceptHealth mastery data only — never a generated syllabus, never targets the AI sets, never a progression system not rooted in actual quiz performance. The milestone thresholds are hardcoded constants, not LLM output.

**What is explicitly OUT of scope:**
- No per-subject milestone breakdown (goal-level only).
- No persistence of milestone state — compute on every load from the live response.
- No notifications, badges, or celebration animations.
- No changes to `ConceptHealthService`, quiz flows, or dashboard.
- Do not touch `GoalNudgeResponse` (used by the dashboard nudge separately).

**Existing patterns to reuse:**
- `progress-report-client.tsx` — the milestones card goes between `GoalSummaryHeader` and `NextStudyCard`.
- Progress bar pattern from `SubjectProgressCard` (`h-3 overflow-hidden rounded-full bg-muted`).
- The page already uses `"use client"` — no new client/server split needed.

- No other backend files need to change.

**Frontend**

- `frontend/lib/api.ts` — add `notPracticedConcepts: number` to the `GoalSummaryResponse` type.
- `frontend/app/progress/progress-report-client.tsx`:
  - Define a `MILESTONES` constant (array of `{ label: string; reached: (g: GoalSummaryResponse) => boolean }`).
  - Add a `GoalMilestonesCard` component that renders the 6 milestone markers. It takes `goalSummary: GoalSummaryResponse` as its only prop.
  - Insert `<GoalMilestonesCard goalSummary={goalSummary} />` between `GoalSummaryHeader` and `NextStudyCard` in `ProgressContent`. Only render when `goalSummary.totalConcepts > 0`.
- No other files need to change.

**Milestone card visual spec:**
- Render milestones as a horizontal (or wrapping) row of step indicators.
- Each indicator: small circle icon + label text.
  - Completed milestone (`reached === true`): filled circle (e.g. `bg-blue-600`), label in normal foreground.
  - Next milestone (first `reached === false`): outlined circle with a ring highlight (e.g. `ring-2 ring-blue-500`), label in foreground — this is the active target.
  - Future milestones (all others after the next): muted circle (`bg-muted`), label in `text-foreground/50`.
- Below the milestone row, show a progress bar spanning from milestone 0 to milestone 6, filled to the current highest-reached milestone index (e.g. if 2 of 6 are reached, bar is at ~33%).
- Card title: "Goal Milestones"

## ERROR STATES

- `goalSummary` is null → `GoalMilestonesCard` is not rendered (handled by the existing null-check in `ProgressContent`).
- `totalConcepts === 0` → do not render `GoalMilestonesCard` (no concepts tracked yet; milestones would all be trivially false or misleading).
- `notPracticedConcepts` missing from API response (e.g. older cached response) → milestone 3 ("All concepts reviewed") uses `(g.notPracticedConcepts ?? 1) === 0`, so it simply stays unreached rather than crashing.
