## TASK

Add a 90-day Pro access tier ("Exam-Cycle Pass") as a new `EXAM_CYCLE` billing cycle so board exam takers can commit to a 90-day prep window at ₱599 PH instead of paying ₱249/month three times.

## GOAL

Board exam reviewers study in bursts aligned to their exam date — typically 60–90 days. Monthly billing doesn't match this mental model. An exam-cycle pass lets them commit once ("I'm prepping for the June ALE") at a meaningful discount (₱599 vs ₱747 for 3× monthly) while keeping full Pro access and monthly quota resets for the duration.

## CONTEXT

The billing system already handles duration-based access: subscriptions use `endAt`-based PREPAID grants, and `BillingUsageResetJob` resets monthly quotas independently of the billing cycle. Adding `EXAM_CYCLE` slots into this existing model — the activation and quota-reset logic are unchanged.

The config-driven pricing architecture means the change is mostly structural: new `BillingCycle` value, new `examCycle` field on the config and response objects, new config entries in `application.yaml`, and a new checkout option in the frontend billing UI.

**What is explicitly OUT of scope:**
- No changes to subscription activation, webhook handling, or `BillingUsageResetJob` — the PREPAID + `endAt` model already handles 90-day access correctly.
- No Xendit integration changes — creates a fresh invoice, same as MONTHLY/YEARLY.
- No paywall modal change — paywalls surface MONTHLY pricing; exam cycle is a committed purchase surfaced in settings and pricing sections.
- No exam cycle for Plus — Pro-only tier.
- No static fallback in `pricing-config.ts` for exam cycle — only show the option when live API data confirms `examCycle.available === true`.
- No change to `SimplePricingSection` (landing page) — keep the landing page pricing simple.

**Key implementation notes:**
- `EXAM_CYCLE` maps to `paidPlanPricing.getExamCycle()` in `PricingService.resolveCyclePricing()`.
- `buildPlanPricing()` includes `examCycle` alongside `monthly` and `yearly` in the response.
- The frontend resolves `"EXAM_CYCLE"` → `planPricing.examCycle` in `resolveCyclePricing()`.
- Exam cycle is Pro-only in the UI — the `examCycle` config entry for Plus can exist but must be `active: false`.
- The settings page currently derives `subscriptionBillingCycleLabel` as `YEARLY ? "Yearly" : "Monthly"` — update to include `EXAM_CYCLE → "90-Day Exam Pass"`.

## ERROR STATES

- `billingPricing` not yet loaded (null) → exam cycle button not shown (gated on `?.available`); no crash.
- `examCycle.active === false` in config → `CyclePricing.available === false` from backend → button not shown in UI; no backend path to create a checkout for it.
- User requests `EXAM_CYCLE` checkout for Plus → `PricingService.resolveCheckoutSelection()` calls `resolveCyclePricing()` which returns the Plus `examCycle` config (inactive) → throws `CHECKOUT_BILLING_CYCLE_UNAVAILABLE` as with any inactive cycle — same guard, no new handling needed.
- `EXAM_CYCLE` not recognized by `matchesCycle()` before fix → vouchers silently skip it; fix adds the explicit case so vouchers scoped to `EXAM_CYCLE` apply correctly.
