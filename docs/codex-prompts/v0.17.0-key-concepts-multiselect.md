Fix the intermittent key concepts generation failure and add multi-select

## GOAL

Reduce user-facing generation failures caused by LLM key concept field
mismatches, and introduce multi-select questions to add format variety for
notes with multi-attribute concepts (e.g. laws with multiple clauses,
lists of properties). Multi-select is available on all plans — it is a
quiz quality improvement, not a premium feature.

---

## CONTEXT

**Key Concepts Fix**

`generateStudyPack` already calls `retryOnceOnInvalidOutput`, so a retry
path exists. The remaining mismatch is between the JSON schema constraint
(`minItems: 8`) and Java validation (`MIN_VALID_KEY_CONCEPTS = 5`): the
schema forces OpenAI to always return ≥8, but when it deviates the Java
code accepts down to 5 — the two ends are not aligned. Additionally, the
`PromptStudyPack` inner record deserializes `keyConcepts` by exact field
name match only, so LLM responses that return `key_concepts` will silently
produce null and throw before the retry.

Fixes required:
1. `schema.json keyConcepts.minItems`: change 8 → 5 so the JSON schema
   constraint aligns with `MIN_VALID_KEY_CONCEPTS = 5` in
   `normalizeAndValidateKeyConcepts`.
2. Add `@JsonAlias("key_concepts")` on the `keyConcepts` component of the
   `PromptStudyPack` inner record so field-name deviations are coerced
   rather than silently dropped.
3. In `developer.txt`, tighten the keyConcepts prompt instruction:
   - Must use the field name `keyConcepts` (not key_concepts)
   - Each item must be 1–4 words, plain text string, no quotes or nesting
   - Minimum 5 items, maximum 10 items

No other changes to `normalizeAndValidateKeyConcepts` or the retry
mechanism are needed.

**Multi-Select Questions**

`QuizItem` already has a `questionFormat` field (`"MCQ"` | `"TRUE_FALSE"` |
null). Multi-select extends this by adding `"MULTI_SELECT"` as a valid
value and a new `correctIndices: List<Integer>` field on `QuizItem`.

Design decisions:
- 4 choices always (same constraint as MCQ) — `QuizValidationUtils` choice
  count check remains unchanged.
- `correctIndices` contains 2–3 of the 4 choice indices that are correct.
  v1 does not support 4-of-4 correct ("all of the above").
- Scoring: all-or-nothing v1. A multi-select question is correct only if
  the user selected exactly the same set as `correctIndices`, no more, no
  less.
- Session state: add a parallel `selectedMultiChoices` JSONB key
  (`Map<Integer, List<Integer>>`) in `QuizSessionStateUtils`. The existing
  `selectedChoices` key is unchanged.
- `correctIndex` on `QuizItem` should be set to `correctIndices.get(0)`
  for MULTI_SELECT items so legacy code paths (sharing, export, review
  utils) that only read `correctIndex` see a valid single-answer fallback.
- Do NOT add multi-select to the Board Exam prompt — PH licensure MCQ is
  single-correct. All other modes (Quick Review, Challenge Quiz, Adaptive
  Practice, Long Exam, Teacher Quiz) may include multi-select.
- Generate at most 1–2 MULTI_SELECT questions per quiz batch. Use for
  concepts that have multiple defining attributes (e.g., enumerate all
  correct properties of X, list which items belong to a category).
- Multi-select is plan-agnostic (available on Free, Plus, and Pro).

Anti-drift rules from AGENTS.md that apply:
- `QuizSessionStateUtils` owns all reads/writes to session state JSON.
  Do not manipulate the JSON directly in service code.
- `QuizValidationUtils.hasInvalidChoices()` hard-checks `choices.size() != 4`.
  Do not relax this for multi-select (choices always stay at 4).
- Do not add multi-select to Board Exam prompts.
- `@JsonIgnoreProperties(ignoreUnknown = true)` is already on `QuizItem`;
  do not remove it.

**CRITICAL ANTI-DRIFT RULES — must be implemented exactly as specified:**

1. **Board Exam schema call must explicitly pass `false`.**
   In `OpenAiLlmStudyPackService`, the Board Exam code path that calls
   `buildGeneratedQuizSchema(questionCount, allowTrueFalse)` MUST pass
   `false` as the second argument — not the default, not a variable that
   could be true. Passing the default (which is `true`) would allow
   MULTI_SELECT to be emitted in Board Exam sessions.

2. **`quiz-session-export.ts` — per-choice `isSelected` must handle MULTI_SELECT.**
   In `buildQuestionReviewItems`, the `.map((choice) => ...)` that builds
   `choices[].isSelected` must NOT use `selectedChoiceIndex` for
   MULTI_SELECT items — `selectedChoiceIndex` is null for MULTI_SELECT and
   will mark every choice as not selected in the PDF/review export.
   Required logic:
   ```ts
   isSelected: item.questionFormat === "MULTI_SELECT"
     ? (selectedMultiChoices[index] ?? []).includes(choice.canonicalIndex)
     : choice.canonicalIndex === selectedChoiceIndex,
   ```

3. **Challenge quiz `onSelectMultiChoices` — avoid stale closure.**
   Inside `setSelectedMultiChoices`'s updater function, do NOT use
   `selectedChoices` from the render closure when calling `syncProgressRef`
   and `persistProgress`. Use `progressRef.current.selectedChoices` instead.
   The `progressRef` is the reliable source of latest state inside setters.
   Wrong: `syncProgressRef(currentIndex, selectedChoices, next)`
   Correct: `syncProgressRef(currentIndex, progressRef.current.selectedChoices, next)`

4. **`LongExamService.saveProgress` — empty deselect must clear, not skip.**
   The guard for writing multi-select to session state must NOT have the
   `!isEmpty()` condition — it prevents clearing when the user deselects all
   choices, leaving a stale answer in the session state.
   Wrong: `if (request.selectedMultiChoiceIndices() != null && !request.selectedMultiChoiceIndices().isEmpty())`
   Correct: `if (request.selectedMultiChoiceIndices() != null)`
   `QuizSessionStateUtils.withSelectedMultiChoice` already normalizes an
   empty list to `[]`, which is the correct cleared state.

5. **Board Exam runtime — `onSelectMultiChoices` must be a no-op.**
   In challenge-quiz page, `onSelectMultiChoices` must return early when
   `isBoardExamMode` is true. The `questionFormat` prop override
   (`isBoardExamMode ? "MCQ" : currentQuestion.questionFormat`) is also
   required so the component never renders multi-select UI in Board Exam.

## ERROR STATES

- LLM returns `correctIndices` with only 1 item for a MULTI_SELECT
  question → `QuizValidationUtils` should reject (MULTI_SELECT requires
  ≥2 correct indices); `retryOnceOnInvalidOutput` handles the retry.
- LLM returns `correctIndices` with an index out of range (>= choices.size())
  → reject the question item in validation; do not fail the whole study pack.
- User submits a MULTI_SELECT question with no selections → treat as
  unanswered; do not mark correct or incorrect; do not advance to next
  question.
- Session state with old `selectedChoices` format loaded for a session
  that now contains MULTI_SELECT questions → `readSelectedMultiChoices`
  returns empty map; MCQ selections in `selectedChoices` remain intact.
- `correctIndices` null/absent on a MULTI_SELECT question at review time
  → show "Answer unavailable" in review; do not crash.
