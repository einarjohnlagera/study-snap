## TASK

Add an admin-only `/admin/funnel` page that shows five key conversion funnel metrics computed from existing tables — no new tracking infrastructure, no new migrations.

## GOAL

The admin currently has no visibility into where users drop off in the signup → generate → practice → upgrade loop. These five metrics answer the most actionable question first: are users even reaching the core value before deciding not to pay?

## CONTEXT

### Decisions made

- **Five metrics only** — nothing else for v1. Do not add charts, time-series, or date-range filters.
- **No new migrations** — all metrics derive from existing tables: `users`, `study_packs`, `notes`, `analytics_events`, `user_usage`, `subscriptions`.
- **No new analytics events** — existing `AnalyticsEventType` values cover everything needed. Do not add to the enum.
- **Read-only service** — `@Transactional(readOnly = true)` on the service class. No writes.
- **Admin-only** — `@PreAuthorize("hasRole('ADMIN')")` on the controller, same as `AdminDashboardController`.
- **Separate controller and service** — do not add to `AdminDashboardController` or `AdminDashboardService`; create `AdminFunnelController` and `AdminFunnelService`.
- **Single endpoint** — `GET /admin/funnel/metrics` returns all five metrics in one payload.
- **New frontend page at `/admin/funnel`** — follows the same layout and component conventions as `frontend/app/admin/campaigns/page.tsx`.
- **Add a "Funnel →" nav link** in the admin dashboard header (same pattern as the existing "Campaigns →" link in `frontend/app/admin/page.tsx`).

### The five metrics

| # | Metric | What it reveals |
|---|---|---|
| 1 | **Activation rate** | % of verified users who have generated at least one Study Pack; median days from signup to first generation | Are users reaching the core value? |
| 2 | **Stuck before generation** | Count of verified users who have notes older than 7 days but zero Study Packs | "Has content, never generated" — onboarding friction |
| 3 | **Free quota hit rate** | % of free users (no active PLUS/PRO) whose current-period `studyPackGenerations >= freeMonthlyStudyPackLimit` | Are free users even reaching the paywall? |
| 4 | **Paywall conversion rate** | % of users who fired `PAYWALL_VIEWED` and later fired `SUBSCRIPTION_STARTED` | Is the paywall compelling? |
| 5 | **Value loop closure rate** | % of users who generated a Study Pack AND started a quiz within 7 days of their first generation | Do users close the practice loop? |

## REQUIRED CHANGES

### Backend

**New DTO: `AdminFunnelMetricsResponse.java`**

A single response record containing five nested objects:

```java
public record AdminFunnelMetricsResponse(
    ActivationMetrics activation,
    StuckUsersMetrics stuckUsers,
    QuotaHitMetrics quotaHit,
    PaywallConversionMetrics paywallConversion,
    ValueLoopMetrics valueLoop
) {
    public record ActivationMetrics(
        long totalVerifiedUsers,
        long activatedUsers,
        double activationRatePercent,
        Double medianDaysToFirstPack   // null when no activations yet
    ) {}

    public record StuckUsersMetrics(
        long stuckUsersCount
    ) {}

    public record QuotaHitMetrics(
        long freeUsersHitQuota,
        long totalFreeUsers,
        double ratePercent
    ) {}

    public record PaywallConversionMetrics(
        long usersSeenPaywall,
        long usersUpgradedAfterPaywall,
        double ratePercent
    ) {}

    public record ValueLoopMetrics(
        long usersGeneratedPack,
        long usersStartedQuizWithin7Days,
        double ratePercent
    ) {}
}
```

Rate fields: compute as `activatedUsers * 100.0 / totalVerifiedUsers` (with a zero-denominator guard returning `0.0`). Round to one decimal place.

**New service: `AdminFunnelService.java`**

`@Service @Transactional(readOnly = true) @RequiredArgsConstructor`

Single public method: `AdminFunnelMetricsResponse getMetrics()`

Inject: `UserRepository`, `NoteRepository`, `StudyPackRepository`, `AnalyticsEventRepository`, `UserUsageRepository`, `SubscriptionRepository`, `StudySnapProperties`.

Query guidance for each metric:

**Metric 1 — Activation:**
- `totalVerifiedUsers`: JPQL `SELECT COUNT(u) FROM UserEntity u WHERE u.emailVerifiedAt IS NOT NULL`
- `activatedUsers`: JPQL `SELECT COUNT(DISTINCT sp.ownerUserId) FROM StudyPackEntity sp`
- `medianDaysToFirstPack`: Use a native SQL `@Query` in the relevant repository (or as a `@NativeQuery` via `EntityManager`):
  ```sql
  SELECT PERCENTILE_CONT(0.5) WITHIN GROUP (
      ORDER BY EXTRACT(EPOCH FROM (fp.first_at - u.created_at)) / 86400.0
  )
  FROM users u
  JOIN (
      SELECT sp.owner_user_id, MIN(sp.created_at) AS first_at
      FROM study_packs sp
      GROUP BY sp.owner_user_id
  ) fp ON u.id = fp.owner_user_id
  WHERE u.email_verified_at IS NOT NULL
  ```
  Returns `Double` (null when the table is empty). Cast the result to `Double` before returning.

**Metric 2 — Stuck users:**

JPQL `@Query` on a repository:
```
SELECT COUNT(DISTINCT n.ownerUserId) FROM NoteEntity n
WHERE n.createdAt < :cutoff
AND NOT EXISTS (
    SELECT 1 FROM StudyPackEntity sp WHERE sp.ownerUserId = n.ownerUserId
)
```
where `:cutoff = OffsetDateTime.now().minusDays(7)` passed from the service. Only count verified users: add `AND EXISTS (SELECT 1 FROM UserEntity u WHERE u.id = n.ownerUserId AND u.emailVerifiedAt IS NOT NULL)`.

**Metric 3 — Free quota hit rate:**

1. Get the IDs of users with an active PLUS or PRO subscription using the existing `subscriptionRepository.findCurrentlyActiveByPlanTypeInAndStatus(...)` pattern. Collect these into a `Set<UUID>`.
2. Query `user_usage` for the current period: entries where `periodEnd >= now()` and `periodStart <= now()`.
3. From those entries, count:
   - `totalFreeUsers`: entries whose `userId` is NOT in the paid user set
   - `freeUsersHitQuota`: entries where `userId` not in paid set AND `studyPackGenerations >= properties.getPricing().freeMonthlyStudyPackLimit`
4. If no current-period usage records exist, return zeros.

**Metric 4 — Paywall conversion:**
- `usersSeenPaywall`: JPQL `SELECT COUNT(DISTINCT ae.userId) FROM AnalyticsEventEntity ae WHERE ae.eventType = :paywallViewed`
- `usersUpgradedAfterPaywall`: JPQL:
  ```
  SELECT COUNT(DISTINCT ae.userId) FROM AnalyticsEventEntity ae
  WHERE ae.eventType = :subscriptionStarted
  AND ae.userId IN (
      SELECT DISTINCT ae2.userId FROM AnalyticsEventEntity ae2
      WHERE ae2.eventType = :paywallViewed
  )
  ```
- Bind `:paywallViewed = AnalyticsEventType.PAYWALL_VIEWED` and `:subscriptionStarted = AnalyticsEventType.SUBSCRIPTION_STARTED`.

**Metric 5 — Value loop closure:**

This requires a correlated native SQL query. Use native SQL:
```sql
SELECT COUNT(DISTINCT fp.user_id)
FROM (
    SELECT ae.user_id, MIN(ae.created_at) AS first_generated_at
    FROM analytics_events ae
    WHERE ae.event_type = 'STUDY_PACK_GENERATED'
    GROUP BY ae.user_id
) fp
WHERE EXISTS (
    SELECT 1 FROM analytics_events quiz
    WHERE quiz.user_id = fp.user_id
    AND quiz.event_type IN (
        'QUICK_REVIEW_STARTED',
        'CHALLENGE_QUIZ_STARTED',
        'ADAPTIVE_PRACTICE_STARTED',
        'BOARD_EXAM_STARTED',
        'LONG_EXAM_STARTED',
        'INTERVIEW_PRACTICE_STARTED'
    )
    AND quiz.created_at >= fp.first_generated_at
    AND quiz.created_at <= fp.first_generated_at + INTERVAL '7 days'
)
```
- `usersGeneratedPack`: `SELECT COUNT(DISTINCT ae.userId) FROM AnalyticsEventEntity ae WHERE ae.eventType = 'STUDY_PACK_GENERATED'` (JPQL is fine here)
- `usersStartedQuizWithin7Days`: result of the native SQL above

## ERROR STATES

- **Fetch failure on page load** → show inline error message ("Could not load funnel metrics.") with a "Retry" button. Do not show a blank page or throw.
- **403 from the API** → `router.replace("/dashboard")` (same pattern as other admin pages).
- **Zero-denominator in rate calculations** → return `0.0` for the rate; never divide by zero. Handle in the backend service.
- **No analytics events yet** → return `0` for all counts; `0.0` for rates. The page should render valid empty cards, not crash.
- **Null `medianDaysToFirstPack`** (no activations yet) → backend returns `null`; frontend renders `"—"` for the card value.
