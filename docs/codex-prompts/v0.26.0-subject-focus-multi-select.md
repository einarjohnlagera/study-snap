## TASK

Replace the Study Focus course-program chip picker with a subject-level multi-select so learners can set specific focus areas (e.g. "History of Architecture", "Pharmacology") rather than broad programs. Add a new `focusSubjects text[]` column to store these selections, adapt the Profile section copy per profile type, and improve the Progress page empty state with an actionable one-click setup.

## GOAL

The current Study Focus picker shows course programs ("Architecture", "Nursing") — the same taxonomy as the Learning Profile section, creating a confusing redundancy. Subjects are already AI-inferred per note and per study pack. Allowing learners to pick specific subjects gives them a more precise progress target and makes the Progress report more actionable ("I'm focusing on Pharmacology and Anatomy" vs. "I'm studying Nursing").

For board exam takers, this complements the exam goal (set via exam hub intent): even with an exam goal set, the subject breakdown on the Progress page already shows subject-level mastery cards. For students, picking focused subjects tells the Progress page what to surface as the goal rollup.

## CONTEXT

**What already exists (do not rebuild):**

- `NoteEntity.subject` — AI-inferred per note during study pack generation (e.g. "History of Architecture", "Building Technology"). Populated by `StudyPackService`, normalized via `SubjectNormalizationUtils`.
- `SubjectController` — `GET /subjects?scope=mine` already returns the authenticated user's distinct subjects from their own notes via `noteService.listMineSubjects()`. The frontend `listSubjects(scope)` function in `api.ts` already calls this.
- `ProgressReportService.groupQualifyingPacksBySubject()` — already groups study packs by `studyPack.getSubject()`, computes `SubjectProgressEntry` (mastered/due/notPracticed per subject), and returns them as `ProgressReportResponse.subjects`. This is already rendered as `SubjectProgressCard` components on the Progress page.
- `GoalSummaryResponse.weakestGoalSubject` — already computed and used in `NextStudyCard` to show a "Focus on X — you have concepts left to practice" CTA.
- `UserEntity.studyGoal` — a single `text` column. Holds either an exam slug ("ale", "pnle", "let") or a course program name ("Architecture"). Set by the exam hub intent cookie flow and the existing Profile chip picker. **Do not change this column or its semantics.**

**Current Study Focus section behavior (Profile page):**

- If `studyGoal` is set → shows "Change" / "Clear" buttons with the current goal name.
- If `studyGoal` is null → shows course program chips from `listCoursePrograms("mine")`, single-select, saves to `studyGoal`.
- The section copy says "Pick a subject to track mastery toward:" but shows program names — this is the mismatch we are fixing.

**Goal priority in `ProgressReportService`:**

1. `studyGoal` is an exam slug → EXAM goal type (unchanged).
2. `studyGoal` is a course program name → SUBJECT goal type (unchanged).
3. `studyGoal` is null AND `focusSubjects` is non-empty → new SUBJECT_FOCUS goal type (new in this task).
4. Both null/empty → `buildGoalSummary` returns null (unchanged).

**What is explicitly OUT of scope:**
- No curated DepEd/PRC subject reference lists — those are v0.27.
- No "suggest subjects you don't have notes for yet" feature.
- No independent goal tracks per subject (combined rollup model only).
- No change to `studyGoal` or the exam hub intent cookie flow.
- No change to `GoalNudgeResponse` or the dashboard goal nudge.
- No change to `BillingUsageResetJob`, quiz flows, or study pack generation.
- No new analytics events in this task.

## ERROR STATES

- `focusSubjects` is empty after normalization (all blank/null after trim) → treat as if `focusSubjects` is not set; `buildGoalSummary` returns null.
- `listSubjects("mine")` returns empty (user has no notes with AI-inferred subjects yet) → show "Create some notes first — your subjects will appear here as focus options." No chip picker rendered.
- All selected focus subjects match no study packs (user removed those notes) → `buildGoalSummary` returns null for SUBJECT_FOCUS; Progress shows the improved empty state.
- Profile update fails on save → show error message in the Study Focus section (same pattern as existing `studyGoalMessage` state).
- `goalType === "SUBJECT_FOCUS"` with `weakestGoalSubject` null → `NextStudyCard` links to `/public/library` (no subject filter) with generic message "Browse community notes to build your knowledge."
