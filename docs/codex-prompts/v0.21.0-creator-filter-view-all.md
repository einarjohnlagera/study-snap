## TASK

Add a `creator` (username) query param to `GET /notes/public` and add a "View all X notes →" link on the public profile page that navigates to `/public/library?creator=<username>` when the creator has more than 8 public notes.

## GOAL

Prolific creators currently have no way for visitors to see their full catalog — the public profile caps at 8 notes with no escape path. Making the Public Library the canonical browsing surface for a creator's notes gives visitors a richer discovery experience and positions the Public Library as the single source of truth for creator content.

## CONTEXT

### Decisions made

- `creator` filter uses the creator's `username`, never `userId` or `displayName`. Username is the stable public identifier introduced in v0.12.0.
- "View all X notes →" link on the public profile page is conditional: visible only when `profile.publicNotesCount > 8` (i.e. the 8-note cap is hiding some notes).
- When `?creator=` is active in the Public Library URL, the UI shows an active "By @username" filter badge that can be cleared to return to the full library.
- The `creator` filter is combinable with all existing public library filters (`courseProgram`, `subject`, `tags`, `search`, `audience`, `sort`).

## ERROR STATES

- `creator` param with a username that does not exist → return an empty list (same behavior as any filter that matches zero notes); do not throw 404 — the library should gracefully show an empty state
- Network error loading public library with `creator` filter → show the same retry/error state as any other public library load failure
- `profile.username` is null on the public profile page (legacy accounts without a username) → hide the "View all" link entirely; do not render a broken URL
- Clearing the `creator` filter badge should return to `/public/library` discovery mode (no active filters), not to a stale previous filter state
