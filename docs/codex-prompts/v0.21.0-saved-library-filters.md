## TASK

Add backend-persisted saved filters to the private library: users can name and save the current filter state, see their saved filters in the filter bar, apply one with a single click, and delete saved filters they no longer need.

## GOAL

Users who study across multiple subjects or exam tracks re-apply the same filter combinations every session. Named saved filters let them organize their private library the way they think about it — "PNLE Notes", "Grade 5 Math", "Ready to Review" — without manually re-selecting fields each time.

## CONTEXT

### Decisions made

- **Backend-persisted from day one** — no localStorage fallback. Cross-device consistency matters for a study tool used on multiple devices.
- **New table `user_library_filters`** with migration `V68__user_library_filters.sql`. Schema: `id` (UUID PK), `user_id` (UUID FK → users, cascade delete), `name` (VARCHAR 100 NOT NULL), `filter_state` (JSONB NOT NULL), `created_at` (TIMESTAMPTZ NOT NULL DEFAULT now()).
- **`filter_state` shape** mirrors the private library URL params: `{ search?: string, subject?: string, courseProgram?: string, tags?: string[], status?: string, sort?: string }`. Store only the keys that are set; omit nulls/empty arrays.
- **Endpoints**:
  - `GET /library-filters` — list all saved filters for the authenticated user; ordered by `created_at DESC`
  - `POST /library-filters` — create a new saved filter; request body: `{ name: string, filterState: object }`; responds with the created record
  - `DELETE /library-filters/{id}` — delete a saved filter by ID; owner-only (user can only delete their own filters); responds 204 No Content
- **No update endpoint for v1** — users delete and re-save if they want to rename or change a filter.
- **No plan gating** — available to all plan tiers (FREE, PLUS, PRO).
- **Scope: private library only** — public library saved filters are deferred.
- **Saved filter names** are max 100 characters.
- **Applying a saved filter replaces** all current filter params with the saved state (does not merge).
- **No cap on saved filter count** for v1.

## REQUIRED CHANGES

### Backend

**Migration `V68__user_library_filters.sql`**:
```sql
CREATE TABLE user_library_filters (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    name VARCHAR(100) NOT NULL,
    filter_state JSONB NOT NULL,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE INDEX idx_user_library_filters_user_id ON user_library_filters(user_id);
```

**New entity `UserLibraryFilterEntity`**:
- Fields: `id` (UUID), `userId` (UUID), `name` (String), `filterState` (String/JSONB stored as String), `createdAt` (Instant)
- Use `@Column(columnDefinition = "jsonb")` for `filterState`

**New repository `UserLibraryFilterRepository`** (extends `JpaRepository`):
- `List<UserLibraryFilterEntity> findByUserIdOrderByCreatedAtDesc(UUID userId)`
- `Optional<UserLibraryFilterEntity> findByIdAndUserId(UUID id, UUID userId)` — for owner-check on delete

**New DTOs**:
- `SavedLibraryFilterResponse`: `{ id: UUID, name: String, filterState: Object, createdAt: Instant }`
- `CreateSavedLibraryFilterRequest`: `{ name: String (max 100, not blank), filterState: Object (not null) }`

**New service `UserLibraryFilterService`**:
- `list(UUID userId)` → `List<SavedLibraryFilterResponse>`
- `create(UUID userId, CreateSavedLibraryFilterRequest request)` → `SavedLibraryFilterResponse`; validate name is not blank and not > 100 chars; throw `InvalidSavedFilterRequestException` (new named subclass) for validation failures
- `delete(UUID filterId, UUID userId)` → `@Transactional`; load by `findByIdAndUserId`; throw `SavedFilterNotFoundException` if not found; delete

**New controller `UserLibraryFilterController`** (path: `/library-filters`):
- `GET /library-filters` → `list(user.userId())`
- `POST /library-filters` → `create(user.userId(), request)`
- `DELETE /library-filters/{id}` → `delete(UUID.fromString(id), user.userId())` → 204 No Content
- All endpoints: `@PreAuthorize("hasAnyRole('USER','ADMIN')")`

### Frontend

**New API helpers in `lib/api.ts`**:
- `getSavedLibraryFilters()` → `GET /library-filters`
- `createSavedLibraryFilter(name: string, filterState: object)` → `POST /library-filters`
- `deleteSavedLibraryFilter(id: string)` → `DELETE /library-filters/{id}`

**Library page / filter bar component**:

*Save filter:*
- "Save filter" button (e.g. bookmark icon + "Save filter" label) visible in the filter bar **only when at least one filter is active** (i.e. any of search, subject, courseProgram, tags, status, sort is set to a non-default value)
- Clicking opens a small dialog/modal: a text input for the filter name, "Save" (primary) and "Cancel" (secondary) buttons
- On submit: call `createSavedLibraryFilter`; on success, close the dialog, add the new filter to the local saved filters list, and show a brief success toast ("Filter saved")
- Name input: max 100 characters; show inline error if blank on submit

*Saved filters picker:*
- A "Saved filters" dropdown trigger or expandable list section in the filter bar
- Loads `getSavedLibraryFilters()` on mount; shows each saved filter as a row with its name and a delete icon
- Clicking a saved filter row applies its `filterState` to the current filter URL params (replaces all current filter values)
- Clicking the delete icon calls `deleteSavedLibraryFilter(id)`; on success, remove from the list; show a brief toast ("Filter deleted") or confirm in-place; do not ask for confirmation (destructive but low-stakes)

## ERROR STATES

- `POST /library-filters` with a blank name → 400; frontend shows inline "Name is required" error in the dialog; dialog stays open
- `POST /library-filters` with a name > 100 chars → 400; frontend shows inline error; dialog stays open
- `DELETE /library-filters/{id}` where filter is not found or owned by another user → 404; frontend shows a toast "Could not delete filter" and removes the item from the list anyway (optimistic UI is acceptable here)
- Network error on `GET /library-filters` → show nothing (saved filters section collapses silently); do not block the library from loading
- Network error on `POST /library-filters` → show a toast "Could not save filter"; dialog stays open so the user can retry
- Loading saved filters on page mount: if the request is in-flight, disable the "Saved filters" trigger or show a loading skeleton; do not flash a broken empty state
