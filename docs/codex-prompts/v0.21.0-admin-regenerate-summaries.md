## TASK

Add a `POST /admin/study-packs/regenerate-summaries` endpoint that re-generates the `summary` field only for study packs owned by admin users, skipping packs whose summary already contains enriched content.

## GOAL

NoteLib's official notes (owned by admin accounts) were generated before the summary enrichment (comparison tables, Common Misconceptions) shipped in v0.20.0. This endpoint lets the admin trigger a one-time backfill that upgrades those summaries to the enriched format without touching quiz, key concepts, or any other generated field.

## CONTEXT

### Decisions made

- **Summary-only re-generation** — only `study_packs.summary` is updated. Quiz questions, key concepts, tags, subject, and title are untouched. This is not a full regeneration.
- **Admin-owned packs only** — target study packs where the note's owner has `UserRole.ADMIN`. This is the role-based official account check introduced in the same release (see `NoteService.isOfficialAuthor()`). Do not hardcode any email or userId.
- **Skip already-enriched summaries** — if `study_packs.summary` already contains a `|` character, the pack already has a comparison table and should be skipped to avoid redundant LLM calls.
- **Async via `llmParallelTaskExecutor`** — same executor used for parallel study pack generation. Do NOT use `studyPackGenerationTaskExecutor` for this (see AGENTS.md anti-drift note).
- **Immediate response** — return `{ queued: N, skipped: N }` synchronously. Re-generation runs in the background.
- **No retry on partial failure** — if a single summary call fails, log the error and continue. Do not fail the whole batch.
- **No new migration** — only updates the existing `summary` column.
- **No quota deduction** — summary re-generation does not count against `user_usage.studyPackGenerations`.
- **Idempotent** — re-running the endpoint is safe; already-enriched summaries are skipped.

### Anti-drift rules from AGENTS.md

- `llmParallelTaskExecutor` is the correct executor here. The `studyPackGenerationTaskExecutor` must NOT be used (it is for the main generation flow only; see AGENTS.md).
- Throw named exception subclasses — no `new AppException(...)` inline. No new exceptions should be needed for this endpoint; errors in individual pack regeneration are logged, not thrown upward.
- Repeated string literals must be extracted to `private static final String` constants — the `|` character used for enrichment detection should be a named constant.
- `@Transactional` on each individual summary update in the service (not the whole batch method — individual writes must be committed before the next one starts).
- Do NOT deduct study pack quota. Do NOT call any usage tracking method.
- Do NOT regenerate quiz, key concepts, tags, subject, or title.

**1. New interface method on `LlmStudyPackService`:**


**2. New implementation in `OpenAiLlmStudyPackService`:**

`regenerateSummary()` calls the OpenAI API with:
- **System message**: the same content from `developer.txt` (already loaded in the class for `generateStudyPack`)
- **User message**: the raw note content, same format as used in `generateStudyPackOnce()`
- **Response schema**: a minimal JSON schema with only a `"summary"` string field (do not include quiz, keyConcepts, tags, etc.)
- **Validation**: after parsing, check `StringNormalizationUtils.countWords(summary) > MAX_SUMMARY_WORDS`; throw `invalidOutput(...)` if exceeded (same pattern as `validatePromptStudyPack`)
- **Retry**: wrap in `retryOnceOnInvalidOutput(...)` same as `generateStudyPack`
- The model used should follow the same model selection logic as `generateStudyPack` (read from `StudySnapProperties`)

**3. New repository method on `StudyPackRepository`:**

```java
@Query("SELECT sp FROM StudyPackEntity sp WHERE sp.ownerUserId IN :adminUserIds AND (sp.summary IS NULL OR sp.summary NOT LIKE '%|%')")
List<StudyPackEntity> findByOwnerUserIdInAndSummaryNotEnriched(@Param("adminUserIds") List<UUID> adminUserIds);
```

Also needs a method to find the source note for a study pack — use `NoteRepository.findById(sp.getNoteId())` in the service.

**4. New DTO: `AdminRegenerateSummariesResponse`:**

```java
public record AdminRegenerateSummariesResponse(int queued, int skipped) {}
```

**5. New service: `AdminStudyPackService`:**

`@Service @RequiredArgsConstructor` — no class-level `@Transactional`; each write is transactional individually.

Inject: `UserRepository`, `NoteRepository`, `StudyPackRepository`, `LlmStudyPackService`, `AsyncTaskExecutor llmParallelTaskExecutor`.

Single public method: `AdminRegenerateSummariesResponse regenerateOfficialSummaries()`

Logic:
1. Find all users where `role = UserRole.ADMIN` via `userRepository`
2. Collect their UUIDs into a list
3. Call `studyPackRepository.findByOwnerUserIdInAndSummaryNotEnriched(adminUserIds)` — these are the packs needing regeneration
4. For each pack: submit a `CompletableFuture.runAsync(() -> regenerateOnePack(pack), llmParallelTaskExecutor)`
5. Do NOT wait for completion — return `{ queued: packs.size(), skipped: (total admin packs - packs.size()) }` immediately

For `regenerateOnePack(StudyPackEntity pack)` (private, `@Transactional`):
1. Fetch the source note via `noteRepository.findById(pack.getNoteId())` — skip if not found (log warn)
2. Build a `StudyPackGenerationContext` from the note and its owner (read learnerLevel from owner, courseProgram from note)
3. Call `llmStudyPackService.regenerateSummary(note.getContent(), context)`
4. If successful: update `pack.setSummary(newSummary)`, `studyPackRepository.save(pack)`
5. If any exception: log at WARN level with the pack ID and reason; do not rethrow

**6. New controller: `AdminStudyPackController`:**

```java
@RestController
@RequestMapping("/admin/study-packs")
@RequiredArgsConstructor
@PreAuthorize("hasRole('ADMIN')")
public class AdminStudyPackController {
    private final AdminStudyPackService adminStudyPackService;

    @PostMapping("/regenerate-summaries")
    public AdminRegenerateSummariesResponse regenerateSummaries() {
        return adminStudyPackService.regenerateOfficialSummaries();
    }
}
```

## ERROR STATES

- **No admin users found** → return `{ queued: 0, skipped: 0 }` with no error
- **No unenriched packs found** → return `{ queued: 0, skipped: N }` with no error
- **Individual pack LLM failure** → log at WARN, skip the pack, continue the batch; the response `queued` count still reflects how many were submitted (not how many succeeded)
- **Note not found for a study pack** → log at WARN with the pack ID, skip silently
- **403 from the API (non-admin user)** → handled by Spring Security; no application code needed
- **Frontend fetch failure** → show inline error on the button ("Could not queue regeneration. Try again."); do not crash
