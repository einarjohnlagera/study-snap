## N1. A third way a public child becomes a public root (new, amends the Scope)

**`PATCH /collections/{id}/parent` with a null parent** (`updateParent`, Svc:~897-910, controller `NoteCollectionController.java:174-182`, USER or ADMIN) detaches a child from its Goal and **leaves its `visibility` untouched**. The only guard is `assertPublishedSubjectMoveKeepsTermsCoherent` (Svc:3461), which blocks moving a published child only when the child **carries a term label** or the destination uses terms. So for a published child **without** a term (every board-exam Goal's sections: ALE, CPALE, CELE, LET, PNLE have none) an admin can detach it and it becomes a **PUBLIC top-level collection**, which `listPublic` then shows on Explore as an "Official" card and `getPublic` reads as a root. The three computing Goals (with terms) are protected by the term guard.
- **Status:** CONFIRMED by code reading only (not reproduced). **Not a live exposure today:** production has exactly the 8 known PUBLIC roots (read 2026-11-14).
- **Proposed Phase 0 change (PROPOSAL; CORRECTED by the cold review, see the section below):** when `updateParent` detaches (`parentId == null`) a child that is **PUBLIC, whatever its former parent's visibility**, set the child PRIVATE in the same transaction, leaving `published_at` stamps untouched; the curator can re-publish it deliberately as a standalone plan. (The first draft limited this to a PUBLIC former parent; the cold review showed a PUBLIC child under a PRIVATE parent is reachable today and would be promoted too.) Tests: detach a PUBLIC term-less child under a PUBLIC Goal, and under a PRIVATE Goal → it is PRIVATE, absent from `listPublic`, 404 on `getPublic`; detaching a PRIVATE child is unchanged; re-parenting to another parent is unchanged.
- **Owner decision R5 is unaffected:** this touches no legacy section (the nine are PRIVATE already) and republishes nothing.

## N2. The pre-check that was meant to detect promoted children is too weak (amends the Scope)

Scope pre-check **P3** ("PUBLIC roots carrying child markers: `term_label` or `sibling_position` not null") catches only orphans created by **Goal delete** (`ON DELETE SET NULL` keeps those columns). `updateParent(null)` **clears** `sibling_position` and `term_label` (Svc:903-905), so a detached child is **invisible to P3**. **Replace P3 with a roster comparison:** list every PUBLIC root (`id`, `title`, owner role) and require it to equal the known Official roster (CELE, CPALE, ALE, LET, BSCS, BSIT, BSIS, PNLE; 8 rows today); any extra row is a STOP-and-report, never an auto-fix. Keep P1, P2, P2b, P5, P5b and N9 as written. **Add P6:** children whose owner differs from their parent's owner, expected 0 (item 3).
