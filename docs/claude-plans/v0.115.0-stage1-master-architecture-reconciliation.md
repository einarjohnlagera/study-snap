## 1. Executive judgment

**The direction is confirmed and the scope is smaller than the original brief assumed.** No universal
sync engine, no event sourcing, no generic inheritance framework, no taxonomy proliferation.

Two problems are **live**, not future architecture:

1. **Domain Context under-classification.** The taxonomy is not obviously incomplete; it is
   inconsistently applied. Most single-program curated notes carry no explicit value.
2. **Stranded adopters.** Existing adopters sit on older Official Review Set snapshots while source
   curricula improve. Re-adoption is a hard no-op, growth has already stranded curriculum, and
   **learners have already attempted re-adoption.**

**One hard sequencing constraint governs the whole programme:** the publish-transition applicability fix
must ship **before or with** the first additive update pass, because the update pass mints learner notes
through `copyNote` and would sharply expand the affected population.

### ⚠️ Four corrections to the previous revision of this document

Recorded rather than silently swapped.

1. **"Expected residue 0–3, most plausibly 0" is REMOVED.** Publishing an expected distribution before
   the pass runs is precisely the failure that produced the original 215 contaminated rows — a
   pre-committed answer reproduced instead of a per-note assessment. **The honest residue is an OUTPUT,
   never a target.**
2. **Classification is TREATMENT-FIRST, not computation-driven.** The previous framing led with the
   ~239-note computation-guidance gap, which inverts the rule. `ADR-001` binds: choose the value that is
   the correct authoring treatment. `quantitative` is a **consequence** of that choice, never a reason
   for it. **Do not classify a Nursing or Accountancy note to switch on computation guidance.**
3. **"The numerator never shrinks" is WITHDRAWN as too broad.** The correct invariant is narrower:
   **learner study history is preserved.** Current-curriculum counts may legitimately change when topics
   are retired or the source restructures.
4. **AI-tooling scheduling is removed** (see the note above).

## 3. Domain Context — the 11-value baseline

**Active baseline:** `ENGINEERING_MATHEMATICS` · `ENGINEERING_SCIENCES` · `CIVIL_ENGINEERING` ·
`PROFESSIONAL_PRACTICE_AND_REGULATION` · `GENERAL_EDUCATION` · `PROFESSIONAL_EDUCATION` · `NURSING` ·
`ACCOUNTANCY` · `ARCHITECTURAL_DESIGN` · `ARCHITECTURAL_HISTORY_AND_THEORY` ·
`PLANNING_AND_SITE_DEVELOPMENT`

### The mechanism that explains the state of the library

**Classification is driven by the generation gate, not by curator diligence.** Every note with 2+
programs is classified because the server forces it; **699 of 809 single-program notes are not**, falling
through to the program *name* as the authoring domain.

**⚠️ Therefore the four zero-usage values measure which notes the gate FORCED, never which values are
right.** Any future proposal to remove them must clear this finding first.

**The consequence, stated as a consequence and not as a motivation:** ~239 curator notes (Nursing 106,
Architecture 73, Accountancy 60) currently generate with no computation guidance, on the permanent-per-note
path. Civil Engineering is the control at 62/62 passing, purely because `engineering` is a keyword.
`ACCOUNTANCY` is the trap case — it declares `quantitative = true`, but the flag is never reached on an
unset note and the keyword is `accounting`, which `accountancy` does not contain.

**⚠️ This is a reason the under-classification MATTERS. It is not the rule for choosing a value.**

### Architecture is compositional, not absent

| Treatment | Value |
|---|---|
| Space planning, circulation, anthropometrics, ergonomics, programming, universal design, concept development | `ARCHITECTURAL_DESIGN` |
| History of architecture, Philippine architecture, theory, criticism, heritage conservation | `ARCHITECTURAL_HISTORY_AND_THEORY` |
| Site planning, topography, zoning, parking, urban planning, site analysis, solar/wind siting, landscape | `PLANNING_AND_SITE_DEVELOPMENT` |
| Building services, plumbing, HVAC, electrical, lighting, acoustics, fire protection, vertical transportation, construction materials/testing/management | `ENGINEERING_SCIENCES` |
| Building codes, professional law, ethics, licensure, contracts, regulatory accessibility | `PROFESSIONAL_PRACTICE_AND_REGULATION` |

**⚠️ The three Architecture values are NOT a licence to reclassify genuinely engineering material.**
`ENGINEERING_SCIENCES` is quantitative; the three are not, so misrouting a computational note silently
removes its computation guidance.

### Expansion is a named future trigger, not an active slice

**Do not open a taxonomy release for symmetry.** A new value requires a **recurring treatment gap that
existing values cannot express honestly** — established prospectively from well-understood curriculum
treatment is acceptable; a Course/Program merely existing is not.

- **Computing** — re-open when authored computing material repeatedly cannot be represented honestly.
- **Biomedical / Medicine** — re-open when health authoring shows a recurring treatment family not
  expressible by `NURSING` / `GENERAL_EDUCATION` / `PROFESSIONAL_PRACTICE_AND_REGULATION` / existing values.
- **All others** — treatment gap first.

**Default posture: classify first → author real content → identify genuine gaps → add a value only when
needed.** This is *not* a return to "wait until the server throws."

### Composition matrix — observed vs potential, kept separate

**Observed (proven by production explicit assignments):** Architecture → 4 contexts · Civil → 4 ·
Architectural Engineering → 4 · Mechanical → 4 · `ENGINEERING_SCIENCES` → 23 programs. Genuinely
non-diagonal.

**Not observed:** Nursing, Education, Accountancy, Medicine, Pharmacy, PT. **⚠️ These are UNDER-OBSERVED
because their notes fall through unclassified — that is not evidence of clean composition, and must not
be reported as such.** Potential composition may be stated only where authoring doctrine is already
clear, and must be labelled as inferred.

**Post-classification test:** if those families return ~100% diagonal, that is the consolidation signal.

## 4. ALE targeted classification (Slice 0A)

**Scope: `domain_context` ONLY.** Review Set, Subject Plans, Sections, titles, Applicable Programs,
Authored Depth, topics, ordering and placements are all preserved. Do not rerun settled curriculum
structure.

**Method:** treatment-first, per note, using the §3 mapping. Subject grouping is a *starting point for
curator review*, never an answer: National Building Code / Professional Practice / BP 334 / Building Laws
→ regulatory; Site Planning → planning; Building Technology / Building Utilities → engineering sciences;
Architectural Conservation → history and theory. **Theory of Architecture, Architectural Design and
Structural Components require curator hand-checking.**

**⚠️ NO EXPECTED RESIDUE FIGURE IS STATED, AND NONE MAY BE.** The honest unset residue is an **output**.
If zero notes remain unset, fine. If several do, record them as findable backlog markers. **Forcing rows
to reach 100% would repeat the exact failure that contaminated the original 215.**

**Deliverables:** before-distribution capture · the pass · after-distribution capture · the residue list
with per-note reasons.

**Execution:** this writes `domain_context` on production rows, so it is **owner-executed**. Engineering
hands over a `docs/claude-plans/*.sql` file with exact statements, expected row count per group and
verification steps, then stops. **The comprehensive ALE build is gated on the after-capture existing.**

## 6. Publish/applicability implementation contract (Slice 1)

### Semantics

- A copied note is **learner-owned and independent**. Provenance terminates.
- Copied applicability is **source-derived initialization**, never live curator ownership.
- **Public applicability authority transfers at publication.**
- No universal inheritance system is introduced.

### Contract

At the `PRIVATE → PUBLIC` transition for **learner-owned** notes, clear copied program rows in
`NoteService.updateVisibility`. That method already computes the predicate for analytics, and it is the
**sole** path to non-`PRIVATE`.

- **One write path. Zero public-discovery SQL changes. Inert on all 536 existing rows** (0 are public).
- Clearing **un-shadows** the learner's own field, which the client renders and requires — **authority is
  transferred, not merely revoked.**
- **Leave a null string null** — public but unshelved until the learner answers.
- **Reject backfilling** from the joined catalog name; it would relaunder curator classification through
  a different column.
- **Restrict to non-curators** or it destroys the catalog.
- Known edge: public → private → public loses rows permanently. A companion server-side fix is owed so an
  omitted `courseProgramText` retains the stored value rather than stamping the profile program.

### ⚠️ Precision on option C — rejected semantics vs unreachable implementation

**The settled decision is narrow:** *we are not solving this by making the learner's free-text value clear
copied rows; public applicability authority is handled at publication instead.*

Separately, and as a **repo fact rather than a product argument**: C as previously proposed **cannot fire
in the current model**, because shadowing makes the learner's free-text value effectively shadowed on
copied notes. **Do not conflate the two, and do not extrapolate either into a broad claim that learner
ownership does not matter** — it does; it is exercised at publication.

### Scope guard

**Do not broaden this into a public-discovery redesign.** No new discovery authority tables, no new
provenance enums, no new publication workflow, no new visibility state. **If implementation exposes an
unacceptable semantic edge case, escalate explicitly before changing the architecture.**

## 7. Placement identity and idempotence

### ⚠️ Placement identity — SETTLED FROM THE DATABASE, 2026-09-05

`note_collection_items` carries **`UNIQUE (collection_id, note_id)`**. Therefore, verified rather than
assumed:

| Question | Answer |
|---|---|
| Same source note twice in one Subject Plan? | **NO** — forbidden by the constraint |
| Same note in multiple Sections within one Subject Plan? | **NO** — Sections are labels on items, and there is exactly one item per `(collection, note)`, so a note has exactly one label per plan |
| Same note in multiple Subject Plans? | **YES** — different `collection_id` |

**Durable placement identity is `(collection_id, note_id)`** — i.e. `(source Subject Plan, source Note)`,
exactly the invariant the tightening asked to confirm or refute. **It requires no new column, and no title
or label matching.** 100% of the 4,374 existing placements already carry `copied_from_note_id` for the
note half.

### Idempotence — storage settled, application NOT

**The database guarantees no duplicate placements.** What is **not** verified is whether the application
insert path handles the resulting unique violation gracefully or throws mid-pass.

**Required proof before implementation signoff — engineering verification, not a product decision:**

1. Run the same additive update twice.
2. Second run creates **zero** duplicate note copies.
3. Second run creates **zero** duplicate collection placements.
4. The same learner note is not inserted twice into the same adopted Subject Plan.
5. One source note reused across different Subject Plans remains correctly distinguishable.
6. **A regression test around repeated update application.**

`copyNote` idempotence per `(owner_user_id, copied_from_note_id)` is established and should be reused —
but it covers the note layer only, and must not be generalized to the membership layer without (1)–(6).

## 8. Additive Review Set update contract (Slice 2)

### Conceptual contract

> **An adopted Official Review Set is learner-owned, but retains ongoing source identity so NoteLib can
> offer non-destructive curriculum updates.**

Neither a permanently detached snapshot nor a live mirror.

### This is live product debt

**92 learners · 523 adopted collections · 4,374 placements.** Re-adoption is a hard no-op (`adopt()` bails
before `copySourceItems` runs). **364 source placements and 68 whole Subject Plans are already stranded —
100% from post-adoption growth, 0% from learner removal — and 10 no-op re-adopt attempts by 4 distinct
users show learners are already asking.** Do not defer this on the theory that adoption is too small.

### What applies automatically, and what does not

| Source change | v1 behaviour |
|---|---|
| **Add** note / Subject Plan / placement | **Apply** |
| Rename | **Surface only** |
| Reorder | **Surface only** — never overwrite learner order |
| Retire | **Surface only** — never delete learner note or history |
| Move | **Surface only** — never silently restructure |

**Rationale: until source-at-sync provenance exists, the system cannot distinguish learner customization
from upstream change.** Applying a structural mutation without that distinction would overwrite learner
work.

### Learner ownership is absolute inside updates

An update may add Subject Plans, notes and placements. **It must not replace** learner note bodies,
learner Study Packs, learner edits, `ConceptHealth`, quiz/session history, or learner-authored additions.
The learner note stays independent; the **plan** source relationship persists. **These provenance
semantics remain separate.**

### Minimum update provenance — concrete, not a vague "snapshot"

Per placement, captured at last sync:

| Field | Why |
|---|---|
| source Subject Plan identity | ✅ exists (`sourcePlanId`) |
| source note identity | ✅ exists (`copied_from_note_id`) |
| **source section/label at last sync** | ❌ **new** — mutable, and the one genuinely unreconstructable fact |
| **source position at last sync** | ❌ **new** — mutable |
| **source parent/location at last sync** | ❌ **new**, only if notes can move across Subject Plans |
| **last source sync timestamp** | ❌ **new** |
| **learner-removal tombstone** | ❌ **new**, prospective |

**If these live in one JSON snapshot, its schema must be defined explicitly before implementation.** No
event sourcing. No semantic version system unless later evidence requires it.

### Learner removals — prospective

Production shows **zero** learner removals in the stale population, so the tombstone ships with an **empty
backfill**. That is not a reason to omit it: if a learner intentionally removes an upstream topic, future
updates **must not re-add it**. **This is not justification for a synchronization engine.**

### Detached adoptions — a first-class resolver state

Two adoptions point at source collections that no longer exist. **`Detached from source`** is a real
state, not an error path:

- the learner plan stays fully usable;
- **no update is offered**;
- **no source relationship is fabricated**;
- **no repeated failure loop**;
- learner progress is intact.

This belongs in the additive-update slice.

## 9. `targetCompletionDate` disposition

`adoptGoal`'s reparent branch **NULLs `targetCompletionDate`**, so a learner who set a completion or exam
date loses it when later adopting a parent Goal. **The date is learner-owned state and is not recoverable
— nothing else records it.**

**Disposition: fix it BEFORE the additive update release, or inside that release if the same path is
already being modified. Do not defer it indefinitely.** It carries a Backlog Index row.

## 10. Progress and readiness after curriculum expansion

### Two different concepts, kept apart

- **Historical accomplishment** — *"240 topics completed."* Learner history. **Must not be erased because
  the Official curriculum changed.**
- **Current curriculum coverage** — *"240 / 550 current topics."* **May legitimately decrease** when the
  Review Set becomes more comprehensive. That is honest.

**⚠️ Do not artificially preserve the old percentage. Do not describe the change as lost progress — the
denominator changed.**

**Recommended direction** (wording is Category C, open):

> **240 topics completed**
> **44% of your current Review Set**
> 250 new topics were added when your Review Set was updated. Your previous progress was kept.

**⚠️ The invariant is "learner study history is preserved" — NOT "the numerator never shrinks."** Current-
curriculum counts may legitimately change when topics are retired or the source restructures.

### Readiness needs its own audit — do not assume it equals completion

**Before implementing update UX, trace the existing formulas** for: practiced count · readiness · next-topic
recommendation · Subject Plan progress · Board/Long Exam coverage · `ConceptHealth` aggregation · primary
plan display. **Do not invent a readiness-preservation rule without tracing what exists.** This is
Category B and is not yet done.

## 11. Infrastructure constraint — a release consideration, not a product gate

The connection-pool root cause is **unresolved**, and `v0.114.0` established that the
generation-holds-connections hypothesis is **positively unsupported**. **Do not claim the cause is
established, and do not make adoption-update architecture depend on it.**

The operational constraint is real and narrower: the existing pass runs **one transaction per note**, so
a large update could involve many sequential database operations. **Before release: measure the actual
update transaction pattern, and batch or bound it if the measurement warrants.** Do not blindly reuse a
per-note loop at reshape scale without testing — and **do not let the unresolved pool diagnosis gate the
product work.**

## 14. Remaining contradictions with ADR / Decision History

**Three, all documentation-integrity issues rather than decision reversals.**

1. **`ADR-001`'s canonical-shapes table, third row, is factually wrong.** It depicts a learner copy's
   Course/Program string as *"as copied"*, implying populated. `create` sets it `curator ? null : …`, so
   **608 of 1360 curated public notes carry a NULL string** and their copies inherit that null. The table
   describes the V107-era shape — which is why all 536 *existing* copies happen to agree, and why it is
   wrong about copies made today. **Correct the ADR text; no decision changes.**
2. **`ADR-001` still lists options D and C as "deliberately left open."** They are now resolved — both
   rejected, publish-transition authority chosen. **The ADR needs an amendment recording the resolution**,
   or a future reader will re-derive the same two options. *(The mirrored row in
   `NOTES_AND_COLLECTIONS_CONTEXT.md` has already been corrected.)*
3. **`docs/features/` carries no connection-pool, adoption-update or copied-applicability behaviour doc.**
   Slices 1 and 2 change learner-visible behaviour, so the relevant feature docs must be created or
   updated **as part of those slices**, not after.

**No contradiction was found between the Stage 1 findings and any ratified decision.** Where this document
differs from the original brief, it is because repo evidence falsified a premise — recorded in §1 and in

## 16. Final learner-facing contract

> **Official Review Sets improve over time without erasing what learners have already studied or
> customized.**

| Concept | Contract |
|---|---|
| **Canonical Note** | Reusable knowledge, independent of curriculum container where possible |
| **Learner Note copy** | Independent learner-owned knowledge initialized from a source Note. Provenance **terminates** |
| **Applicable Programs** | Where knowledge applies and may be discovered. Curator-authoritative on curated notes; **authority transfers to the learner at publication** |
| **Domain Context** | How knowledge should be authored. Single-valued, closed, **treatment-earned**. Use the current taxonomy consistently first; expand only when real treatment cannot be represented honestly |
| **Official Review Set** | Curated evolving curriculum |
| **Adopted Review Set** | Learner-owned journey retaining **ongoing** source identity, eligible for non-destructive additive updates |
| **Learner study history** | **Preserved** even when the curriculum expands |
| **Current completion / readiness** | **May change honestly** when the curriculum itself changes |
