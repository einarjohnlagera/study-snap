## 2. Item 1 — Summary maths. The naive fix is wrong and `v0.95.1` already recorded why

`frontend/components/ui/summary-markdown.tsx` runs `react-markdown` + `remark-gfm` with **no math
plugin**.

**⚠️ `_` IS MARKDOWN EMPHASIS.** `$x_1 + x_2$` becomes `<em>` *before* any post-processing could see
it, so a display-time regex cannot fix this. It needs **`remark-math` for TOKENIZATION ONLY**,
rendering through the **existing** KaTeX setup — `katex` is already a dependency and `renderMathText`
already handles `$…$`, `$$…$$`, `\[…\]`, plus `normalizeBareMath` for legacy undelimited content.
**⚠️ Keep ONE math configuration; do not introduce a second.**

**⚠️ `v0.95.1` shipped leg (a)** — the plain-text note surfaces, where `renderMathText` applies
directly. **This is leg (b).** **⚠️ Neither is `v0.86.0-note-item-limit-mismatch.md`'s LaTeX item**,
which is *corrupted escapes in stored content* — a different defect. **Do not close that one with
this.**

**⚠️ TEN NON-TEST CONSUMERS SHARE THIS RENDERER**, several public/SEO-indexed — which is why guard
(b) exists:

```
app/collections/[id]/collection-detail-page-client.tsx   app/demo/page.tsx

app/public/library/[subject]/[slug]/page.tsx             app/study/study-pack-results.tsx
```
