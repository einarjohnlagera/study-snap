Product UX's 2026-11-11 direction is to measure the baseline on the same inputs first (`docs/claude-plans/2026-11-10-next-releases-sequence-recommendation.md:111`). ## 7. Metrics and gates, by class

**All workflows:** keep each HTTP attempt's status, response shape, usage, latency, timeout and cost, plus end-to-end workflow success. Request success means the real `/responses` call returns content the production parser can consume; schema validity means the returned payload parses and meets that workflow's strict schema, without altering production parser or schema (`OpenAiLlmStudyPackService.java:444-471,531-583`; Ask Companion: `OpenAiAskCompanionLlmService.java:48-71,101-109`). Record first-attempt and final-after-production-retry results separately. **Parse failure** is any returned/empty response that fails JSON extraction, deserialization, schema/required-field validation or a production validator. An initial failure repaired by the production retry is a **first-attempt failure and a final success**, never a clean first attempt (`OpenAiLlmStudyPackService.java:473-499,576-583,3063-3085`). HTTP/transport failures and timeouts are separate. For routes without a retry wrapper, first and final coincide.

## 8. Thresholds fixed now as same-run-baseline rules

All numbers in this table are **PROPOSED** acceptance bounds, pending owner approval **before output**. “Baseline” means the same workflow's same-run arm on exactly the same frozen inputs. A missing pair, incomplete blind score, unmetered call, missing provider precondition or cap stop is **INCONCLUSIVE**, never a pass or fail. At **PROPOSED N = 30**, one excess event is **PROPOSED 3.33 points** (section 1); these margins allow at most one excess event where stated and cannot prove equivalence for rare harms.

| Gate | PROPOSED rule for each workflow |
|---|---|
| Final request/workflow success | Candidate failure rate ≤ baseline failure rate + **0 points**; report HTTP status, timeout and parser-stage failure types separately. |
