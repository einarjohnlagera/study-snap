## 0b. Budget: the harness does NOT enforce a cumulative cap

Verified in the code (`LlmModelBenchmark.java:129-142`, `MeteringInterceptor.java:78`): `spendStopUsd` belongs to **one command**. Each command builds its own meter that starts at zero; nothing is remembered between commands. If the flag is omitted the default is $8.00 (maximum accepted $10.00), so **every command must carry its own stop, as the sheet does.** The meter checks **before** each call and stops once its running total reaches the stop, so a command can overshoot by at most one call (about $0.07 on Sol, about $0.01 on the others). It prices at list rates, and cached input is billed lower, so it tends to overstate rather than understate. The "about $3.95 worst case" is therefore an **estimate, not a cap**: the stops sum to $3.61 and the ten commands can overshoot by roughly $0.34.

Reference: the same ten commands in `v0.176.0` metered **$3.0342** in total (A3 $1.318 and B3 $1.290 against their $1.40 stops).

**Manual cumulative checkpoint (the owner's procedure).** From `backend/`, after **every** command:

```sh
for f in target/llm-benchmark-v0177/quality-*/summary.csv; do tail -n1 "$f" | awk -F, -v f="$f" '{printf "%s %s\n", f, $20}'; done | awk '{print; s+=$2} END{printf "TOTAL %.4f of 4.00\n", s}'
```

(Column 20 of the last line of each `summary.csv` is `conservativeUsd`; the command was checked on the `v0.176.0` directories and printed $3.0342.)

1. **Do not start a command if `TOTAL` plus that command's stop plus its overshoot allowance (0.07 for A3/B3, 0.01 for the others) exceeds 4.00.** Stop and report instead.
2. After the smoke pass the total should be near $0.16 (`v0.176.0`: $0.158); above $0.40, stop and report.
3. After the smoke pass and again at the end, compare the total with the OpenAI dashboard usage for the key's project. **The dashboard is the authority, the meter is an estimate**; if the dashboard figure is more than 20% above the meter, stop and report.
4. A command that ends in `SPEND_STOP` leaves missing pairs, recorded and never re-run without separate approval. Any re-run is counted in `TOTAL` and must pass rule 1.
