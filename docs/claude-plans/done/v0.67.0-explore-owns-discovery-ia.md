# Plan: "Explore Owns Discovery" IA Convergence — scope addition to v0.67.0

## Context

After `v0.67.0 — Explore Convergence` shipped to the `releases/v0.67.0` branch (implemented by Codex, independently audited by Opus, PR #949 merged into the release branch — but **not yet signed off, not yet merged to `main`**), the owner had a follow-up design discussion with GPT. GPT proposed a cleaner Information Architecture principle: every major authenticated page should answer exactly one user question, and `/explore` should become the *single* owner of content discovery — finding new Official Review Sets / public notes the user doesn't already have — rather than that responsibility being duplicated across the Review Sets (Collections) page and Dashboard.

**One factual correction to the framing this arrived with:** the request described Explore Convergence as "already in progress, but development has not started yet," aimed at "v0.64.0." Neither is accurate — the feature is fully implemented, independently audited, and merged into `releases/v0.67.0`. What *is* true, and what actually makes this workable as "add to the same release": `v0.67.0` has not been signed off yet, so new scope can still land in it as an additional PR before signoff, same as everything else in this release.

Three research passes against the real code (not GPT's description alone) found the actual scope is larger than GPT's message named: Dashboard has its own, separate discovery content (`DashboardCommunityNotesSection`, `DashboardEmpty`'s "ready-made Review Set" link, and `DashboardStudyPlanSection`'s own discovery-mode rendering) that doesn't route through `/explore` at all today. The owner explicitly decided to extend this change to Dashboard too, and to formally document GPT's principle as a locked doctrine in the same change. A further finding — `DashboardPrimaryCollectionHero` already renders the user's primary set at the top of every Dashboard, making `DashboardStudyPlanSection`'s "continue" mode a second, redundant rendering of the same thing lower on the page — surfaced a real decision point; the owner chose to ship the smaller, lower-risk fix now (pointer-mode only for the no-primary case) and log the continue-mode/Hero duplication as a Known Limitation for a separate follow-up, rather than expand this change further.

This also deliberately reopens a question `v0.67.0`'s own original scoping explicitly closed (`docs/product/ROADMAP.md:1154`: "This initiative does not reopen that") and completes a convergence direction that was drafted years ago and deferred (`docs/product/ROADMAP.md:1280`, "Review-Set-Centric Navigation," gated on "the Primary Review Set concept proving useful in real usage" — now judged satisfied, given Primary has been load-bearing infrastructure since v0.40.0 through v0.59.0's Dashboard reorg). Both of these get recorded explicitly in `ROADMAP.md`, not silently overridden.

## What ships

### 1. Collections / Review Sets page (`frontend/app/collections/collections-page-client.tsx`) — becomes pure workspace

- Delete the `DashboardStudyPlanSection` import and its render block (currently ~`:373-381`) — both its continue-mode and discovery-mode. The owned-collections grid below it already surfaces the primary set via `PrimaryIndicator` and primary-first ordering, so continue-mode here is redundant; discovery-mode is now Explore's job entirely.
- Repoint the header CTA (currently a hardcoded, non-label-aware `"Browse official plans"` → `/collections/published?ref=/collections`, ~`:289-296`) to `` `Explore official ${labels.plural}` `` → `/explore` via a new `buildExploreUrl()` helper (see below). This also fixes a pre-existing bug (the label never went through `getCollectionLabels()`).
- Remove the now-dead `courseProgram` state (fetched via `getMe()` solely to feed the deleted section) — real cleanup, not scope creep; leaving it in breaks lint (`no-unused-vars`).
- `docs/features/collections.md` needs updating to match (currently documents the removed section and link at `:125`, `:860-874`).

### 2. New shared URL-building module — `frontend/lib/explore-url.ts` (new file)

Mirrors the existing precedent in `frontend/lib/public-library-url.ts` (parse + build colocated in one module) — this is exactly the kind of hardcoded-string drift that module already exists to prevent, and the Collections page CTA above is a live example of it happening anyway.

- `EXPLORE_PATH`, `EXPLORE_TAB_QUERY_PARAM`, `EXPLORE_SOURCE_QUERY_PARAM`, `ExploreTab`, `resolveExploreTab` (moved out of `explore-page-client.tsx`, which currently has private copies), and `buildExploreUrl({ tab?, source?, filters? })`, delegating filter-param handling to the existing `buildPublicLibraryUrl`.
- `source` (not `ref`/`from`, which are taken by other existing conventions) identifies which page a pointer click originated from — `dashboard`, `collections`, etc. — matching this codebase's existing `discoverySource` precedent (`published-plans-page-client.tsx`).
- `explore-page-client.tsx` imports from this module instead of keeping private copies, and passes `source` through as `metadata` on its existing `AnalyticsPageViewTracker` call (**must be `useMemo`'d on the `source` param** — the tracker's effect deps include `metadata`, so an inline object literal would re-fire the event every render).

### 3. Dashboard — pointer, not duplicate, discovery

**`DashboardStudyPlanSection`** (`frontend/app/dashboard/dashboard-study-plan-section.tsx`) gains a new prop, `discoveryPresentation?: "full" | "pointer"` (default `"full"`, so onboarding's two call sites — which pass neither this nor the props being removed — are unaffected). `viewAllHref` and `browseWhenEmpty` (and the now-unused `matchCount` state) are removed entirely — nothing else consumes them once the Collections page call site is gone.

- Continue-mode (`primaryCollectionId` resolves to a real collection) is **unchanged** in this pass — ships as today, per the owner's decision above.
- Discovery-mode, when `discoveryPresentation === "pointer"`: **do not** let the existing `courseProgramPending` gate run — short-circuit *before* it, or the component silently returns `null` forever once its `listPublicStudyPlans` effect is skipped. Render a small local `ExplorePointerCard` instead (dashed-border `Card`, matching the file's existing empty-state treatment) linking to `buildExploreUrl({ source: "dashboard" })`. The unconditional "set your course/program" nudge and the `#browse-all` fallback card are dropped in pointer mode (both are discovery-motivated); they stay as-is in `"full"` mode for onboarding.
- Both Dashboard call sites (`frontend/app/dashboard/page.tsx`, the STUDENT/PROFESSIONAL branch and the BOARD_EXAM branch) pass `discoveryPresentation="pointer"` and drop `viewAllHref`/`browseWhenEmpty`.

**`DashboardCommunityNotesSection`** (`frontend/app/dashboard/dashboard-community-notes-section.tsx`) — kept as-is structurally (it's already a bounded, filter-free, 4-item teaser with one see-all link — not "discovery" under the doctrine's own teaser exception). Only its outbound link changes: `"See all in Public Library →"` → `"See all in Explore →"`, pointing at `buildExploreUrl({ tab: "notes", source: "dashboard", filters: { courseProgram } })` instead of `/public/library`.

**`DashboardEmpty`** (`frontend/app/dashboard/dashboard-empty.tsx`) — its "Or start from a ready-made {singular} instead" link repoints from `/collections/published?ref=/dashboard` to `buildExploreUrl({ source: "dashboard" })`. Copy stays unchanged (deliberately distinct wording from the pointer card, since a zero-note, no-primary learner will see both).

### 4. New locked doctrine — `AGENTS.md`'s existing `### Page Responsibility Rule` (currently ~`:830-838`)

That section already exists and already has this exact shape (Dashboard/Library/Public Library/etc., one line each) — extend it in place rather than creating a second copy elsewhere. It's also already stale (`Public Library = discovery` is now wrong; no Explore/Review Sets rows exist) — fixing it is required regardless of scope.

New table: Dashboard / Review Sets / Library / Explore / Progress / Companion / Public Profile / Profile / Settings, each with its one question (Explore's: "What material exists that I don't have yet?"). Locked consequences to state explicitly:
- `/explore` is the single owner of content discovery; no other authenticated page may render an inline discovery catalog, adopt-picker, or public-note browse grid.
- Other pages may **point at** Explore (a link, a single pointer card); they may not **do** Explore's job.
- A bounded teaser (fixed small count, no filters/paging/sort, no adopt/copy action, one see-all link) is not discovery — this is what keeps `DashboardCommunityNotesSection` compliant without becoming a duplicate catalog.
- `/public/library` and `/collections/published` remain canonical, separately-addressable routes (deep links, SEO, anonymous access) — this is a navigation-level claim, not a route deletion. **Do not edit `docs/features/public-library.md:5` or `docs/features/exam-hub.md:85`'s "does not replace" hedges — both remain true as-is.**
- `/onboarding` is exempt — a temporally-scoped first-run wizard, not a persistent nav page; its `context="onboarding"`/`"practice-first"` full-adopt surface is unaffected by this whole change.
- Recorded as a locked doctrine in the same category as "Coach vs. Companion" and "Curation, never generation" — a deliberate, dated rule, not informal convention.

Also update while touching this: `AGENTS.md`'s separate `## Navigation Structure` section (~`:989`, still lists the pre-v0.67.0 `Dashboard / Library / Public Library` sidebar grouping — missed when v0.67.0 shipped), and `docs/product/SPEC.md`'s duplicated copy of both the sidebar grouping and the responsibility list (~`:1036`, `:1050-1055`) — replace SPEC's copy with a pointer to `AGENTS.md` as canonical rather than maintaining a third copy.

### 5. `ROADMAP.md` housekeeping (explicit record, not silent override)

- `:1280` "Review-Set-Centric Navigation" — record its stated gate (Primary Review Set proving useful in real usage) as now satisfied, and that the drafted "eventual nav shape" is now reached.
- `:1154` — add a dated note that this line ("Explore Convergence does not reopen that") is superseded 2026-07-30 by this scope addition, and why.
- `:9`/`:232` (Current Release Baseline / Phase 2 note) — record the mid-release scope addition, and amend the `[CHECKPOINT — due 2026-09-13]` framing: once Dashboard/Collections funnel into Explore via pointers, the "pre-launch baseline on the two nav entries Explore replaces" comparison needs pointer-driven views (`EXPLORE_VIEWED` `source` metadata) segmented out from nav-driven ones to stay meaningful.
- `:351` — correct a now-inaccurate claim (`DashboardStudyPlanSection` no longer fires on the Collections page; Library's own tip is about creation, not adoption — already stale independent of this change).

### 6. Known Limitations to log at signoff (not silently dropped)

- **Dashboard's continue-mode still duplicates `DashboardPrimaryCollectionHero`** for users with a primary set — deferred per the owner's decision above, not fixed in this pass.
- Anything else the implementation or its audit turns up, per this project's standard practice.

## Sequencing

Two PRs, in this order (the second only compiles once the first stops passing the props being removed):

1. **`lib/explore-url.ts` + Collections page change + doctrine/ROADMAP docs.** Low-risk, isolated, no shared-component surface change.
2. **Dashboard changes** (`DashboardStudyPlanSection`'s new prop, both call sites, `DashboardCommunityNotesSection`, `DashboardEmpty`) **+ remaining docs.** Higher-risk — touches a higher-traffic page; the biggest real risk is the pending-gate short-circuit (skipping the discovery fetch without guarding the existing `courseProgramPending` check would leave the section silently rendering blank on every Dashboard load with no primary set).

Given the size (2 pages, a shared component's prop surface, a new module, ~9 docs, ~7 test files) and that it spans frontend-only but well past 5 files, this routes to **Codex** per this project's task-routing table — write the Codex prompt(s) next (one per PR, or one combined Long-mode prompt sequencing both), not direct implementation.

## Verification

- `tsc --noEmit`, `npm run lint`, full Jest suite — standard gate, per this project's convention, on the merged state of both PRs together (not just each PR in isolation), since PR2 depends on PR1's removals.
- New test coverage required (not just updates to existing tests): `DashboardStudyPlanSection` pointer-mode — no-primary renders the pointer card and **never calls `listPublicStudyPlans`**; primary-pending-lookup renders nothing (no flash); primary-not-found still renders the pointer, not the old course/program nudge. `lib/explore-url.ts` — exact-string assertions for the URL shapes it builds. Explore page — `EXPLORE_VIEWED` carries `source` when present and fires exactly once (regression guard against the `useMemo` trap).
- Manual real-browser check on a no-primary account (the pending-gate risk can't be caught by tests alone if the short-circuit is placed wrong) and a `BOARD_EXAM` practice-first onboarding walkthrough (onboarding must render byte-identical — it passes none of the removed/added props, so a regression there would be silent).
- Existing tests to treat as a hard regression gate, not touched: the ~14 `dashboard-study-plan-section.test.tsx` tests exercising default (`"full"`) presentation — this is onboarding's only remaining coverage.
