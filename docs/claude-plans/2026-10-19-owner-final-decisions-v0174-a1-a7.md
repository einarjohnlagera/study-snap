Release Implementor — Final Owner Decisions for NoteLib v0.174.0

I've reviewed the consolidated v0.174.0/v0.175.0 implementation plan and the remaining open decisions.

Below are my consolidated owner decisions for A1–A7. These supersede the previous partial responses.

## A1 — Model Routing Scope: APPROVED

Keep v0.174.0 focused on the Study Pack generation family.

- FREE → `gpt-6-luna`
- Plus/Pro → `gpt-6.1-sol`
- Official NoteLib curation (ADMIN) → `gpt-6.1-sol`, regardless of the ADMIN account's subscription tier.

Apply the appropriate routing to Study Pack generation, summary regeneration, note-from-topic generation (single and bulk), Official template seeding, and malformed-quiz repair.

Pin latency-sensitive interactive quiz and practice workflows to their current models for v0.174.0, including Challenge Quiz, +5 Questions, Adaptive Practice, Board Exam, Long Exam, and other applicable interactive quiz paths.

Defer Challenge Quiz tier-specific routing and the approved hybrid quiz preparation experience to v0.175.0.

Do not introduce an unvalidated interactive quiz latency regression.

## A2 — Interview Practice and Companion: APPROVED

Preserve their existing generation model for v0.174.0.

I have verified that the current production value of `LLM_MODEL_PREMIUM` is `gpt-4.1`.

Therefore, approve the proposed temporary `LLM_MODEL_PAID_INTERACTIVE = gpt-4.1` pin for the applicable Interview Practice and companion generation paths.

Keep `LLM_MODEL_CRITIQUE` unchanged.

Do not migrate these interactive paths to Sol without appropriate benchmarking and latency validation.

Document the temporary model pins and ensure they are replaced before the existing models' retirement deadline. Do not assume the v0.175.0 Challenge Quiz work automatically covers every other interactive workflow.

## A3 — Malformed-Quiz Repair: APPROVED

Use the Study Pack owner's current effective subscription tier when selecting the repair model:

- FREE → Luna
- Plus/Pro → Sol
- Official ADMIN curation → Sol

Do not use the plan that the learner held when the Study Pack was originally generated.

Do not automatically regenerate or repair all historical Study Packs.

Preserve existing learning progress and quiz/session history.

The known stale `model_used` / `model_tier` metadata limitation must be documented. Do not introduce misleading metadata or imply that a repaired pack was entirely generated by a different model.

## A4 — Long Exam Pool Size: APPROVED

Defer the proposed Long Exam pool reduction from 48 to 30 to v0.175.0.

I have confirmed that `LONG_EXAM_POOL_SIZE` has NO environment override in Render.

Therefore, production should inherit the effective value from `application.yaml`, unless another configuration source overrides it.

Please inspect the configuration and confirm the actual effective value.

Preserve the current pool size in v0.174.0. Do not reduce it simply because we are changing Study Pack models.

Re-evaluate the appropriate pool size when Long Exam's model routing and latency behavior are addressed.

## A5 — Synchronous `/study` Routes: CONDITIONALLY APPROVED

Accept the existing synchronous Study Pack generation behavior temporarily in v0.174.0.

I understand that Sol generation is estimated at approximately 27–34 seconds for the model call alone, with additional production overhead, and that provider slowdowns could reach the existing 180-second timeout.

Requirements for v0.174.0:

- Show clear generation/loading feedback.
- Prevent accidental duplicate submissions.
- Provide an actionable error and retry state when generation fails.
- Do not promise that every generation will complete within 30 or 60 seconds.
- Do not introduce blind automatic retries that risk duplicate generation, quota consumption, or overwriting a successful result.

Defer the larger asynchronous retry/recovery improvement to v0.175.0.

This temporary acceptance is based on the current limited production exposure, not a permanent UX standard.

## A6 — Monthly Official Curation Cost Alert: APPROVED

Set the initial alert threshold to USD $10 per calendar month for tracked ADMIN Study Pack curation costs.

This is an alert threshold, NOT a hard spending cap.

- Notify when the monitored estimate reaches the threshold.
- Do not automatically block generation.
- Avoid duplicate alerts for the same threshold crossing within a month.
- Make the alert's scope explicit.

I acknowledge the current monitoring limitation:

The automated estimate covers persisted ADMIN Study Pack generation tokens but does not fully cover Official template seeding, summary regeneration, or malformed-quiz repair costs.

Those additional costs must be reviewed manually through the OpenAI billing dashboard until comprehensive tracking is available.

Do not label the partial estimate as total curation spend.

We can revisit the $10 threshold after observing actual production usage.

## A7 — Production Configuration: CONFIRMED

I have personally verified the following in Render production:

1. `LLM_MODEL_PREMIUM = gpt-4.1`
2. `LONG_EXAM_POOL_SIZE` is not configured as a Render environment override.

Please verify the effective Long Exam pool size from `application.yaml` and any applicable configuration precedence.

The absence of a Render override is confirmed; the numeric pool size must still be established from the application's configuration.

A7 requires no further owner input unless the effective configuration is ambiguous or differs from the implementation assumptions.

## Release Boundaries

Preserve our approved two-release strategy.

**v0.174.0 — Enhanced Generation**
- Study Pack model migration and correct tier routing.
- Safe temporary model pins for interactive workflows.
- Official curation model routing and cost alerts.
- Monitoring, regression tests, and rollback controls.
- No mass regeneration, pricing changes, quota changes, or customer announcements.

**v0.175.0 — Challenge Quiz Preparation UX**
- Prioritize eligible question-bank reuse.
- If questions must be generated, show the preparation experience.
- Primary CTA: "Stay on this page".
- Secondary action: "Continue reviewing".
- Allow generation to continue independently in the background.
- If the learner stays, transition to the quiz pre-screen when ready.
- If the learner leaves, provide one in-app readiness notification.
- Clicking the notification must open the exact prepared quiz's pre-screen.
- Never start a timed quiz automatically.
- Add safe timeout handling, recovery, and duplicate/quota protections.
- Validate Challenge Quiz tier-specific routing before rollout.

Board Exam and Long Exam preparation improvements should be separately scoped and scheduled based on their actual workflow requirements.
