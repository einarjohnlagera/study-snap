# v0.89.0 — regeneration reproduction procedure

**Scope item 1, and it is a GATE.** Written 2026-08-19, unrun.

The claim under test: **regenerating a Study Pack can silently drop a comparison table or a Common Misconceptions block the previous version had.** One sample (`Strength of Materials`, 2026-08-04), cause unestablished.

**Pre-committed kill criterion, stated before the read:** if the optional blocks survive every round across repeated regenerations of material that clearly warrants them, the hypothesis is wrong, and `v0.89.0` rescopes rather than fixing a defect it has not demonstrated. This is the `v0.87.0` pattern.

---

## How regeneration actually works

Traced in code, not assumed:

| Fact | Where |
|---|---|
| Regeneration is the **same endpoint** as first generation — `POST /api/notes/{id}/generate` | `NoteController:203` |
| It permits an existing pack via `resolveSourceNoteForGeneration(..., true)` | `StudyPackService:196` |
| It is **async** — the note moves `GENERATING` → `STUDY_PACK_READY` | `startAsyncGenerationFromNote` |
| It **rejects a note already `GENERATING`**, so rounds must be serialized | `StudyPackService:627` |
| It **updates the pack in place** — each round destroys the previous summary | versioning rule, `CLAUDE.md` |
| It **bills quota, with no admin bypass on this path** | `StudyPackService:202` → `assertMonthlyStudyPackQuotaAvailable:1009` |

Monthly Study Pack limits: **FREE 10 / PLUS 50 / PRO 100** (`application.yaml:100-102`).

### ⚠️ Two consequences that shape the procedure

1. **Do NOT run this against the real `Strength of Materials` note in production.** It is a published curator note; regenerating it eight times would overwrite its content repeatedly, in place, with no version history — the exact defect under test, inflicted deliberately on real material.
2. **Run it locally.** Local uses the same prompts and the same real OpenAI model via `LLM_API_KEY`, touches no production row, and lets you raise the quota with `PRO_MONTHLY_STUDY_PACK_LIMIT` if 8 rounds would exhaust it.

## Probe material

Use a note whose content **unambiguously warrants both optional blocks**, so that a missing block is variance rather than a correct judgement that the block did not apply. `developer.txt:35-36` conditions them on:

- a comparison table — *"if the notes cover multiple related concepts that can be meaningfully compared"*
- Common Misconceptions — *"if the notes contain concepts that are commonly misunderstood or confused"*

So the probe needs **several comparable named concepts** and **at least two well-known confusions**. Suggested content (paste as a note body):

> Stress is force per unit area; strain is the resulting deformation per unit length. Young's modulus, the shear modulus, and the bulk modulus each relate a different kind of stress to its corresponding strain: Young's for axial loading, shear for tangential loading, bulk for uniform pressure. Elastic deformation reverses when the load is removed; plastic deformation does not. The yield point marks the transition between them, and the ultimate tensile strength is a separate, higher value that marks the maximum stress before fracture. Learners frequently confuse yield strength with ultimate tensile strength, and frequently assume stiffness and strength are the same property when a material can be stiff but weak, or flexible but strong.

That paragraph names three comparable moduli (table-worthy) and states two explicit confusions (misconception-worthy). **If a round drops a block on this material, it is dropping a block that applied.**

## Procedure

1. Start the stack and confirm `LLM_API_KEY` is set.
2. Create the probe note and generate once. Record the baseline summary.
3. Run the loop below for **8 rounds**, capturing the summary after each.
4. Score each round for both blocks and tabulate.

Eight rounds is chosen so that a per-round drop probability around 0.5 is unmistakable, and a genuinely stable output is also unmistakable. **If the first 3 rounds all drop a block, stop early — the point is made and every round costs a real LLM call.**

### The loop

```bash
#!/usr/bin/env bash
# v0.89.0 regeneration reproduction. Run against LOCAL, never production.
set -euo pipefail

API="${API:-http://localhost:8080/api}"   # 8085 if using the remapped docker-compose
EMAIL="${EMAIL:?set EMAIL}"
PASSWORD="${PASSWORD:?set PASSWORD}"
NOTE_ID="${NOTE_ID:?set NOTE_ID — the probe note, NOT a published note}"
ROUNDS="${ROUNDS:-8}"
OUT="${OUT:-/tmp/regen-probe}"

mkdir -p "$OUT"
TOKEN=$(curl -fsS -X POST "$API/auth/login" \
  -H 'Content-Type: application/json' \
  -d "{\"email\":\"$EMAIL\",\"password\":\"$PASSWORD\"}" | python3 -c 'import sys,json;print(json.load(sys.stdin)["token"])')

for i in $(seq 1 "$ROUNDS"); do
  echo "── round $i: regenerating…"
  curl -fsS -X POST "$API/notes/$NOTE_ID/generate" -H "Authorization: Bearer $TOKEN" > /dev/null

  # Serialize: the endpoint rejects a note that is already GENERATING.
  for _ in $(seq 1 120); do
    STATUS=$(curl -fsS "$API/notes/$NOTE_ID" -H "Authorization: Bearer $TOKEN" \
      | python3 -c 'import sys,json;print(json.load(sys.stdin)["status"])')
    [ "$STATUS" = "GENERATING" ] || break
    sleep 5
  done
  echo "   status=$STATUS"

  docker exec notelib-postgres psql -U ss_user -d study_snap -At \
    -c "select summary from study_packs where note_id = '$NOTE_ID'" > "$OUT/round-$i.md"
  echo "   captured $(wc -c < "$OUT/round-$i.md") bytes"
done

echo
printf '%-8s %-12s %-24s\n' ROUND TABLE MISCONCEPTIONS
for i in $(seq 1 "$ROUNDS"); do
  f="$OUT/round-$i.md"
  grep -qE '^\|.*\|' "$f" && T=yes || T=NO
  grep -qi 'Common Misconceptions' "$f" && M=yes || M=NO
  printf '%-8s %-12s %-24s\n' "$i" "$T" "$M"
done
```

## How to read the result

| Outcome | Verdict |
|---|---|
| Both blocks present in **every** round | **Hypothesis wrong.** Rescope the release; do not fix. Record that the prompt's conditional wording does not in practice cause loss on qualifying material. |
| Either block **absent in some rounds, present in others** | **Reproduced.** The mechanism is per-round re-decision on an optional block. Proceed to scope item 2. |
| Either block absent in **every** round including the first | **Not the defect under test** — the model is not producing the block at all on this material, so the probe is wrong, not the product. Strengthen the probe content and re-run before concluding anything. |

⚠️ **Record the raw summaries, not just the scores.** A block can also degrade rather than vanish — a two-row table where there were four, or one misconception where there were three. The scores above are binary and would call that a pass. Diff the rounds against each other before accepting a "stable" result.

⚠️ **This measures the summary only.** The original observation was about the summary, but if step 1 reproduces, check whether `keyConcepts` and `quiz` vary across the same rounds before scoping a fix — a fix aimed only at the summary would leave the same class of loss elsewhere.
