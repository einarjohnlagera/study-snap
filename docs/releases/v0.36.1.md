# Release Notes: v0.36.1 — Post-Release Fixes

## Release Theme

Close out issues surfaced immediately after v0.36.0 shipped — a Builder dead-end, vocabulary drift, and stale docs from the initial post-signoff audit, plus a second round of Builder navigation, layout, and Note Detail fixes found while using the release in practice.

## Key Features

**🧭 Builder Goal-Creation Reliability**
- `Add Subject Plan` now also requires `collection.parentCollectionId === null`, so an already-nested Subject plan with zero notes no longer shows a control that always fails server-side.
- Subject plan detail pages back-link to their parent Goal instead of the flat Study Plans list, once the parent's title has resolved.

**📐 Builder Navigation & Layout**
- Standalone header `Refresh` removed from both Builder branches; a `Refresh` control now lives inside the Add-notes modal, scoped to just the note list.
- Goal and leaf collection detail now share one `PlanHeroCard` layout (badges above the title); Goal's badge shows subject count instead of a meaningless notes-ready count.
- Subject-block and note-row `Move up`/`Move down`/`Up`/`Down` controls moved into a compact icon cluster next to the drag handle, so action rows are fixed at two items and never wrap — fixing a cramped, orphaned-button layout at tablet widths (iPad Air/Mini) that a breakpoint-only fix didn't fully resolve.

## Polish & Fixes

- `dashboard-goal-card.tsx` and `goal-nudge-card.tsx` now say "N concepts due" instead of "N concepts due for review", matching the locked readiness vocabulary; `% mastered` on both cards is unchanged.
- Note Detail readiness summary moved from above all tab content to just before Performance Overview, so it no longer sits above whatever tab a user is reading.
- `AGENTS.md`'s "Study Plan Readiness Rule" and documentation baseline updated to match shipped v0.36.0 behavior.
