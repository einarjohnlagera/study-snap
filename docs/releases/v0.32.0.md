# Release Notes: v0.32.0 — Account & Communication Controls

## Release Theme
Give users real control over their account and the email NoteLib sends them, and close the associated privacy and compliance gaps (GDPR right-to-erasure + portability; CAN-SPAM/GDPR one-click unsubscribe).

## Key Features

**🗑️ Account Deletion (with a 30-day safety net)**
- Settings → Account now offers account deletion with type-to-confirm `DELETE`. The account immediately enters a `PENDING_DELETION` state, all sessions are revoked, and login is blocked — but **nothing is destroyed yet**.
- Within a 30-day grace window, logging back in with valid credentials **reactivates** the account (login surfaces an `ACCOUNT_PENDING_DELETION` prompt). An active paid pass is flagged ("you'll lose N days, no refund") before confirming.
- After the window, a scheduled purge runs the irreversible cleanup: private notes and personal practice data are deleted, public notes and retained financial records are anonymized to a "deleted user" sentinel, active subscriptions are terminated, and `analytics_events` are left untouched. Each user's purge is isolated in its own transaction.

**📥 Download My Data**
- A new owner-only `Download my data` export returns the user's own account basics, notes, Study Packs, collections, and a practice summary as a single JSON file — GDPR data portability. It's rate-limited, principal-scoped, and intentionally excludes secrets, analytics, and financial records.

**✉️ Email Preferences Center**
- The ad-hoc "Study Reminders" card is replaced by a dedicated Email Preferences section covering four optional categories — study reminders, weak-concept nudges, weekly summary, and Product news & tips — with transactional account/billing email shown as an always-sent info note, not a toggle.

**🔕 Opt-in by Default for Weekly & Marketing Email**
- The Sunday weekly summary and the new marketing category (`Product news & tips`) both default **OFF**; re-engagement campaigns now only reach users who explicitly opt in.

**🔗 One-Click Unsubscribe**
- Optional emails now carry a signed, stateless unsubscribe link plus RFC 8058 `List-Unsubscribe` / `List-Unsubscribe-Post` headers. The unauthenticated endpoint flips the matching preference idempotently (no account-existence leak), and the public `/unsubscribe` page links back to the preferences center. Transactional emails are never unsubscribable.

## Polish & Fixes
- **Rate-limiter memory hotfix (prod OOM):** the in-memory `Auth`/`Ai`/`Ocr` rate-limiter maps never evicted buckets, so an IP-keyed auth flood leaked heap until prod OOM'd and restarted; each limiter now runs a scheduled 60s sweep that removes expired buckets. (Shipped first as a hotfix on the v0.31.2 line, then back-merged into this release.)
- **Email deliverability hardening:** `ResendEmailService` retries on HTTP 429 (honoring `Retry-After`, else exponential backoff, max 3 attempts) so transactional email isn't dropped during a send burst; the real capacity fix remains upgrading the Resend tier.
- **Settings UI polish:** custom themed checkboxes (replacing default browser ones), a blue dark-theme-friendly "Always sent" info banner, and a clearer Account action row (Sign Out primary, Delete Account separated with a calm-red entry and solid-red modal confirm).
