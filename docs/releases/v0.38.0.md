# Release Notes: v0.38.0 — Read-Path Optimization Pass

## Release Theme

Extend the projection discipline from v0.37.3 across the remaining hot read endpoints — a latency and DB-load pass, not a memory fix (that was the 2GB instance upgrade) — cutting per-request payload on the app's busiest read paths.

## Key Features

**⚡ Session-History Read Path**
- `QuizSessionHistoryService` used to load every completed quiz session for a user — full `sessionState`/`sessionMetadata` JSONB, no limit — then filter in memory. It backed three hot paths: the collections list, collection detail, and quiz recent-sessions.
- Direct note participation now resolves via a grouped JPQL projection that selects no JSONB at all; only completed Long Exam / Challenge sessions (the only multi-note modes) are scanned for `sourceNoteRefs`. Recent-sessions candidates are now bounded at the database before the existing in-memory participation filter and limit apply.

**⚡ Note Collection Detail Projections**
- Private and public plan detail (`get()` / `getPublic()`) used to materialize full `NoteEntity` (unused `content`), full `StudyPackEntity` (unused `quiz`/`source_text`), and full `GeneratedQuizEntity` (only the id was read) for every item.
- Notes and generated quizzes now route through lean record projections; Study Packs reuse the existing `findProgressViewsByNoteIdIn` projection from v0.37.3. Study Pack status, due concepts, public-note filtering, and missing-note behavior are unchanged.

**⚡ Private Library List Projection**
- `listMine` loaded the entire `quiz` JSONB column per page item just to call `.size()`, and never read `source_text`.
- The page fetch now runs through a lean projection with no `quiz`/`source_text`; quiz counts for just the returned page are resolved through an isolated PostgreSQL-native `jsonb_array_length` query. Cursor ordering, pagination, and question counts are unchanged.

**⚡ Goal Per-Child Readiness Batch**
- `getGoal` used to call the full single-plan readiness computation once per Subject-plan child — an N+1 that scaled linearly with a Goal's child count (deferred from v0.37.3).
- Child note unions, Study Pack progress projections, note-subject resolution, and concept-health lookups are now all batched once across every child, then partitioned per child. Per-child failure isolation, child ordering, Goal rollups, and the single-plan `getReadiness` endpoint are all unchanged.

## Polish & Fixes

- No schema, endpoint, or DTO change anywhere in this release — every response is byte-identical to before, verified with new real-Hibernate (`@SpringBootTest` + H2) tests rather than mocks, per the v0.37.3 projection-detection lesson.
- All four changes shipped as separate Codex-generated PRs, each audited against its own real-Hibernate test suite and a full local build before merge (1028 tests, 0 failures).
- Considered persisting `study_packs.question_count` to fully eliminate the native `jsonb_array_length` read and close its H2 test gap; deferred to the backlog — the write-path sync burden (every quiz mutation would need to keep it current) isn't justified until the library list shows up in slow-query logs.
