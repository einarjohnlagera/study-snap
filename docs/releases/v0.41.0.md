# Release Notes: v0.41.0 — Learning Companion (MVP)

## Release Theme

Add a persisted, curator-authored guidance layer on top of Official Review Sets — the first phase of the Guided Learning Initiative, turning a Review Set from "a collection of notes" into a premium guided learning experience.

## Key Features

**🧭 Learning Companion**
- A top-level Review Set can now carry an authored Companion — four sections: Overview, Study Strategy, Common Mistakes, and FAQ — stored as a nullable JSONB column on the collection row, 1:1 with a top-level Review Set only.
- ADMIN-only `Manage Companion` action with a full authoring modal, wired to full-replace and clear endpoints.
- Collection detail now renders the authored Companion for learners in both Goal and leaf views, using the existing markdown prose renderer and skipping empty draft sections.
- Publishes with the Review Set and travels on adopt (added to the copied set alongside notes and Study Packs); excluded from same-owner self-copy, same category as other generated content. FREE for all learners — zero paid uplift by design.
- Manual authoring only in this version; no AI generation yet, and Study Timeline / Final Checklist are deliberately deferred to link the live weekly countdown and readiness features when built, never re-authored as static prose.

## Polish & Fixes

- Fixed a cross-PR terminology gap where "Companion" copy on the collection detail page was hardcoded instead of resolving through `getCollectionLabels`.
- Moved `Primary`/`Adopted` identity badges out of the flattened row they shared with the notes count and execution-status badge, into their own tier next to the title (detail page) or directly under it (list cards).
- Fixed `/collections` list cards stretching unevenly per row on long titles; cards now share a uniform row height with the notes-count/last-updated footer pinned to the bottom regardless of title length or badge count.
- Added success toasts for editing details, setting/removing primary, and saving/removing a Companion on the collection detail page, plus a delete confirmation toast on the `/collections` list page. Scoped to Review Set actions for now; app-wide CRUD feedback is tracked as a future initiative.
- Pre-signoff pressure test caught and fixed two cross-PR issues: `adoptGoal`'s child-reparenting path wasn't clearing `targetCompletionDate`/`companion` the way the equivalent `updateParent()` path already does, and the new toast timers used bare `setTimeout`/`clearTimeout` instead of this codebase's `globalThis` convention.
