# Release Notes: v0.29.1 — Bulk Generation Polish

## Release Theme
Make Bulk Generation honest and ready for everyone: tell users exactly which topics failed (and why), then open the feature from admin-only to all users with a first-run experience that handles quota gracefully.

## Key Features

**📋 Partial-Outcome Reporting**
- Bulk generation now reports its real outcome instead of silently delivering fewer notes than the `Queued N notes` toast promised. `POST /notes/bulk-generate` returns a `resultId`, and the background worker writes one terminal, owner-scoped `bulk_generation_result` receipt at batch completion — including zero-failure and whole-batch-failure cases.
- `GET /notes/bulk-generate/results/{id}` is owner-scoped and read-once (it deletes the receipt after returning, guarded against a double-read race), with a 24h cleanup job sweeping any unread receipts.
- The Library keeps the immediate `Queued N notes` toast, then after the existing auto-refresh poller settles it reads the receipt and shows a **dismissible banner listing the exact failed topic strings**, with `Retry these` that pre-fills `/library/bulk-generate` with the failed topics plus the original subject, course/program, target audience, and public toggle.
- Content-first behavior is unchanged: a failed content generation still creates no note row, and post-create Study Pack failures are not counted as failed topics (the note exists and shows its own state).

**🌐 Bulk Generation Opened to All Users**
- The ADMIN-only gates are removed from the Library Create entry, the `/library/bulk-generate` route, and the bulk endpoints (now `hasAnyRole('USER','ADMIN')`), while ADMIN keeps its quota bypass and the existing profile-aware metadata resolution stays intact. Email verification and onboarding remain enforced.
- The first-run experience is quota-aware: non-admin batches classify no-row failures as either genuine **generation failures** or **note-generation quota blocks**. The Library banner offers `Retry these` only for genuine failures and routes quota-blocked topics through plan-aware upgrade CTAs (`getUpgradeCtas`) instead of looping users back into the same wall.
- The Bulk Generate page shows remaining note-generation quota when available, the single Note Create "Generate from topic" panel links to bulk generation for users with a list of topics, and Help adds a deep-linkable `/help#bulk-generate` guide.

## Polish & Fixes
- The bulk receipt is the one narrow, conscious relaxation of the v0.29.0 "no batch/progress infrastructure" rule — a terminal, write-once / read-once receipt that expires after 24h; it is not a batch-job entity, live progress table, per-item status row, or new status enum, and the broader rule still holds everywhere else.
- The receipt distinguishes generation failures from note-generation quota blocks (`V73` introduced the receipt; `V74` added the quota-blocked topic list, backfilled to empty for existing rows).
- The Note Create cross-link is a persistent navigational affordance, not a one-time guidance tip, so it stays discoverable on every visit.
