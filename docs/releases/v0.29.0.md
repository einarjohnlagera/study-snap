# Release Notes: v0.29.0 — Bulk Generation & Generation-Context Correctness

## Release Theme
Kill the one-note-at-a-time tax on seeding study content — and make generated content correct for everyone it reaches: leveled by course/program rather than the author's learner level, with profile types enforced as a real boundary and the bulk flow polished end to end.

## Key Features

**📦 Admin Bulk Generation**
- An ADMIN-only, Note-Create-aligned Library flow: one subject plus a topic list generates a note **and** its Study Pack per topic, unattended, on the existing executors with throttled fan-out and per-item isolation — one bad topic never fails the batch. No batch-job entity, progress table, or new status enum; this is orchestration over the building blocks that already existed.
- Built admin-first to seed exam-prep buckets but architected behind a removable role gate — opening it to all users later is a gate-flip, not a rebuild. Per-user quota is wired through the existing services so the all-users path is real; ADMIN bypasses it.
- Bulk-created notes set the batch `subject` (it wins over the AI subject) while still accepting the AI-refined title and tags from the Study Pack write-back.
- Paste a multi-line list to add many topics at once — splits one topic per line (CRLF-aware, never on commas), strips leading list markers (bullets and numbered prefixes, guarded with trailing whitespace so `.NET` and `1.5 inch` survive), caps with a visible notice instead of silent truncation. The logic is a pure, unit-tested `parsePastedTopics`.
- After queuing, the Library **auto-refreshes** so generated notes appear on their own (no manual refresh), and each arriving note **animates in** via the shared motion entrance. The same poller also fixes the identical single-note generation gap.

**🎚️ Generation-Context Correctness**
- Static note and Study Pack content now calibrates depth, vocabulary, terminology, examples, and embedded Quick Review material by the note-first **Course / Program** instead of the author's learner level — so shared and copied content stays appropriate for everyone in that program.
- Quiz and exam prompts plus the exam-question pool keep learner level for taker-specific difficulty (re-resolved per session). Learner level is no longer required to generate a note or Study Pack, and the vestigial bulk Learner Level field is gone.

**🛡️ Profile-Type Integrity & Server-Side Onboarding**
- Onboarding is now a real server-side boundary: content-creating and generation mutations (note create, note-from-topic, Study Pack generation, note copy, bulk generation, batch import) enforce a completed profile through `OnboardingGuardService`, closing the previously client-only bypass.
- The guard fires only for the legacy completed-but-null cohort (`profileType == null && onboardingCompletedAt != null`); users mid-onboarding and copy-on-signup are exempt, so the activation funnel is never blocked. No silent defaulting — affected users get one focused, blocking profile-type prompt that asks only what's missing.

**🎯 Challenge Quiz Adoption**
- The post-session next step now promotes **Take a Challenge** as the primary action after a strong-majority Quick Review (at most one missed concept, i.e. ≥4/5) instead of only a perfect score, keeping `Retry Incorrect Questions` as a secondary action on a single miss — aimed at the public-note conversion cohort, who land directly in Quick Review and only see this surface.
- `Copy Study Pack` on public notes now lands on the copied note's **detail page** so the full Study Pack and the Challenge Quiz entry point are visible, instead of auto-launching Quick Review. `Quiz yourself on this note` still honors its quiz promise; `Copy to My Library` still lands on detail.

## Polish & Fixes
- Profile-type guard regression fixed before ship: gating on bare `profileType == null` would have 403'd every new user's onboarding generation and silently lost copy-on-signup intent — the guard now scopes to the legacy completed-but-null cohort only.
- The Library generation poller is silent (no skeleton flicker, no pagination reset), sustained while any note is generating or the list is still growing, and bounded by a quiet window sized to exceed the sequential inter-topic gap plus a hard-cap backstop — so a large batch is not truncated mid-way and a wedged backend cannot poll forever.
- The bulk-generated note entrance animation reuses the house motion system, so it is disabled under `prefers-reduced-motion` for free; the initial list does not animate wholesale.
- Multi-line paste strips list markers paste-time only — typed input is never altered — and the import is capped at the topic max with a visible "N more weren't added" notice rather than dropping silently.
- When a bulk topic's content generation fails, no note row is created (a note without content is not persisted) and the rest of the batch proceeds; surfacing that shortfall to the user is logged as a v0.29.1 follow-up.
