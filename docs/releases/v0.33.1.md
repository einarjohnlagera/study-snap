# Release Notes: v0.33.1 — Study Plan polish & Curated Plan Coverage

## Release Theme
Make curated Study Plans credible enough to test: improve discovery and editing polish, then add a scoped Goal → Subject hierarchy and a single-canvas builder so curators can assemble real multi-level plans without changing readiness, billing, or the note-first model.

## Key Features

**🎯 Goal → Subject Study Plan hierarchy**
- Collections now support one owner-scoped nesting level through nullable `parent_collection_id`: a top-level Goal can contain child Subject plans, while Subjects continue to hold notes. The two-level rule is enforced transactionally — parent must be top-level, child must have no children, self-parent is rejected, and cross-owner parents stay hidden behind `404`.
- Goal detail lists child Subject plans with each child's existing readiness plus a rolled-up Goal readiness: `round(100 × Σ child.mastered / Σ child.total)`, returning `0` when total concepts are zero. This intentionally sums already-computed child counts and does **not** re-dedup same-named concepts across subjects.
- `/collections` now shows top-level plans only; Goal cards show child-plan counts and link to the Goal page. Leaf plan detail, label-derived sections, adopt, and `/me/progress` remain unchanged.

**🧱 Study Plan Builder canvas for Goals**
- Added `/collections/{id}/builder`, a single canvas where the Goal is the workspace, Subject plans are draggable/collapsible sections, and notes are cards inside/across those Subjects.
- The builder orchestrates existing collection APIs: add Subject = create collection + nest, rename = metadata update, delete = delete child collection only, add notes = add items, move note across Subjects = remove + add, with optimistic UI and refetch-on-settle.
- The only new backend capability is explicit child ordering: `sibling_position` plus owner-scoped `PUT /collections/{id}/children/order`. Goal children now return in sibling order with null positions last.
- This replaces the scattered nest/unnest curation path where it overlapped, while preserving the read-only learner Goal view and ordinary leaf-plan detail.

**📚 Study Plan polish for curation and scanning**
- The Recommended plan card no longer offers a re-adopt CTA for a plan the user already owns or has adopted. Owned sources show an "In your library" state and open the existing plan instead.
- Section drag on leaf Study Plan detail is scoped within each label-derived section, so dragging can no longer imply a cross-section move. To move a note between sections, change its existing Section label.
- Plan cards on `/collections` show course/program instead of description, giving learners and curators a more useful scanning signal.
- Leaf plan detail readability improved with stronger section headers, the shared Section combobox, and a clamped header description.

## Polish & Fixes
- Fixed metadata edits so title/description saves no longer wipe course/program, and course/program saves no longer wipe description.
- Kept readiness Free and derived from the existing `ProgressReportService` / ConceptHealth model — no persisted readiness fields, new thresholds, AI calls, chart library, quota changes, billing changes, or checkout changes.
- Recorded the deliberate reversal of the old "no parent/child collections" rule in the collections docs, scoped strictly to the two-level Goal → Subject model. Deeper nesting, recursive Goal adoption, module-level mastery, direct notes on Goals, and arbitrary depth remain out of scope.
