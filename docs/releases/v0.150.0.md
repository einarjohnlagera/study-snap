# Release Notes: v0.150.0 — Membership, Not a Slot

## Release Theme

Program Family membership becomes many-to-many, closing a real production bug where a brand-new
family was invisible to Note authors, and giving admins a working way to manage family membership for
the first time.

## Key Features

**🔗 A Course/Program Can Now Belong to Multiple Program Families**
- Program Family membership moved from a single, exclusive slot to a proper many-to-many
  relationship. A program like Computer Engineering can now genuinely belong to both Engineering and
  Computing & Technology at the same time, without being silently removed from either.
- This required an architecture-level change: the underlying data model previously could not
  represent a program belonging to more than one family. The owner reviewed and approved the new
  design, including a small, storage-neutral clarification to the product's own architecture
  documentation.

**🐛 Fixed: New Program Families Were Invisible to Note Authors**
- Two families created by an admin (Health Sciences and Accounting) never appeared in the "Add
  Course/Program" picker used when authoring a note — even though they showed up correctly everywhere
  else. The picker was building its own family list from existing catalog entries, so a brand-new
  family with no members yet contributed nothing to it.
- Fixed by having the picker read from the same canonical family list the admin screen already uses.
  Empty families are now selectable the moment they're created, on every authoring surface (Note
  Editor, Note Detail, Bulk Generate, and Admin).

**🛠️ Admins Can Now Actually Reassign a Program's Family**
- A previous release added the underlying capability to change an existing Course/Program's family,
  but no screen in the app ever offered a way to use it — an admin's only option was calling the API
  directly. This release adds a real Edit action to the Admin catalog table: pick any program, adjust
  its family memberships, save.

## Polish & Fixes
- A pre-signoff review found that the release's most important new test — proving that creating a
  program in two families adds only that program to the current note, never the other family members
  — used an assertion that could pass even if that boundary were later broken. Strengthened before
  shipping, and verified against a deliberate mutation to confirm it now genuinely catches the mistake
  it exists to prevent.
- Corrected two claims in the previous release's own notes: it said admins could reassign a program's
  family through the app (they could not, until this release) and that a catalog program could be
  marked inactive (no part of the app has ever been able to do that — tracked separately as future
  work, not fixed here).

## Known Limitations
- The two new families from the previous release, plus two more the team created independently since
  then (Computing & Technology, Built Environment & Design), are not yet populated with members in
  production. Populating them is a short, manual admin task planned as the next step after this
  release ships.
- Marking a catalog program inactive still isn't possible anywhere in the app — the underlying column
  exists, but nothing has ever been built to set it. This is unrelated to this release's own scope and
  is tracked as its own future item.
