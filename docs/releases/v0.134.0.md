# Release Notes: v0.134.0 — Notification Foundations

## Release Theme

Hardened the notification substrate's taxonomy, dedup identity, retention and delivery path while `notifications` was still empty in production — so the first real notification producer lands on a shape that can carry it.

## Key Features

**🏷️ Badge policy moved onto a notification category**

- `NotificationCategory` is now the single owner of numeric-badge policy; `NotificationType` is producer identity and delegates to its category.
- One flag yields two complementary sets — badge-eligible and retention-expirable — with a test asserting they partition every category, so the two can never silently drift apart.
- `ACTION_REQUIRED` is marked transitional in code: it has no producer today and the first real producer replaces it.

**🔑 Dedup keys can now tell producers apart**

- The dedup discriminator widened from a bare entity id to a string, so two producers holding the same entity id can no longer collide on one key.
- Existing announcement keys are byte-identical, and the unique index remains the sole idempotency mechanism — no pre-insert existence check was added.

**🔔 The badge now reads the server, not a string literal**

- Notification responses carry an explicit `actionable` field derived from the category.
- The inbox stopped inferring badge policy from a `"ANNOUNCEMENT"` string comparison, which would have mis-counted the moment a third non-actionable type existed.

**🗂️ Announcements no longer pile up unread forever**

- Retention now expires unread non-actionable notifications at the existing 90-day window, while unread actionable ones are still kept indefinitely — a pending request must never vanish.
- Previously an unread row was immortal: one announcement to every user left a permanent row per recipient, because most people never open the bell.

**⚡ Publishing an announcement no longer waits for delivery**

- Fan-out moved off the admin request thread onto a bounded background executor, sized against the database connection pool rather than throughput.
- Publishing now reports how many recipients were queued and says delivery is in progress, instead of claiming a delivery that has not happened yet.
- A rejected queue leaves the announcement published and tells the admin to press Publish again — the recovery that already worked, kept working.

**📈 Delivery became observable**

- Four new metrics: notifications delivered by type, duplicate-key conflicts, fan-out duration, and fan-out rejections.
- The duplicate-conflict counter is the idempotency guard's own health signal — the one number that shows the unique index doing its job.

## Polish & Fixes

- Added a partial index matching the inbox's exact filter and sort, verified against a real PostgreSQL container rather than only parsed.
- Removed a fan-out helper left with no callers once publishing resolved its own audience.
- Corrected the notification feature documentation, whose descriptions of dedup keys, badge policy, retention and the publish response had all been overtaken by the code.
- Recorded that a permanent-suppression defect was found in the *proposed* design for the next release's notification producer, and corrected before any of it was built.
