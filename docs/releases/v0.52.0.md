# Release Notes: v0.52.0 — Proactive In-App Feedback Prompts

## Release Theme

Stop waiting on cold outreach to churned users and instead surface the existing feedback pipeline proactively, at the two moments a current user's experience is freshest — right after their first-ever quiz result, and when they return after a period of inactivity — plus a design pass on the feedback pipeline itself so both the ask and the review of it hold up under real use.

## Key Features

**💬 First-Quiz-Ever Feedback Prompt**
- Every completed quiz mode (Quick Review, Challenge Quiz, Board Exam, Adaptive Practice, Long Exam) now resolves an owner-wide "has this user ever completed a session before" signal before returning its completion response.
- The result screen shows a one-time "how did that go?" ask specifically the first time that signal is true, instead of every time — Long Exam gains the same inline feedback entry point the other modes already had.
- Falls back to the existing generic helpfulness panel whenever the signal can't be resolved, so feedback collection is never silently lost.

**👋 Return-After-Inactivity Feedback Prompt**
- A new `GET /feedback/context` signal reuses `RetentionService`'s existing inactivity definition and threshold — no new cutoff, no change to the existing 3-day inactivity email or its scheduler.
- Dashboard shows a one-time "welcome back" ask for returning users with prior quiz history; if both moments overlap, the first-quiz ask takes priority so a user is never asked twice.

**🎨 Feedback Modal & Admin Detail View**
- Restyled the Send Feedback modal: a quieter icon-led header, quick-start chips with a dismissible "Reporting: X" context indicator, and a threshold-aware character counter — no change to what gets submitted or where.
- Admin's Recent Feedback table gained a per-row read-only `View` modal (reusing the existing Refund-modal pattern) showing the full message, clickable URL, email, timestamp, and status — all from data already loaded, no new backend read.

**📎 Optional Screenshot Attachment**
- Users can attach one PNG/JPEG/WebP screenshot to feedback, downscaled client-side to roughly 1600px and capped at 2MB, sent as a second best-effort request after the existing text submission succeeds.
- Bytes live in a new one-to-one `feedback_image` table — kept off `FeedbackEntity` on purpose so Admin's existing list read never hydrates image bytes; the detail modal fetches the image lazily, only on open.

## Polish & Fixes

- Corrected an early implementation of the first-quiz signal that had silently widened the pre-existing, currently-accruing v0.48.0 open-loop experiment field instead of introducing its own — the experiment's cohort scope is untouched, and the new signal now has its own name (`isFirstCompletedSessionEver`).
- Corrected the screenshot feature's notification email so it always sends immediately at text submission, rather than waiting on the separate, best-effort image upload to resolve — a network hiccup on that optional second request can no longer silently swallow the notification for an already-saved feedback submission.
- Full pre-signoff pressure test across all three merged PRs found and fixed three gaps no single PR's diff could see: the screenshot attachment controls stayed enabled during an in-flight submission (could let a user swap the file after it was already captured for upload); Adaptive Practice never unblocked the feedback panel when a completion had no session id; an oversized screenshot that needed no resizing showed the wrong ("...after resizing...") error copy.
