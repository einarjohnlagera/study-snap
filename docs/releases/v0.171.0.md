# Release Notes: v0.171.0 — Checkout, Recovered

## Release Theme

Closes the checkout-abandonment leak a production funnel audit found, and adds the one piece of
signup attribution the product was missing: which entry surface actually brings people in.

## Key Features

**💳 Checkout reminders, the easy way**
- A production read of all 16 failed Xendit invoices showed a clean story: nobody picked a payment
  channel, nobody attempted a payment — every one just expired, unengaged, within 24 hours. Not a
  declined payment, not a price objection.
- Rather than build a reminder-email system from scratch, this ships Xendit's own native
  payment-reminder notification — one new field (`payer_email`) on the invoice NoteLib already
  creates, plus a dashboard setting the owner enabled. No new job, no migration, no template to
  maintain going forward.
- Whether the reminder actually arrives inside the 24-hour window is still unconfirmed — Xendit
  sends it directly to the payer, so there's no event NoteLib can watch for. A real test checkout is
  the only way to know, tracked as an open checkpoint due 2026-10-21.

**📍 Signup entry-surface attribution**
- New accounts now record which kind of page first brought them in — the landing page, a public
  note, Explore, or an Exam Hub — alongside the UTM and referrer data NoteLib already captured.
- Extends an existing, already-shipped mechanism rather than building a new one: no new anonymous
  cookie, no new capture path, just one more column on the same first-touch-attribution record.

## Polish & Fixes
- Investigated a third, previously-unknown Hikari long-connection-hold pattern found while reading
  a prior release's own monitoring checkpoint. Unlike the two mechanisms that release fixed, this one
  traces to an already well-optimized public library discovery query — the connection holds appear to
  coincide with real database CPU pressure rather than a single bad query, most likely driven by that
  page having no caching at all. Left as an open decision for the owner (cache the response, add HTTP
  caching, or trim the query count) rather than guessed at.
- Corrected an earlier overclaim in the monitoring record: a finding had cited "the full stack trace"
  for three leak occurrences when only two had actually been individually checked. Verified the third
  before the claim was allowed to stand.
- Two already-open documentation pull requests (BSCS Year 1 curriculum shaping and the dual-AI
  release workflow redesign) were merged into this release branch instead of sitting further behind.
