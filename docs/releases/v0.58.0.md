# Release Notes: v0.58.0 — Reusable Practice Assets & the Return Loop

## Release Theme

Turn Challenge Quiz's always-fresh, disposable AI-generated questions — and Board/Long Exam's dormant per-user pool — into persisted, revisitable practice assets a learner can return to and redo what they missed, closing the one gap left in the product's "curation, never generation" identity.

## Key Features

**🔁 Usage-Driven Exam Pool Activation**
- Board Exam Mode and Long Exam's existing per-user question pool — previously built but dormant behind `examPoolPrewarmEnabled=false` — now seeds and reuses a learner's own pool after real usage, instead of silently regenerating a fresh set every session.
- The eager prewarm-on-generation kill switch stays off; this is forward-looking infrastructure, since production currently has zero PRO users on these modes.

**🎯 Challenge Quiz Question Bank**
- Every newly LLM-generated Challenge Quiz question — on session start and on "+5 Questions" — now persists into an owned, per-user, per-Study-Pack bank instead of being discarded at the end of the session.
- Future sessions on the same Study Pack claim eligible same-learner-level banked questions first and generate only the shortfall, delivering questions with less new LLM cost over time.
- Bank persistence is best-effort: a read/write failure falls back to the existing always-fresh generation path and never blocks a session.

**↩️ Redo Missed Questions**
- Completed Challenge Quiz sessions now recommend **Redo Missed Questions** once a learner has at least three owned, same-learner-level bank entries last answered incorrectly.
- The entry starts an ordinary, quota-exempt Challenge session sourced only from those claimed questions, with zero LLM call to start — no quota impact, full progressive controls, and normal ConceptHealth writes on completion.
- Distinct from Quick Review's unchanged **Retry Incorrect Questions** link.

## Polish & Fixes

- Fixed a migration issue caught during PR1's audit: the new question-bank table's `origin_session_id` was non-nullable with `on delete cascade`, which would have deleted a banked question outright when its originating session was deleted. Changed to nullable with `on delete set null`, matching the existing `claimed_session_id` pattern.
- Added test coverage the audit found missing: bank read/write failure degrading gracefully to fresh generation, and a mixed banked-plus-generated shortfall on session start.
- Sharpened the "zero LLM call" claim (service docstring, `docs/features/challenge-quiz.md`, this file) to specify it covers session start only — a redo-missed session's "+5 Questions" still falls through to normal LLM generation, caught during the full pre-signoff pressure test.

## Known Limitations

- **Copies don't inherit the source's bank or pool.** A learner who copies a popular note (including adopting an Official Review Set, which is a copy under the hood) starts with an empty bank/pool and independently regenerates everything via the LLM, even though the content is identical to the source's. This is the gap a future cross-user pool is meant to close, not attempted here by design.
- **No variety or outcome-awareness in repeat claims for the normal (non-redo) claim path.** The ordinary claim query returns eligible rows oldest-generated-first with no shuffling and no preference for previously-incorrect questions. A learner who never uses "+5 Questions" or Redo Missed Questions will see the same initial batch, in the same order, on every subsequent Challenge Quiz session for that Study Pack.
- **"+5 Questions" isn't quota-exempt-aware.** A redo-missed session's zero-LLM-cost guarantee covers only the start of the session — clicking "+5 Questions" falls through to normal LLM generation, same as any other Challenge session. This has always been true of "+5 Questions" generally (it's unmetered for every Challenge session, not new this release); whether to disable it specifically for redo-missed sessions is an open product question deferred to a future release.
- **A redo-missed request can silently resume an unrelated in-progress session.** The single-active-Challenge-session check matches only on session type, not on the specific sub-mode requested. A learner with an in-progress ordinary Challenge or Board Exam session who hits Redo Missed Questions is resumed into that unrelated session instead, with no signal that the redo-missed flow didn't start. Low probability and no data corruption, but confusing if hit; not fixed this release.
