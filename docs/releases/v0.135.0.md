# Release Notes: v0.135.0 — Update Signal

## Release Theme

Learners who adopted an Official Review Set now hear about it when the curator publishes an update — the first notification NoteLib has ever produced.

## Key Features

**🔔 Adopters are told when a Review Set they use is updated**

- Publishing an update to an Official Review Set now notifies every learner who adopted it, deep-linked to their own copy so the update is one tap away.
- The notification says only that the set was updated — it never claims a count, because one signal can stand for several publishes.
- Reading or dismissing it changes nothing about the curriculum. The notification is awareness; the Review Set remains the truth.

**✋ Editing still reaches nobody**

- Curators can keep working on a set without learners seeing half-finished changes. Only pressing **Publish update** produces a signal.
- A set going public for the very first time announces nothing — there is no update to announce, and nobody has adopted it yet.
- A curator who adopted their own set is never told about their own publish.

**🔁 A later update always gets through**

- Notifications are keyed to the published revision, so a genuinely later update always reaches learners — even after they have read or dismissed the previous one.
- While a learner is already holding an unopened update signal, further publishes do not stack up more of them.
- Pressing Publish twice with nothing new in between changes nothing and notifies nobody.

## Polish & Fixes

- Removed the placeholder notification type that had no producer, now that a real one exists.
- Delivery runs after the publish has been saved, so a notification problem can never undo a publish.
- Documented that an update signal you have neither opened nor dismissed stays in your inbox until you act on it.
- Recorded the publication boundary's new consequence in the Review Set documentation: publishing is now a learner-visible event, not only a visibility change.
