# Release Notes: v0.81.0 — Challenge Bank Integrity

## Release Theme

Questions you have already answered should stay out of your next Challenge Quiz, and the questions saved for you should be ones you can actually receive.

## Key Features

**🔑 A depth correction no longer collides with your saved questions**
- Saved Challenge questions are now unique per learner, Study Pack, question **and** curriculum depth
- When a note's authored depth is corrected, questions saved at the previous depth are kept alongside the new ones instead of clashing with them

**♻️ Questions that could never be served are now claimable**
- A small set of saved questions carried no curriculum depth and could never be matched to a session, so their owners could never receive them
- They now take the depth of the note they belong to, falling back to college level only when the note has none
- Nothing is deleted, and a question is only stamped when doing so cannot clash with one already saved at that depth

## Polish & Fixes

- Corrected the documented description of how saved-question writes behave, so it matches what the code actually guarantees
- Recorded why one appealing fix for the remaining gap does not work, so it is not attempted again the same way

## Known Limitations

- **Saving questions is best-effort in intent but only partly guaranteed.** If two Challenge sessions for the same Study Pack run at the same time and generate the same question, that session can still fail. The wider fix was attempted in this release and withdrawn — it stopped questions being saved at all — so the gap is documented rather than papered over, with a dated check on whether it happens in practice.
- The number of previously unclaimable questions this release rescues was not measured beforehand, so a follow-up read confirms it.
- If a Challenge session fails while starting, the questions it had reserved stay reserved and are not returned to the pool. This predates the release and is recorded rather than fixed.
- The new uniqueness rule has no automated test coverage; it can only be exercised against a real PostgreSQL database, and requires PostgreSQL 15 or newer.
