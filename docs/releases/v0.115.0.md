# Release Notes: v0.115.0 — Learner Publication Authority

## Release Theme
When you publish a note you copied from the curated library, the programs it gets shelved under become yours to state — rather than the original author's to have decided for you.

## Key Features

**🏷️ Your published copy carries your classification, not the curator's**
- A note you copy from the library inherits the curator's program tags. Until now, publishing that copy let *their* tags decide which public shelves it appeared on — for a note they never published themselves.
- Publishing a copy now clears those inherited tags and hands the decision to you.
- Curators are unaffected: a curated note keeps its authored programs on publication, exactly as before.

**✍️ The Course / Program field becomes yours to fill in**
- Inherited program tags used to hide that field entirely, so you *couldn't* state your own classification even if you wanted to. This was a capability gap, not a matter of nobody bothering.
- With the inherited tags cleared, the field appears and is yours to answer.
- Your note goes public straight away — publishing is never blocked. It simply sits unshelved until you say where it belongs, and it is never silently filled in on your behalf.

## Polish & Fixes
- Editing a note no longer stamps your profile's program onto it when the request omits that field — the note keeps its own stored value.
- Recorded the Stage 1 architecture reconciliation for the Comprehensive Review Set Overhaul, from three independent audits.
- Corrected two entries in `ADR-001`: the shape a copied note actually takes, and the resolution of the overlapping-representation question.
