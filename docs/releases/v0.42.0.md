# Release Notes: v0.42.0 — AI-assisted Companion authoring + regeneration

## Release Theme

Give curators an LLM-assisted first draft for Learning Companion content, with mandatory human review before publish — extending the "Curation, never generation" rule with a curator-facing clarification while keeping the learner-facing guarantee (no auto-generated plans) fully intact.

## Key Features

**✨ AI-assisted Companion draft generation**
- ADMIN curators can now generate a first draft for any single Companion section (Overview, Study Strategy, Common Mistakes, FAQ) or all four at once, from a new `Generate` action in the existing authoring modal.
- Generation never persists on its own — drafts land in the modal's local form state only, and the curator must still review, edit, and click the existing Save button before anything reaches a learner.
- Uses the existing OpenAI service's PREMIUM model tier; no new LLM infrastructure. FAQ generation is bounded to 3–6 items with schema-level enforcement and a retry-once-on-invalid-output safeguard.
- Generating an already-authored section is the same action as regenerating it — no separate regenerate endpoint was needed. A confirm guard protects a curator's unsaved edits from being silently overwritten by a fresh generate.

**⚠️ Companion staleness signal**
- ADMIN curators now see a "Companion may be outdated" indicator when a Review Set's structure (its Subject Plans or notes) has changed since the Companion was last saved.
- Backed by a lightweight structure snapshot (member count + sorted child/note ids) captured only when Companion is saved, and compared inline on the existing Goal detail read — no new background job or polling.
- Learner-facing display is completely unaffected; the signal only ever surfaces inside the ADMIN-gated authoring modal.

**📚 Companion Resources section**
- A fifth Companion section, deferred from v0.41.0's four-section MVP: a free-form markdown field for curator-authored links and references, rendered through the same markdown renderer as the other sections.
- Deliberately manual-authoring-only — excluded from AI generation (an LLM cannot produce trustworthy URLs) and from the staleness comparison (authored content, not structural membership).

## Polish & Fixes

- Resolved the "Timeline/Checklist live-feature embeds" scope item without new code: v0.41.1's information-hierarchy reorder already positions the Companion display card immediately below the live weekly countdown and readiness cards on both view branches, so a jump-link or duplicate live-data recap inside Companion would have added nothing beyond that existing adjacency.
- Pre-signoff pressure test (three-agent audit, warranted since the release's three feature PRs repeatedly touched the same shared Companion save path) caught and fixed one cross-PR gap: `setCompanion` accepted a null content body without guarding against it, unlike every other request-DTO mutator in `NoteCollectionService` — a null body would still compute and persist a structure snapshot while leaving `companion` itself null. Fixed with a one-line guard matching the file's existing convention.
