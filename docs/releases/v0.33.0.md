# Release Notes: v0.33.0 — Study Plans as a Retention Engine

## Release Theme
Turn Study Plans into a readiness surface: place one ConceptHealth-derived readiness signal where it has reach, ungate that signal to Free, smooth publish/discovery and curation so curated plans reach and organize learners — shipping the retention *lever* (the retention outcome itself depends on curated-plan coverage and is measured separately).

## Key Features

**🎯 Plan readiness — a dedicated, owner-scoped readiness view**
- New owner-scoped `GET /collections/{id}/readiness` and a dedicated `/collections/[id]/readiness` route, reached by a **"Check readiness" CTA** on plan detail (not a tab, never inline on the execution rows). It shows overall readiness % plus per-subject readiness scoped to the plan's notes, cross-links to the full `/progress`, and serves clean zero shapes for empty / no-pack / not-started plans.
- Readiness is **derived, not stored** — it reuses the existing `ProgressReportService` ConceptHealth classification and `masteryPercentage`, so a plan's numbers match `/me/progress` for the same concepts. No new mastery signal, no persisted field, no AI call.
- A reusable `ReadinessSummary` component (inline SVG ring + the existing CSS progress-bar pattern, no chart dependency) is shared across surfaces, and one readiness vocabulary — `ready / mastered / due / not started` — is reconciled across note, plan, and Progress. This records a deliberate, scoped reversal of "plans don't duplicate Progress": readiness belongs on the dedicated sub-route only; execution-detail rows keep their no-mastery rule.

**📊 Per-note readiness signal, now visible to Free**
- Note Detail now shows a compact readiness rollup for ready notes with key concepts (`% ready · X/Y mastered · N due · not started`), computed from the already-fetched concept-health — no extra fetch, no new generation.
- **Free-gate split (access, not billing):** the readiness *signal* — the rollup and which concepts are due — is now visible to Free, aligning Note Detail with the already-Free `/me/progress` and giving the Free cohort its return trigger. The per-concept review-**timing** detail (`Due — Nd ago`, timestamps, the "Needs work" struggling chip) stays PLUS/PRO, with a plan-aware upgrade affordance. No price, quota, pass-duration, or checkout change.

**📚 Study Plan publish, discovery & curation polish**
- **Publish decouple:** course/program and description now persist independently of publishing, fixing the silent metadata loss when Publish failed its notes validation. Publish stays gated (every note public, at least one note) with a clearer blocker — validation was not weakened, only the metadata loss was fixed.
- **Recommended plans on `/collections`** with an honest empty state: the Dashboard "Recommended" pattern now also surfaces on the user's own Study Plans page (course/program-scoped); when the learner's program has no curated plan yet it shows a clear "No curated plans for {program} yet" state instead of rendering nothing.
- **Select all / Deselect all** in the "Add notes" picker (scoped to the search) and the Library selection mode (scoped to the active filters, including notes beyond the first display page) — removes the one-by-one tedium when assembling a plan.
- **Sections (modules):** the plan detail page now groups notes into named sections derived from the existing item `label` (`position` still owns order; unlabeled notes fall into a trailing **Ungrouped** section; plans with no labels keep the flat list). Frontend-only — no new section entity, no nested/umbrella plans, and section headers carry no mastery/readiness.

## Polish & Fixes
- **Readiness vocabulary consistency & fallback hardening:** restored the em-dash in the PLUS/PRO `Due — Nd ago` timing chip, and hardened the note-detail readiness fallback to key off the never-redacted `isDue` flag so a not-due concept resolves to `mastered` (rather than collapsing to `not started`) even when `readinessStatus` is absent on a Free-redacted response.
- **Library selection-create description:** the Library split-button create modal now collects an optional description and passes it through, matching the `/collections` modal — a plan built by multi-selecting notes is no longer title-only.
