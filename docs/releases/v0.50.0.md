# Release Notes: v0.50.0 — Mobile Bottom Tab Bar

## Release Theme

Give mobile users (now ~75% of the base) a persistent bottom navigation bar, plus lay measurement groundwork for the retention experiments already in flight and a quick search-visibility fix.

## Key Features

**📱 Persistent mobile bottom navigation**
- Four icon-and-text tabs — Dashboard, Library, Review Sets (profile-aware collection navigation), and Public Library — pinned to the bottom of the screen below the `md` breakpoint.
- Desktop sidebar and the mobile hamburger drawer are unchanged; the tab bar is purely additive for small screens.
- Automatically hides during exam focus and active assessment/review screens, so it never stacks with another fixed-bottom element.
- Coordinates with the home-screen-install nudge, which now sits above the tab bar's safe-area-aware height instead of overlapping it.

## Polish & Fixes

- Confirmed the live feedback control is header-mounted, not a floating bottom launcher, so it needed no coordination work with the new tab bar.
- Exam Hub pages (`/exam`, `/exam/ale`, `/exam/pnle`, `/exam/let`) were fully built and already emitting search-friendly structured data, but missing from the sitemap — invisible to the sitemap Google actually crawls. Added.
- Under-the-hood measurement groundwork for the retention experiments already running: first-touch UTM/referral capture at signup, an offline-usage beacon, and a view event on the official plan catalog page. Collection only — no dashboard or report reads this data yet, and nothing here is user-visible.

## Known limitations

- The home-screen-install nudge applies its raised offset unconditionally, so on routes without the tab bar (public/marketing pages, active quiz sessions) it floats with a small unnecessary gap. Cosmetic only, no overlap.
- `docs/testing/mobile-ui.md` still describes a "floating Send Feedback launcher" that this release's audit confirmed is actually a header-mounted icon — pre-existing documentation drift, left for a follow-up doc pass.
