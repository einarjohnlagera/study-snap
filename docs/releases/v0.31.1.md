# Release Notes: v0.31.1 — Adoptable Study Plans Discovery & Status

## Release Theme
v0.31.0 shipped one-tap plan adoption; v0.31.1 makes those plans discoverable and gives learners a clear sense of where they stand — an onboarding entry point, a way to browse every matching plan, and execution-status signals on the Study Plans surfaces — while tightening bulk-tool quota awareness. Additive only, no new architecture.

## Key Features

**🎓 Adopt a Plan Straight from Onboarding**
- The onboarding completion step (Step 5) now offers the same one-tap recommended-plan adopt card as the Dashboard, below `Continue Studying` / `Go to Dashboard`.
- It self-hides when no published plan matches the learner's course/program, leaving Step 5 unchanged for those tracks; otherwise it adopts via the existing `listPublicStudyPlans` + `adoptStudyPlan` (no new endpoint).
- Onboarding completion is already persisted on Step 5, so adopting and navigating to the new collection never loses onboarding state.

**🔎 Browse Every Published Plan for Your Track**
- New `/collections/published` surface lists **all** published plans matched to the learner's course/program — fixing the Dashboard's previous top-match-only blind spot when several plans are published per track.
- Reached via a prop-gated `See all N plans` link on the Dashboard card (shown only with 2+ matches; never on the onboarding card). Each plan adopts through the shared `PublicStudyPlanCard` with Start/Continue per adoption state.
- Frontend-only (reuses `GET /collections/public?courseProgram=` + `GET /collections`, no new endpoint); loading, error/retry, no-course-program guidance, and empty states are all handled.

**🏷️ Study Plan Execution Status**
- The Study Plans list (`/collections`) shows a **Not started / In progress / Completed** badge derived from practiced-vs-total notes — execution status, not mastery (no percentages, milestones, or streaks; those stay in Progress). This added a practiced-note count to the list DTO, computed with the same completed-session signal as the detail rollup and batched to avoid N+1.
- Study Plan detail rows now show a learner-facing per-note status — `Needs Study Pack` → `Not started` → `Practiced` (plus transient generating/failed states) — replacing the redundant `Study Pack ready` / `Quiz ready` hint.

**📊 Bulk-Tool Quota Awareness**
- Bulk generate folds the note-generation quota into the Topics cap (`X / min(50, remaining)`), hard-caps add/queue at the remaining note generations (with a backend submit-time reject as the stale-tab safety net), and soft-confirms a Study-Pack shortfall (notes still get content as drafts).
- Bulk import surfaces remaining OCR/image-scan quota (Draft-only; OCR consumed only for images/scanned PDFs). Both reuse a generalized `NearLimitBanner` with a credit-noun prop. No new quota category — values read from `/api/me/plan` only.

## Polish & Fixes
- Library and Public Library search fields gained an inline clear (`×`) button when they contain text, distinct from the filter panel's `Clear all`; search inputs use a 16px mobile font to avoid iOS Safari focus-zoom.
- Public Library search is snappier: stale-while-revalidate keeps prior results and search focus on screen during a refetch (with a small `Searching…` indicator) instead of flashing the whole list to skeletons, debounce dropped 400ms → 250ms, and dropped keystrokes on fast typing are fixed (the input no longer resets when a refetch resolves). URL sync is unchanged, so refresh-persistence, deep-linking, and sharing a pre-filtered view still work.
- Bulk generate's submit button is now a static `Generate` (the `X / cap` topic counter above is the count source), removing a duplicated label that could briefly read `0` on a dev recompile; topic inputs bumped to 16px on mobile.
- Exam Builder now shows an amber `N of M notes excluded — no quiz generated yet` notice listing those notes, instead of silently dropping collection notes that have no generated quiz.
