# Release Notes: v0.165.0 — Bounded Discovery

## Release Theme

Stops a public Note page's discovery rails from recomputing live popularity rankings across every page of a Subject or Program's note list — the mechanism behind 24 production backend restarts in a month — and closes three generation-behavior defects a Computing curriculum pilot found.

## Key Features

**🛡️ Bounded Public Note discovery rails**
- The "More from {Subject}" and "More {Program} notes" rails on a public Note page no longer walk every page of that Subject's or Program's entire note catalog, ranking by live popularity in JavaScript as they go — each now issues exactly one bounded, most-recent-first fetch.
- A note sharing the current note's Subject can no longer appear in both the quiz-preview's "More from {Subject}" rail and the always-visible "More in {Subject}" section at once — the rarely-seen rail defers to the always-visible one.
- Subject-vs-Program duplication between the two rails is intentionally left as-is, per this release's own rule that a bounded fetch beats a cosmetic dedup — and it's only visible after a visitor finishes the embedded Quick Check, which is why leaving it is cheap.
- A `[CHECKPOINT]` is on record to confirm the fix actually reduces restarts once it reaches production — the diagnosis's thread-occupancy mechanism was inferred from indirect evidence, not measured directly, and the fix is not yet live as of this release's signoff. No API form changed, so the frontend and backend may deploy in either order.

**🧮 Computing generation-behavior fixes**
- Shell commands and file paths (`g++ program.cpp -o program`) no longer render as malformed LaTeX math in generated Study Pack summaries.
- A Note's Subject no longer leaks into a generated title or a Bulk-Generated note's own body heading as "{Title} in {Subject}" — titles now name the knowledge itself.
- Study Pack generation now logs the authoring domain, Subject, and whether computation guidance fired, closing a gap that made this behavior impossible to diagnose from the logs alone.

## Polish & Fixes
- `fetchAllPublicNotePages` now always requests a database-indexed sort, which also removes the same expensive ranking-query multiplier from the subject listing page, exam hub pages, and the sitemap's own internal walks (their page-by-page walk is unchanged and out of scope; each page is now cheap instead of expensive).
- A Public Note's course/program link is now read from its own joined Applicable Programs instead of re-deriving it by walking that program's entire note list.
- An independent, cold-context pass re-verified every claim in this release's own implementation notes against the merged code rather than trusting the release notes at face value, and found one real overclaim (corrected): the sitemap doesn't re-sort its walked results the way the other two surfaces do, though this has no visible effect since a sitemap's entry order carries no ranking signal to a crawler.
- Corrected a pre-existing doc drift found along the way: the generated note's section names in `docs/features/notes.md` no longer describe sections the code stopped emitting several releases ago.
