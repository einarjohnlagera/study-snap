# Release Notes: v0.137.0 — Deploy Integrity

## Release Theme
A release merged without deploying, and nobody found out for six hours — this makes that visible, and makes the record of what is deployed trustworthy again.

## Key Features

**🚨 A merge that produces no deploy is now detectable**
- `scripts/check-deploys.sh` compares `main` against what Vercel and Render actually serve, and `/signoff` runs it after every release PR merges
- It tests for a deploy that is *absent*, not one that failed — nothing failed in the incident that prompted it, so the existing failure notifications had nothing to fire on
- It refuses to report success when it cannot check, because "I could not look" reported as "all clear" is the same mistake in a different costume

**📋 The record of what is deployed is trustworthy again**
- Four claims about production state were carried in the present tense long after they stopped being true, and a release was scoped on them; all four are corrected against the queries that disprove them
- A new standing rule: a claim about production state is a snapshot, not a fact — re-read it before repeating it
- A second standing rule: removing, renaming or making-required an API endpoint form breaks in *both* directions, so both sides must ship together and the release has to say so

## Polish & Fixes
- Restored the production frontend deploy, which had silently stayed a release behind the backend
- Corrected the record for two database migrations and one data fix that were all long since applied
- Named the cheapest available detector for a stale tracker row: when a row's own cells contradict each other, that is the defect announcing itself
- Recorded that the deploy check is manual, and what it would take to make it automatic
