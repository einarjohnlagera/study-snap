# Release Notes: v0.130.0 — Notification Inbox

## Release Theme
NoteLib can now tell you something and know you have seen it, with a bell in the header, an inbox behind it, and an admin surface for announcements that is the inbox's first real producer.

## Key Features

**🔔 A notification inbox, with a bell that means something**
- A bell sits in the header on every signed-in page, showing a number only when something actually needs you
- Announcements appear in the inbox but never inflate that number, so a badge you see is always something to act on
- At zero there is no badge at all — not a "0", not an empty circle
- Opening the panel does not mark everything read. Reading is per-row, so a pending item cannot be silently cleared by glancing at the list
- Dismissing hides a row and does nothing else — it never accepts, declines, revokes, or changes anything the notification points at
- A notification outlives the thing it points at by design, so every link degrades to a plain "no longer available" state rather than an error page

**📣 Admin "What's New"**
- Announcements have a Draft → Published → Ended lifecycle, targeted at everyone, a profile type, or a plan
- Once published, the wording is fixed. To correct copy you end the announcement and publish a replacement, and the form says so before you publish rather than after
- What people already received is a copy, so editing the announcement definition can never rewrite what someone already read
- Targeting picks who is likely to care. It is never a permission check, and an untargeted account keeps exactly the access it had
- Links must stay inside NoteLib. An off-site or protocol-relative address is refused when written and again when rendered
- Publishing again after a timeout is safe: nobody receives anything twice, and anyone who joined the audience in between receives it now

## Polish & Fixes
- Fixed a bell that could show a number the inbox could not show: dismissing something without reading it removed it from the list while leaving it counted forever
- Fixed the badge freezing after fifteen minutes idle — the background check could never refresh an expired session token, so the number silently stuck on its last value
- Deleting an account now also deletes its notifications; they were being left behind permanently, because the routine that clears old ones deliberately keeps unread items forever
- Added the missing guard on the number shown to signed-out visitors on a Review Set page, which until now could have been replaced by a hardcoded zero without a single test noticing
- Corrected a claim about adoption counts that had spread to five documents: applying an update to a Goal does add you as an adopter of any newly-added subject plan, which is correct, and the test that said otherwise never exercised the case
- Corrected the admin confirmation for re-publishing, which said it only retried missed deliveries when it also reaches anyone who has joined the audience since
- Recorded, rather than quietly fixed, that publishing to a very large audience holds a database connection for the whole send — with a scale trigger written down so it gets revisited before it can hurt
