# Release Notes: v0.83.0 — Target Audience Removal (Phase 2)

## Release Theme
Notes are now classified on four axes that each do real work, and the Public Library filters on a facet the product can actually act on.

## Key Features

**🗂️ Target Audience retired from authoring**
- The audience selector is gone from the note editor, Bulk Generate, Note Detail and onboarding
- Curators classify a note on the four axes that carry weight — Subject, Domain Context, Authored Depth and Applicable Programs — instead of composing a fifth that reached no prompt and gated no access
- Nothing you have already authored changed: existing values are preserved, and an unrelated edit or a copy never rewrites them

**🔎 Authored Depth replaces the audience filter in the Public Library**
- A new depth filter with a shareable `?level=` URL, alongside subject, tags, course/program and creator
- Depth chips are built from the depths public notes actually carry, so a filter can never be offered that matches nothing
- The Public Library had no depth filter before this release — `learner_level` was shown on cards but never filterable, so this builds the replacement the architecture had promised rather than assuming it already existed

**🔗 Old shared links keep working**
- A `?audience=` URL from a shared or indexed link renders the full unfiltered library instead of erroring
- Legacy request fields and browser drafts written before the update are accepted and ignored

## Polish & Fixes
- Note metadata is now formally four axes, with `ADR-001`, `SPEC.md` and the feature docs updated to match the shipped code
- The GPT context modules were brought in line with the code — they had still been describing the audience field as live and instructing that it be supplied
- Added test coverage for applying a depth filter from the filter sheet, verified by confirming the test fails when the behaviour is broken
- Removed six dead helpers left behind once the audience chips were gone
- Corrected the release notes' own claim about browser-draft tolerance, which held in one direction only
- `notes.target_profile_type` is deliberately retained as historical evidence: it is the input the `v0.82.0` depth backfill derived from, and the September review of that backfill cannot run without it
