# Release Notes: v0.154.0 — Closing the Loop

## Release Theme

Closes out three independently-verified, gate-true Backlog Index items — each anchored to current code
before being scoped, rather than trusted from its row's prose.

## Key Features

**🔓 `course_programs.is_active` write path**
- The catalog's `is_active` column has existed since `v0.145.0` but nothing in the codebase ever wrote
  it — every "inactive program" claim in prior release notes was aspirational. Admin's existing *Edit
  Program Families* modal on `/admin/course-programs` now carries an Active toggle, writing through
  `PATCH /course-program-catalog/{id}` transactionally alongside (or independently of) family
  membership changes.
- This is the prerequisite for eventually retiring the two legacy fused catalog rows (`Nursing ·
  Medicine`, `Nursing · Pharmacy`) — that retirement is separate follow-up scope, not done here.

**🩹 Automatic recovery for null-clock `GENERATING` notes**
- Every other stale-`GENERATING` row already recovers through the scheduled sweep; a note missing its
  `generation_enqueued_at` timestamp was explicitly skipped and only warned about. It now recovers
  automatically too, using the same `updatedAt`-fallback bound the self-service recovery endpoint
  already applied on request. A live production check at kickoff found zero notes currently in this
  state — this closes a latent structural gap, not an active incident.

**📝 Topic-note generation now carries Subject**
- "Create a Note" (topic-first generation) previously sent Course/Program and Domain Context into the
  LLM prompt but silently dropped the draft's Subject field. It's now included, narrowing generation
  within the resolved Domain Context per `ADR-001` rather than competing with it. A blank Subject
  changes nothing.

## Polish & Fixes

- All three items independently had a real defect introduced by the implementing session and caught
  before commit: item 1's lost-update risk (re-sending a stale family-membership snapshot on an
  Active-only toggle), item 2's unbounded recovery (no age check, a live regression risk for a future
  non-atomic writer), and item 3's stale-closure bug (a `useCallback` dependency array missing
  `draft.subject`, caught by lint). Each was fixed and covered by a regression test proven to fail
  without the fix.
- Because that pattern repeated across every item, signoff escalated past the single `advisor()`
  summary originally scoped and ran one falsification-framed cold agent against all three fixes'
  specific claims instead. Nothing was disproven.
- `docs/features/notes.md` updated — it documented exactly what the topic-generation request carries
  and had gone stale the moment item 3 shipped without a matching doc update.
- Two Backlog Index rows closed with `file:line` evidence (the `is_active` write-path row and the
  topic-note subject-contract row, including its now-stale title); one corrected in place (the
  `GENERATING`-strand row's "null clock rows strand indefinitely" claim no longer holds).
- Unrelated pre-existing uncommitted work (a Feature Planner session charter, a Product UX context doc,
  an owner-run SQL validation plan, a regenerated CPALE curriculum workbook) rode along as docs-only
  housekeeping on the open release branch.

## Known Limitations

- **Retiring the two legacy fused catalog rows** (`Nursing · Medicine`, `Nursing · Pharmacy`) is not
  done — this release only ships the write path that makes it possible. Tracked in `ROADMAP.md`'s
  Backlog Index as ready to scope, no longer blocked.
