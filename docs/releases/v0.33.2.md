# Release Notes: v0.33.2 — Plan Detail Redesign (view/edit split)

## Release Theme
Make the leaf Study Plan detail usable on mobile by replacing the permanent wall of edit chrome with a clean read view by default, and add section-level inline rename so curators can reorganize plans without tedious per-note label changes.

## Key Features

**Clean Read View by Default**
- `/collections/[id]` now opens without drag handles, Section comboboxes, Move buttons, or Remove buttons visible
- A single `Organize` toggle in the Notes card header reveals all structural controls; label flips to `Done organizing` while active
- Flat plans (no label-derived sections) get the same view/organize split without any collapse behavior

**Collapsible Section Cards**
- Each label-derived section is now a visually bounded card with a collapse toggle in the header
- Sections start collapsed on mobile (< 1024 px) and expanded on desktop (≥ 1024 px)
- Section header shows name, note count, and a rotated chevron affordance with a hover background so the toggle reads as clickable
- Section name color changed from blue (which read as a navigation link) to foreground weight

**Title Peek on Collapsed Cards**
- Collapsed cards show the first 1–3 note titles joined by `·`, with a `+N more` suffix when there are more
- Pure content preview — no progress or mastery semantics

**Inline Section Rename (Organize Mode)**
- In organize mode the section name becomes an editable input: click to edit, Enter or blur commits, Escape cancels
- Committing to a name that already exists triggers a merge confirmation modal ("Merge into 'X'?") — confirming sends one batch API call to relabel all notes in the section
- `"Ungrouped"` is reserved and cannot be used as a target name

## Polish & Fixes

- Section card header: replaced `ChevronDown` / `ChevronRight` two-icon toggle with a single `ChevronDown` that rotates, and bumped chevron contrast from `/55` to `/70`
- Section card expanded state: added a `border-t` divider between the header row and the note list for a cleaner separation
- `SectionCardHeader` component extracted to eliminate duplicate section markup across the organize and view mode render branches
- `StudyPackService` now saves `note.subject` as the Study Pack subject when the note already has one, preventing LLM-generated subject drift on future generations
- `ProgressReportService.resolveSubject()` now reads from the note's own `subject` field, falling back to `studyPack.subject` — heals historical grouping drift on existing plans without per-plan data patches
- Normalized inconsistent `subject` field variants on the 29-note LET Professional Education curated plan so the readiness page groups cleanly (data ops, no code change)
