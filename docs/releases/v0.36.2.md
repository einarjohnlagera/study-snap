# Release Notes: v0.36.2 — OCR Disable Hotfix

## Release Theme

Stop the backend's repeated out-of-memory crashes on Render by disabling the memory-heavy Google Vision OCR path, and cut a real cost while pre-revenue in the process.

## Key Features

**🛑 OCR Kill-Switch**
- Added `studysnap.ocr.enabled` (env `OCR_ENABLED`, default `true`), gating every call site that invokes Google Vision OCR: image note upload, the scanned-PDF fallback, and the photo-to-Study-Pack quick capture.
- When disabled, each path throws a new typed `OcrDisabledException` (`OCR_DISABLED`, HTTP 503) before any OCR call, quota check, or rate-limit check runs — no wasted work, no wasted quota.
- Native-text PDF extraction and `.txt`/`.docx` upload are completely unaffected — they never touch OCR.

## Polish & Fixes

- Root-caused repeated Render OOM kills (crashing every 20-90 minutes) to `GoogleVisionOcrService` constructing a fresh gRPC `ImageAnnotatorClient` per call — up to once per page for a scanned PDF, up to 30 pages per import — whose native/off-heap memory churns faster than it's reclaimed and has no headroom in the container's memory budget.
- The frontend needs no code change to show a reasonable failure message: its existing generic API-error handling already surfaces the backend's error message verbatim, and the new exception's message is written for end users to read directly.
- A polished, dedicated "OCR unavailable" state plus a feedback-capture mechanism (asking users if they want OCR back) is intentionally deferred to a fast-follow — this release is the fast kill-switch only.
