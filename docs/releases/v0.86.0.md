# Release Notes: v0.86.0 — Generation Recovery

## Release Theme
Pre-warmed exam content and in-flight sessions that die on deploy now recover themselves, instead of sitting forever in a status nothing can leave.

## Key Features

**♻️ Age-based generation recovery**
- One scheduled sweep covers the three surfaces that could strand work permanently: exam question pools, Long Exam sessions, and notes
- A stale row resolves to `FAILED` — a status the product already knows how to recover from — and stops there
- Exam pools then rebuild through the existing next-use refresh; Long Exam sessions let the next start create a fresh one; notes feed the existing **Retry Generation** button
- Recovery never re-dispatches work, never auto-regenerates a Study Pack, and never touches quota

**⏱️ Generation clocks that survive reuse**
- Exam pool rows are reused across generations, so `created_at` cannot say when the current attempt began — every `PENDING` and `GENERATING` write now stamps its own clock
- Notes stamp an enqueue time in the same transaction that marks them `GENERATING`, refreshed on every retry
- `V118` seeds both clocks from deploy time rather than from a reused row's `created_at`, so no live attempt is swept on the first tick and genuinely stuck rows become eligible exactly one bound later

**🎛️ Bounds you can tune without a deploy**
- Every threshold, the cron, the batch size and a kill switch are configuration-owned
- Defaults are deliberately conservative placeholders — 60 minutes for pool work, 30 for Long Exam sessions, 120 for notes — sitting far above the measured worker envelope
- Tightening them after production observation is a config change, not a code change

**📐 Generated notes bounded by the limit the model is actually given**
- Note bullets are now measured in characters — the bound the prompt states and the schema enforces — instead of a word ceiling published nowhere
- A formula plus its variable definitions is word-dense and character-light, so quantitative topics were failing a limit the model was never told about
- Verified live: five of five previously-failing Engineering Economics topics now generate

## Polish & Fixes
- Fixed a null dereference in the generation interlock that turned every clean discard into a false `outcome=failed` with a stack trace, and re-wrote the note's status in a way that floated it to the top of the library
- The interlock is now documented as the deliberate safety mechanism it is, so a late-finishing worker discards its result instead of resurrecting a note the learner was already told had failed
- Each recovered row commits in its own transaction, so one unreadable row can no longer discard everything the sweep had already recovered
- The 240-character bound is now stated in every prompt section it governs, not just one
- Strengthened four tests that passed for the wrong reason, each verified by mutation
- Corrected the release's own claim that one unpublished bound remained — three others survive in the same method and are recorded as a known limitation
- Refreshed `AGENTS.md`, which still described this release by the scope it was opened with rather than the one it shipped
