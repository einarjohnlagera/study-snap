# Release Notes: v0.114.0 — Connection Evidence

## Release Theme
Settle, by direct reading rather than by argument, how long a database connection is actually held — and
finally run the outage queries that decide whether the next big piece of work is aimed at the right thing.

## Key Features

**🔍 The running instance now reports its own connection lifetime**
- One line at startup naming both settings that decide how long a JDBC connection is held: the effective
  `hibernate.connection.handling_mode`, read back from the `EntityManagerFactory`, and the effective
  open-in-view state, read from whether the interceptor is actually registered
- Every clause is derived from live state — never a configured value, never a framework default filled in
- Closes a real gap rather than a ceremonial one: the existing measurement runs against the H2 test
  profile, so a JPA key in the production overlay could have moved production's behaviour with the whole
  test suite still green

**🧪 The falsification queries finally ran, and they changed the answer**
- All seven read-only production queries executed against the 2026-09-04 outage window
- Generation activity is **absent** on a deliberately widened window — no quiz sessions, no enqueued
  notes, no pools, no drafts — so the explanation that the connection-pool work was built to address has
  no supporting evidence at all
- A previously refuted explanation is back: one public note was requested sixteen times in seventy-eight
  seconds, against a normal rate of one or two per hour, starting fifteen seconds before the failure
- The verdict is recorded as unsettled, because that is what the evidence supports

**🛡️ A guard that proves the reading is real**
- The startup line is pinned by tests using values that are deliberately not real Hibernate settings, so a
  version that printed a constant instead of reading the live one cannot pass
- Four deliberate breakages, four failing tests, each one named
- The configuration guard now also covers the JPA namespace, not just the datasource one

## Polish & Fixes
- Corrected a configuration comment whose wording caused a later session to conclude that work had never
  been done when in fact it had — the evidence simply lived somewhere the search did not look
- Recorded that two of this release's four planned items were already delivered in a previous release,
  with the reason the original check missed them
- Corrected an earlier note claiming none of the outage queries could detect anonymous read traffic; one
  of them can, which is what made it the query that mattered
- Dated the outstanding connection-leak investigation from the actual production rollout timestamp rather
  than an approximate one, and recorded an interim reading along with why it settles nothing
- Added a short-dated checkpoint to confirm the new startup line is genuinely read in production — the
  precise failure this release exists to correct
