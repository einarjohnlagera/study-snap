# Release Notes: v0.151.0 — No Backdoor Left, Round Two

## Release Theme

Closes the same shared-quiz-link gate gap `v0.143.0`/`v0.144.0` already closed for the exam question
pool — this time for the share links themselves, on the single-Note path, the bulk-regeneration path,
and the confirmation dialog a curator reads before running a bulk batch.

## Polish & Fixes

- A `STUDY_PACK`-only regeneration (the default scope on `POST /notes/{id}/regenerate`) now deactivates
  a note's live quiz share links, matching what the combined `NOTE_AND_STUDY_PACK` scope already did.
  `saveStudyPack` replaces the quiz content on either scope, so a recipient could otherwise keep being
  graded against a quiz built from content the note no longer has — the exact failure `v0.110.2` shipped
  to close, reopened one scope over.
- The bulk-regeneration path carried the identical scope gate in its consequence-counting service,
  which backs both the preflight modal's disclosed count and the per-item batch receipt. Fixed so the
  disclosure a curator sees before confirming a batch, and the receipt recorded after it runs, both
  match what the batch actually does.
- The bulk-regeneration confirmation dialog's shared-quiz warning was itself gated to the combined scope
  only, so even a fixed backend would have shown a curator zero warning on the default scope. That gate
  is dropped too.
- Corrected two feature docs (`docs/features/bulk-regeneration.md`, `docs/features/study-pack-generation.md`)
  that stated the old, now-incorrect scope restriction explicitly.

## Known Limitations

- A signoff pressure test found one narrow, pre-existing gap in the bulk-regeneration receipt, not
  introduced by this release: a batch's per-item receipt records whether a share link was deactivated
  from a value captured before that item runs, so a link created on a note's quiz while its item is
  still processing is correctly deactivated but the receipt can still show it wasn't. Documented in
  `docs/features/bulk-regeneration.md`, not fixed here.
