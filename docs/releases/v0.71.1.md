# Release Notes: v0.71.1 — Applicable Programs Follow-ups

## Release Theme

The follow-through on Release B: a learner can finally see and understand which programs their copied note belongs to, curation authority stops crossing between accounts, and the surfaces that only half-knew about the new applicability model catch up.

## Key Features

**📋 Your copied notes explain themselves**
- A note copied from curated material now shows the programs it applies to, read-only, with a plain line saying where they came from: *"Set by the note this was copied from. Your own course or program is on your profile."*
- The Course / Program field is no longer required on those notes. It never did anything there — the copied programs decide where the note is filed — so asking for it was asking you to fill in a box nothing read.
- The full program list finally lives where the note cards have always promised it does. Previously both the card and the note said "N programs" and the names appeared nowhere a learner could reach.
- Applying AI metadata suggestions on a copied note no longer dead-ends for accounts without a program on their profile.

**🔐 Curation stays with the note's owner**
- Setting a note's Applicable Programs now requires owning that note. Admin access grants catalog curation, not authority over other people's notes.
- This closes an ordinary route back into a state a migration had to clean up: programs added to someone's note that they could not see, change, or remove.
- Reading is deliberately unchanged, which is what lets the read-only display above work at all.
- The Admin curator page now lists only the notes it can actually edit, instead of 4,480 rows of other people's private material with an edit button that would fail.

**🧭 Program-aware surfaces that were previously blind**
- Post-session goal nudges, Continue Studying, and public profile cards now read curated applicability rather than only the older text field — so notes authored for an Official Review Set stop looking unclassified.
- Interview Practice offers sources that share a program with your note again, and never presents an empty picker when nothing matches.
- `GET /notes` returns the applicable programs it has always advertised, instead of an empty list.

## Polish & Fixes
- A learner opening a note on an older browser tab no longer risks having their course/program silently replaced by their profile value.
- Failing to save a draft on the way to checkout now tells you what to fix *and* confirms the draft was preserved; previously it could only say one, and in practice said neither.
- The Course / Program filter explainer stopped claiming counts could exceed the note total — it sat above a dropdown that shows no counts. It now explains what the filter actually does.
- Shared Course / Program pickers honour the placeholder their caller passes, so states like "Loading course programs…" appear instead of being silently replaced.
- Note Detail and the note cards now use one phrasing, "Applies to N programs", rather than disagreeing with each other.
- A curator-only catalog lookup can no longer block a learner's own metadata editing when it fails.
- The onboarding guard that keeps curator rules from firing mid-onboarding now covers every authoring path, with no remaining exception.
- Bulk generation, note creation, and note editing all agree on who counts as a curator.
- No database migration and no schema change shipped in this release.
