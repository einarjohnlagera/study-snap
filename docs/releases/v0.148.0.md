# Release Notes: v0.148.0 — Say What You Mean

## Release Theme

Two backend correctness fixes for signals that quietly meant less than their name implied: a keyword
scan that flagged content as "quantitative" by accident, and a reminder email that quietly always
arrived on the same day.

## Key Features

**🎯 Quantitative Content Detection Now Matches Real Words, Not Substrings**
- `isQuantitativeContext` used to flag a note as needing computation guidance if any of 50 keywords
  appeared *anywhere* in its text — including inside unrelated words: `ratio` inside "corporation,"
  `solve` inside "resolve," `current` inside "currently," `interest` inside "interested." Seven of the
  most substring-prone keywords (`ratio`, `solve`, `current`, `interest`, `integral`, `balance`,
  `units`) now require a real, standalone word match — including their plain plural and verb forms
  ("ratios," "solving"), so genuine quantitative content isn't lost along with the false positives.
- Fixing the substring bug would have accidentally cost some Nursing and Accountancy content its
  computation guidance too, since those notes reached "quantitative" only through the same accidental
  match. `nursing` and `accountancy` are now their own keywords, closing that gap — and, as a side
  effect, permanently fixing two of the three programs an older release had already found under-covered
  by name alone.
- Affects future regenerations only; nothing already generated changes.

**📅 Weekly Reminder Emails No Longer Cluster on One Day**
- Learners who never picked specific review days were being checked for a due-concepts reminder every
  single day, which meant they all quietly synchronized onto whichever weekday happened to fire first —
  three weekdays carried roughly ten times the volume of the other four. Each such learner is now
  assigned one consistent day of the week, spreading the load the same way a learner who picks their own
  days already is.
- No visible change for anyone who has already chosen review days in Settings.

## Polish & Fixes
- Both fixes are pure logic changes computed at read/generation time — no migration, no new endpoint,
  no persisted state change for either.
- A now-unused cooldown setting (`dueConceptsDigestCooldownDays`) was removed rather than left behind.
