# Release Notes: v0.60.1 — Challenge Quiz Fix Pass

## Release Theme

Fix five Challenge Quiz defects surfaced while exercising v0.60.0's Official template sharing in production — an executor-saturation bug blocking the backfill, a never-implemented shuffle, a silently-inert manual difficulty selector, silent auto-submission of abandoned sessions, and a non-functional "Redo Missed Questions" button.

## Key Features

**⚙️ Executor Saturation Fix**
- Official Challenge Quiz template seed dispatch (both the eager per-note hook and the admin backfill) now runs on the shared `llmParallelTaskExecutor` bulk-fan-out pool instead of the live-generation `studyPackGenerationTaskExecutor`, so a large backfill can no longer delay or reject real user-facing Study Pack generation.
- A `RejectedExecutionException` on dispatch is now caught and logged instead of propagating; the admin backfill response gained a `rejected` count, reported distinctly from `queued`/`skipped` in the `/admin` seed-templates message. Unblocks re-running the v0.60.0 production backfill that had been failing.

**🔀 Whole-Array Shuffle**
- Challenge Quiz's fully assembled question pool (banked + Official template + freshly generated) is now shuffled once at initial session start, instead of always presenting fixed generation-order batches forever.
- "+5 Questions" growth shuffles only the newly-appended batch, never the whole array, so already-recorded answers never get silently remapped to the wrong question.
- MATCHING-block-aware: a 2–4 question MATCHING block always moves and stays together as one contiguous unit, since the frontend groups them by array adjacency. Board Exam Mode's ordering is unchanged.

**🗑️ Difficulty Selection Removed**
- Removed Challenge Quiz's inert Easy/Medium/Hard selector — silently non-functional since v0.58.0's per-user question bank shipped — along with its feature gate and all pricing/paywall/marketing claims, rather than re-engineering the bank/template claim path to respect it.
- Challenge difficulty now comes only from the existing last-Quick-Review-score fallback. Board Exam Mode is unaffected — it already used a fixed difficulty and never touched this gate.

**⏱️ Abandoned Session Handling**
- Expired in-progress Challenge Quiz and Board Exam sessions are now auto-forfeited server-side — including releasing any Challenge Quiz bank claims — instead of being silently resumed and immediately auto-submitted as a timeout.
- A live (non-expired) session found through the mode-selection entry now offers a **Resume / Start Fresh** choice, ported from Long Exam's existing pattern, instead of resuming without asking.

**↩️ Redo Missed Questions Fixed**
- Fixed a same-route navigation bug where the button's query-only link never remounted the page, so clicking it just re-displayed the prior session's stale result instead of starting a new one.
- Added the missing error state for fewer than three eligible missed questions — now shows the backend's ready message on a clean, retryable prestart instead of nothing happening.

## Polish & Fixes

- Same-day pre-signoff pressure test found and fixed three refinements: `generateMoreQuestions` ("+5 Questions") now checks session expiry itself and rejects/forfeits instead of extending the time limit on an already-expired session; the Redo Missed Questions retrigger guard now resets on every start outcome (not just one error branch), so a second request in the same page session actually fires; the Resume/Start Fresh prompt is now forced onto mode-selection for TEACHER profiles too, which otherwise skipped straight to Setup with the resume candidate silently unshown.
- Fixed stale "Difficulty selection" claims left over from the removal across `SPEC.md`, `EXAM_MODES.md`, `PLANS.md`, `pricing.md`, and `subscriptions-and-usage-limits.md`.
- Fixed a stale `AGENTS.md` version line that contradicted its own anti-drift section.

## Known Limitations

- **`generateMoreQuestions`'s failure-path claim release can itself be rolled back.** A generation failure mid-batch re-throws inside the class-level `@Transactional`, rolling back the release call meant to free the claimed bank rows, which can leave them stuck until they naturally expire. Needs the release to run in its own transaction (`REQUIRES_NEW`) or as a post-rollback step; deferred as narrow and out of scope for a patch release.
- **An expiry-triggered session start can race a concurrent completion.** `resolveExistingChallengeSession`'s lookup isn't pessimistically locked like `completeSession`'s read is — a completion and an expiry-driven forfeit landing close together can have the forfeit's write commit after the completion's, overwriting `COMPLETED` back to `FORFEITED`. Requires near-simultaneous requests (two tabs, or a reload right at the expiry boundary) to hit; deferred as narrow.
- **The Resume/Start Fresh prompt only fires from the note detail page's Challenge Quiz card**, scoped to the `?entry=mode-selection` query param. The collection/Review Set premium-exam launch navigates to the same page without that param, so it silently auto-resumes a live session with no choice offered — same underlying gap as the TEACHER fix above, via a different entry point. The smallest correct fix is likely appending `entry=mode-selection` to that one navigation call, but it wasn't verified end-to-end in time for this release.
