# Release Notes: v0.67.0 — Explore Convergence

## Release Theme

Give signed-in learners one nav-level destination — Explore — to discover both curated Official Review Sets and the public notes library, and let Exam Hub pages point straight into an official-set adoption path when one exists for that hub's course/program.

## Key Features

**🧭 Explore, a New Nav Destination**
- Desktop and mobile navigation replace the standalone "Public Library" item with "Explore," reordering to Dashboard / profile-aware Collections label / Library / Explore / Progress.
- `/explore` composites the existing Official Review Set catalog and public notes library behind a segmented "Review Sets" / "Notes" control, plus a pointer card into the Exam Hub index.
- `/collections/published` and `/public/library` remain live, unchanged, independently addressable routes — Explore is a navigation-level composite, not a new canonical content URL.

**🎓 Exam Hub Official-Set Adoption**
- Each Exam Hub page now resolves its course/program(s) against published Official Review Sets, exact match only, and shows a preview + adopt path when one exists.
- Lookups fail open — an anonymous, SEO-relevant hub page never blanks on a lookup failure — and dedupe correctly when one collection matches more than one of a hub's course/programs.
- Signed-out adoption preserves exam intent through the existing cookie and routes through `/auth`.

**🗂️ "Explore Owns Discovery" — Collections & Dashboard Converge**
- A same-day mid-release scope addition made `/explore` the single authenticated owner of content discovery: `/collections` is now a pure owned workspace with its embedded discovery catalog removed, and Dashboard's two discovery surfaces became bounded pointer cards into Explore instead of full catalogs.
- `AGENTS.md`'s Page Responsibility Rule now locks this as doctrine.

## Polish & Fixes

- An independent fresh-context Opus audit of the Codex-delivered diff, before merge, found and fixed: a missing `EXPLORE_VIEWED` page-view event that would have made this release's own checkpoint (below) unmeasurable; two doc-accuracy corrections (`exam-hub.md`'s `redirect`-param claim, `navigation.md`'s back-link label); three minor cleanups (an unused icon, an import-location fix, a stale comment).
- A full pre-signoff pressure test — four parallel review agents covering nav/Explore, backend/analytics/shared utils, Collections/Dashboard, and Exam Hub/Public Library/PlanPicker, warranted by this release's release-wide surface area and 3 PRs touching shared files — found and fixed one further gap before signing off: adopt/preview analytics events weren't carrying the same dashboard/collections pointer-origin metadata that page-view events already had, which would have silently broken the checkpoint's own pointer-vs-direct segmentation. Fixed via a dedicated PR, keyed to avoid colliding with an existing same-named metadata field. Nine further findings from that same pressure test are logged below rather than dropped.

## Known Limitations

- Dashboard's valid-primary continue mode still duplicates `DashboardPrimaryCollectionHero` — deferred per explicit owner decision.
- Dashboard's two no-course/program guidance treatments (Explore pointer vs. the fuller community-notes card and modal) remain inconsistent — the community section was structurally out of scope.
- `/explore` fetches both tabs' data on every load, not just the active one — a real but out-of-scope performance gap.
- A pre-existing sessionStorage-based back-link bug widens its blast radius: a stale label can now read "Explore" for a page never visited.
- The published-plans catalog's `?ref=`-based contextual back-link is now unreachable from real navigation — both pointer-adding changes this release removed its only producers, and its dedicated tests stay green on a path that can no longer fire from a real visit.
- Explore's tab label hardcodes "Review Sets" instead of routing through the existing profile-aware label helper, colliding with `BOARD_EXAM`'s identically-named Collections nav label.
- Exam Hub's official-set card doesn't check whether the visitor already adopted that set, so an already-adopted visitor sees "Start" instead of "Continue" (the backend adopt path is idempotent — no data corruption, just a mislabeled call-to-action).
- The zero-note Dashboard shows two near-duplicate Explore pointer CTAs stacked directly on top of each other.
- A fast double-click on an inactive Explore tab can fire duplicate tab-switch analytics — a narrow timing window, unlikely from real human input.
- Preview and adopt-click analytics fire asymmetrically for already-adopted plans, which will skew any preview-to-adopt conversion rate computed from them.
- The Exam Hub official-set fetch asserts its response shape rather than validating it at runtime — a crash risk on a malformed response, unlike its sibling notes fetch.
- Explore's embedded Notes tab drops the "Share this list" affordance the standalone Public Library page offers.
- A pre-existing, not-introduced-here bug in Dashboard's community-notes Explore link silently drops the course/program filter on re-submit — logged for visibility since this release's own link retargeting touches the same code.
