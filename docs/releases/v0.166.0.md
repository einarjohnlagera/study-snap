# Release Notes: v0.166.0 — Measured Twice

## Release Theme

A routine checkpoint sweep found and fixed a real, previously-unexplained HikariCP long-connection-hold pattern — two unbounded synchronous database operations, confirmed in production, neither the LLM-call mechanism an earlier release had deferred fixing.

## Key Features

**⚡ Bounded Public Profile reads**
- `PublicProfileService` no longer loads every public note (with full content) and every full Study Pack for an account just to compute aggregate stats and let the frontend pick its top 8 — confirmed in production, the largest creator profile was doing this for 1,997 notes on every load.
- The author card shown on every public note page — the dominant trigger, since it refetches on every page view with no caching — now calls a lightweight 3-field summary endpoint instead of the full profile.
- Total copies, shares, and views are now computed with SQL aggregates across every public note, not by summing whatever got hydrated — verified against 210 real seeded notes with an explicit guard against a totals-from-candidates regression.
- The existing "Learning Focus" sentence keeps describing the creator's full catalog, not just their most-engaged notes, via a new grouped-label endpoint that reaches every public note regardless of what gets hydrated for display.

**🔁 Resumable Goal adoption**
- Adopting a Goal with many Subject Plans no longer holds one database connection for the entire copy — confirmed in production, the largest existing Goal has 571 notes, and the old synchronous loop could hold a connection for 60–140+ seconds.
- The request now creates the personal Goal and returns immediately; a dedicated background worker copies each Subject Plan under its own transaction, with progress visible on the dashboard, the collection page, the public study plan card, and the onboarding discovery flow.
- If a deploy or crash interrupts a Goal mid-adoption, a scheduled sweep resumes it automatically — nothing is left half-created, and nothing gets copied twice.
- Standalone Subject Plan adoption and additive Review Set updates, which share the same copy mechanism, are unchanged.

## Polish & Fixes
- Recorded `v0.165.0`'s confirmed production deploy timestamp into its own outage-fix checkpoint, giving it a real due date instead of "not yet measurable."
- Found and corrected a real gap in `v0.165.0`'s title-leak fix: 1 of 3 regenerated Study Packs still leaked the Subject into its title. Measured the obvious fix (a deterministic strip) against 3,390 existing titles in production and found no mechanical rule separates a genuine leak from legitimate disciplinary framing — recommended against building it rather than shipping a fix that would mangle thousands of correct titles.
- Corrected an earlier overstated claim about a five-program mixup on the Computing curriculum pilot: the Program Family "Add all" shortcut was called the confirmed root cause; it's plausible but not confirmed, since the family's own membership doesn't fully reproduce the observed set.
- Closed out 9 overdue checkpoints found during this release's own kickoff sweep, two of which reversed a prior finding: an H5 prompt-quality fix's coverage ratio fell after deploying rather than rising, and a Review Set additive-update feature saw 0.3% uptake against a healthy 44% offer rate — both recorded plainly rather than explained away.
- The HikariCP traces that triggered this release's two fixes turned out to be long holds, not permanent leaks, once checked properly — an earlier same-day pass had overclaimed otherwise; corrected before it reached anyone outside this release.
