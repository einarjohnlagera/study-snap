# Release Notes: v0.37.3 — Study Plan Read-Path Memory Optimization

## Release Theme

Cut memory allocation on the app's busiest Study Plan read endpoints, part of the ongoing production memory-restart investigation.

## Key Features

**🧠 Lighter Study Plan Reads**
- Readiness, note concept counts, Goal detail, the full Progress Report, and the dashboard goal nudge all used to load the entire Study Pack record — including its two largest fields, the full quiz and the original source text — just to read a short list of key concepts. They now load a lean projection carrying only the six fields these views actually need, cutting the heap allocated on every one of these requests.
- Fixed a matching N+1: concept-health lookups for a plan's study packs were fetched one-by-one in a loop; they're now fetched in a single batched query.
- `Goal` detail's item count no longer loads every item row just to count them — it now uses a direct count query.

## Polish & Fixes

- Root-caused and fixed a subtle Spring Data pitfall surfaced during audit: the first version of the new projection query shared an interface with the underlying database entity, which silently breaks Spring's ability to recognize it as a projection and would have 500'd every affected page on first production traffic. Caught before merge with a new database-backed test, since the existing test suite mocked the database and couldn't have caught it.
- No visible behavior change — every response looks and counts exactly as before, just built more cheaply.
