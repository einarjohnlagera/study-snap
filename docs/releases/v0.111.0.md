# Release Notes: v0.111.0 — Multidisciplinary Domain Context

## Release Theme
A curator can now honestly classify a note that belongs to two programs, instead of being unable to generate it at all.

## Key Features

**🏛️ Three new Domain Context values, taking the authoring taxonomy from eight to eleven**
- `Architectural Design`, `History and Theory of Architecture` and `Planning and Site Development` join the closed vocabulary that calibrates AI generation.
- All three ship **non-quantitative**, so they fall through to the existing keyword scan rather than switching computation guidance on. That is a decision, not a default — the flag is permanent per note, because Study Packs never auto-regenerate.
- Names are borrowed from real curriculum vocabulary rather than invented, and none of them duplicates a course-program name.

**🔓 Notes that belong to two programs can be generated again**
- A note carrying both `Architecture` and `Architectural Engineering` with no Domain Context was rejected outright, because the program-name fallback only applies when exactly one program is joined.
- Eight notes in the ALE Review Set were blocked this way. They generate now.
- A further 124 notes that had no honest value to pick finally have one.

**📖 Curator guidance that says where material does *not* belong**
- Each new description names what belongs to it **and** routes the adjacent material away — climate and building-services topics to Engineering Sciences, general-education material away from architectural history.
- This is the fix for the defect that produced 215 unclassified rows in the first place: a description that enumerated a narrower set than the value it named, so nobody ever picked it.

**📐 The strategist rules, the architecture record and the taxonomy ship together**
- The Review Set shaping rules, `ADR-001`, and the curator-facing descriptions were all updated in the same release as the enum.
- Splitting them is what let the vocabulary and its guidance drift apart before.

## Polish & Fixes
- `ADR-001`'s taxonomy failure condition is amended: its ratio was being measured against a stale denominator of 21 programs when the live catalog holds 41, so the condition was never close to tripping.
- The ratio is demoted to a watch figure, because one that grows whenever a program is added is easy to satisfy for the wrong reason. The naming rule and a composition matrix computed against programs that actually exist become the real guard.
- The owner decision behind the three new values is recorded in the ADR's revision log, with both limits on the evidence stated rather than smoothed over.
- Corrected the shaping context's course-program list, which still showed 21 programs a month after the catalog had grown to 41 — the stale list is why an earlier curation pass recommended programs that do not exist.
- Corrected the value counts and enumerations across the notes, challenge-quiz and study-pack-generation feature docs and both GPT context files, several of which still described an eight-value taxonomy.
- Re-stamped a GPT context module whose "last updated" marker had been more than twenty releases behind.
- Recorded that `Architecture` remains deliberately absent from the taxonomy: it was reconsidered during this release and rejected again, because it duplicates a program name and would collapse three genuinely different kinds of writing into one instruction.

## Known limitations
- A note whose Subject exactly matches one of the new value names now shows the existing "your subject may be too broad" advisory — about 51 notes in the ALE set. It is advisory only and never blocks saving, and the same is already true of Nursing and Accountancy.
- Two of the three new values currently apply to a single course program, because the other programs they are meant to serve are not in the catalog yet. They were shipped knowingly on that basis.
- Most of the newly classifiable notes are unblocked rather than reclassified: applying the new values to existing notes is curator work, not a migration.
