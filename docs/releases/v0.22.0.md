# Release Notes: v0.22.0 — Course & Subject Discovery

## Release Theme
"Course & Subject Discovery" — makes Course/Program and Subject first-class discovery signals across the public library, private library, and public profiles, so users can navigate by what they're actually studying rather than by who they are.

## Key Features

**🔍 Course-First Public Library**
- Removed the profile-type audience pre-filter — all users now land on the full unfiltered public library
- Course/Program helper CTA prompts users to browse by course or program when no filter is active
- "More [CourseProgram] notes" section on public note detail pages surfaces related notes from the same track
- Meaningful empty state when a Course/Program filter returns no results, with a "Share a note" CTA

**📊 Private Library Subject Stats Strip**
- Subject chip strip appears inside the filter card when you have 5+ notes across 2+ subjects
- Each chip shows the subject name and note count; clicking applies the subject filter directly
- Backed by a new `GET /notes/stats` endpoint; fetch errors silently suppress the strip

**🧩 Public Profile Subject Breakdown**
- Learning Focus section now shows a "X notes across Y subjects" stat line
- Top subject chips link into the creator-filtered Public Library for that subject
- Derived from public notes only; both username and legacy userId profile routes return the new fields

## Library Note Counts
Both Private Library and Public Library now show a live note count near the filter bar — "X notes" at baseline, "X of Y notes" when filters are active. `GET /notes/public` response wrapped in `{ items, total }` to support the public count.

## Polish & Fixes
- Statement 1/2 quiz questions now break each statement onto its own labeled line across all quiz modes
- Matching group prompt constraint strengthened — choices must be identical across all items in the group; any deviation falls back to standard MCQ, reducing demotions at validation time
- Token refresh race condition fixed — concurrent API calls with an expired token now coalesce on a single refresh request instead of each sending the already-revoked token
- Refresh token lifetime bumped from 1 day to 7 days
