# Release Notes: v0.32.2 — Conversion Diagnosis & Quota Honesty

## Release Theme
Diagnose why activated users don't return instead of guessing, turn on the dormant re-engagement loop as a measured retention test, make the exam quota honest — and fix a production stability bug along the way.

## Key Features

**🔍 Conversion funnel diagnosis + honest instrumentation**
- The release opened by reading the real prod funnel rather than guessing. Activation (68.6%) and the value loop (58.8%) are healthy; the binding constraint is **near-zero W1→W2 retention (5.6%, recent cohorts ~0%)**. A flagged "broken checkout" (6 upgrade clicks → 0 `CHECKOUT_INITIATED`) turned out to be a **metric-inception artifact** — checkout works. The full finding lives in `docs/archive/conversion-funnel-finding.md`.
- The Admin Conversion Funnel is now **date-windowed** (default 30 days; 7 / 30 / 90 / all-time, with `windowDays` / `windowStartedAt` in the response) so event stages with different inception dates aren't compared — the exact mistake that produced the false "broken checkout."
- **Free quota-hit is now per-type** (Study Packs, Challenge Quiz, Adaptive Practice, Long Exam, Board Exam, Interview Practice) plus an "any quota hit" aggregate, instead of study-pack-only; Free-unavailable (0-limit) types are excluded from their denominators.

**✉️ Budget-aware re-engagement (the retention lever)**
- The product already had a re-engagement loop, but every user was created with all reminders **off** — so it never fired. New email/password and Google signups now default **inactivity reminders on** (weak-concept, weekly-summary, and marketing stay opt-in); a migration backfills existing users to inactivity-on only.
- A **per-day email budget** (`studysnap.email.daily-limit`, default 100) sends re-engagement only within the headroom left after a **transactional reserve** (`studysnap.email.transactional-reserve`, default 40), computed from same-day `email_log` sends. Un-sent candidates roll to the next daily run; a kill switch disables re-engagement without touching transactional email. Verification/password-reset sends are now logged so the budget sees the full daily pool.
- A **signature-verified Resend webhook** records bounces/complaints into `suppressed_email`, and all sends skip suppressed recipients — so the scarce free-tier email budget isn't spent on addresses that bounce.

**🎯 Quota honesty via per-session deduction**
- Long Exam and Board Exam now deduct **1 unit per session** instead of per source note, so the existing "12 / 10 sessions" plan copy is literally true and more generous — **without changing the numbers or the monthly reset**. The source count still drives question-count and multi-note generation; prescreens read "uses 1 of N remaining" and no longer block a multi-note exam when one session remains.

## Polish & Fixes
- **Backend OOM fix (production stability):** the container ran `java -jar` with no memory flags, so the JVM capped the heap at ~25% of the 512 MB Render Starter (~128 MB) while Spring Boot's default 200 Tomcat worker threads consumed native memory and starved it under load (all JSONB payloads measured KB-scale, ruling out a "fat query"). Fixed with `-XX:MaxRAMPercentage=50.0 -XX:+ExitOnOutOfMemoryError` and `server.tomcat.threads.max=25` (from 200). Confirm via Render's memory graph over several days.
- **Read-path defense-in-depth:** dashboard and retention aggregate reads now use scalar / session-metadata projections that omit the heavy `session_state` JSONB; account-data export streams completed sessions in bounded batches instead of one unbounded entity list.
- **Plan-launch prescreen polish:** "Choose another mode" is hidden on Long Exam / Board Exam / Interview Practice prescreens when launched from a Study Plan — there's no mode grid to return to, and the back link already routes to the plan.
- **Signup email-typo suggestion:** a soft "did you mean gmail.com?" nudge catches mistyped domains (e.g. `0gmail.com`) that pass HTML validation but bounce, protecting deliverability and sender reputation.
