# Release Notes: v0.54.1 — Public Note Copy Correctness Fixes

## Release Theme

Two small, independent correctness fixes to the public-note copy flow, surfaced while validating a report against the shipped behavior rather than invented from scratch.

## Key Features

**🔁 Copy Idempotency Backfill**
- Re-copying a public note no longer returns a permanently pack-less draft. If your existing copy predates the source note's Study Pack becoming ready, copying again now backfills the Study Pack onto that same copy instead of handing back the stale draft forever.
- Honors the same `includeStudyPack` flag the initial-copy path already respects — no behavior change when a pack was never requested.

**👤 Owner-Aware "Quiz yourself" CTA**
- The public note detail page's "Ready to quiz yourself?" card no longer shows to the note's own owner. It was rendering unconditionally, so an owner clicking it on their own public note was forced through a redundant copy-and-regenerate cycle on content they already had ready.
- Owners now rely on the existing `Open Note` action (already correctly gated on ownership elsewhere on the same page) to go straight to their real note.

## Polish & Fixes

- Corrected a stale `ROADMAP.md` backlog row describing a duplicate "Browse {Hub} hub →" link on public note detail as unresolved — it was already fixed in prior consistency work; no code change needed, doc only.

## Known Limitations

- A user-reported issue — the AI-suggested-metadata modal appearing to flash and auto-bypass during a manual Generate → Quick Review flow on a self-copied note — was investigated but not confirmed or fixed. Static tracing of the generation-completion state machine didn't reproduce the reported mechanism for this specific flow. Tracked in the Backlog Index pending live reproduction.
