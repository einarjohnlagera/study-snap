# Release Notes: v0.51.0 — Read-Path Performance Pass II

## Release Theme

Fix production slowness on Private Library, Public Library, Note Collection detail, and the Dashboard — bounding unbounded backend queries and flattening sequential frontend waterfalls, following the same discipline as v0.38.0's Read-Path Optimization Pass.

## Key Features

**⚡ Real Backend Pagination for Private Library**
- `/library` moves from "load every note once, filter and slice client-side" to true server-side pagination: a new owner-scoped `GET /notes/library` endpoint pushes search, readiness, course/program, tag, and visibility filtering into SQL, with five orderable sort modes.
- The frontend now renders 20-note pages and appends real backend pages through `Load more`, with stale list, pagination, and poll-refresh responses all token-guarded. Filter-wide selection (e.g. bulk actions across every matching note) uses a dedicated matching-id endpoint capped at 1,000 ids, with an explicit warning when quiz-readiness counts only cover the currently loaded window.

**⚡ Real Backend Pagination for Public Library**
- `GET /notes/public` gained an opt-in paginated mode covering search, audience, creator, subject, course/program, tags, Study-Pack readiness, and author-source filters, plus authoritative `recent`, `title`, `featured`, `popular`/`copied`, `views`, `most_copied`, and decay-ranked `recommended` ordering — chosen directly over a simpler cap-and-load-more stopgap. A new lean `GET /notes/public/discovery-sections` endpoint computes the homepage's Featured/Popular/Recent sections without holding the whole public-note table in memory.
- `/public/library` now consumes both contracts: 20-note server-filtered/sorted pages with guarded `Load more`, and a new `GET /tags?scope=public` facet endpoint so the tag picker keeps showing every public tag, not just what's on the current page.

**⚡ Dashboard & Collection Detail Query Reduction**
- Dashboard-overview's two unbounded history scans (every completed quiz session ever, and every Study Pack ever for Board-Exam pacing) are now lean, bounded SQL projections — byte-identical responses.
- The Dashboard's Stage 2 fan-out is gone: the Teacher branch now derives entirely from data already loaded in Stage 1, and the Student/Board-Exam/Professional branch replaced up to 4 per-note requests with one batched endpoint.
- Note Collection detail now publishes its Wave 1 state before awaiting the conditional Goal-detail request, so concept counts and plan readiness start immediately instead of waiting in a waterfall.

**⚡ Two-Tier Library Polling**
- The Private Library's background auto-refresh poller now checks a lean id/status endpoint every tick, only re-running the fully enriched note list when a row actually appears or a generating note resolves — instead of re-fetching everything on every tick.

## Polish & Fixes

- Private-note list responses (`GET /notes`) dropped the unused full `content` column in favor of a lean projection with a bounded preview, and gained an optional `limit` param for future callers.
- Fixed a pre-signoff pressure-test finding: `sort=RECENTLY_REVIEWED` on `/notes/library` was running the same unbounded quiz-session history scan twice per request; it now reuses the already-computed result.
- Fixed a pre-signoff pressure-test finding: `/public/library`'s "Load more" button could get stuck permanently disabled if a filter/sort change landed while a page request was in flight.
- Fixed a pre-signoff pressure-test finding: `/library`'s background poller could silently drop rows loaded via "Load more" beyond its 100-row refresh cap without adjusting pagination state, permanently skipping a gap of notes on the next "Load more."

## Known limitations

- Public Library's engagement-ranked sorts (`featured`, `popular`/`copied`, `views`, `most_copied`, `recommended`) still scan every base-filter-matching candidate to aggregate copy/like/share/view counts before selecting a page — full owner/quiz/Study-Pack enrichment is now bounded to one page, but the engagement-count scan itself is not. Watched for post-release production evidence before considering client caching or denormalized counters.
- Public Library's "More Filters" no longer narrows subject/tag suggestions by a draft Course/Program selection — pickers now show the complete server-owned facet lists instead of rebuilding a co-occurrence map from an unbounded client array. The selected Course/Program still filters actual results server-side.
- A theoretical content-preview mismatch: SQL-side content truncation (first 2,000 characters) happens before whitespace normalization, which could in principle diverge from the old full-content-then-normalize order for a note with unusually long leading whitespace. Judged negligible; not fixed.
