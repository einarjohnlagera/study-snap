# Release Notes: v0.136.0 — Contribution Surface

## Release Theme
Your Impact becomes a real destination at `/impact`, and stops costing a 1,587-record database read on every Settings page load.

## Key Features

**📊 Your Impact has its own page**
- `/impact` is a private, authenticated destination rather than a section buried on your Public Profile
- Notes that helped learners come first; notes with no activity yet stay collapsed under *Other published notes*
- Public Profile keeps a compact owner-only `View impact →` card — visitors see nothing new, and never did

**⚡ The impact read is bounded**
- Loading Settings no longer pulls every public note you own to answer a single yes/no question
- Impact now loads a page at a time, sorted by learners helped, with the per-note view and copy lookups scoped to that page
- A new lightweight summary endpoint returns just the two numbers Settings and the page headline actually need

**🔒 The privacy contract is unchanged and now guarded**
- The impact API still accepts no user identifier of any kind — identity comes from your session, and `/impact?userId=…` is not a request that can be expressed
- A test asserts the *absence* of that input rather than a rejection, so a build that added the parameter and then blocked it would fail

**✍️ Copy that matches what the numbers mean**
- Views are labelled **page views**, because public note traffic is anonymous and can never be counted per person
- *No learners yet* is replaced by *Your shared notes are ready to help someone learn.*
- Accounts with nothing published get *Share what you know.* and a route into the existing Library flow

## Polish & Fixes
- The Knowledge Impact digest email's `View Your Impact` button now opens `/impact`; it previously linked to an anchor on the Public Profile that no longer shows a dashboard
- `Load more` on the impacted list now shows a failure message and offers a retry instead of failing silently
- Section totals refresh from each page response, so `Load more` cannot get stuck requesting pages that come back empty
- Paging inputs are clamped server-side, so an out-of-range page or size cannot produce a server error
- The zero-impact list is not fetched until the section is expanded, and the disclosure control is keyboard-operable and not hover-dependent
- Mobile card layout and two-column grid behaviour are preserved
- Impact ordering breaks ties by note id alone, keeping pagination stable across pages
- The notification design's deep-link matrix now points impact milestones at `/impact` instead of `/progress`
