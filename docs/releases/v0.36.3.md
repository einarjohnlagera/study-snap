# Release Notes: v0.36.3 — OCR Fast-Follow: Messaging & Feedback

## Release Theme

Complete the OCR-disable story from v0.36.2: tell users honestly when image/scanned-document reading is off, everywhere it's off, and ask if they want it back.

## Key Features

**🔔 Consistent "OCR Temporarily Unavailable" State**
- Added a shared notice component used identically across all three OCR-gated flows: New Note/Edit Note upload, bulk import, and the photo-to-Study-Pack quick capture.
- Bulk import treats each failed file independently — an OCR-disabled file gets the paused-feature treatment while a sibling failure in the same batch still renders as a normal error.
- A lightweight "Yes, I'd like this back" affordance on the notice, tracked through analytics so real demand is visible before OCR is ever re-enabled.

## Polish & Fixes

- Fixed a real bug: New Note/Edit Note upload was swallowing the backend's actual "temporarily unavailable" message into a generic "We couldn't extract text from this file" failure. It now surfaces the real message.
- No change to the v0.36.2 kill-switch itself — `studysnap.ocr.enabled` stays the single source of truth; this release only changes how the frontend responds to it.
- Adopted a new rule to prevent Codex prompt files from being committed to the repo going forward — they're local planning material, not a shipped artifact.
