# Release Notes: v0.80.0 — Instrumentation Integrity

## Release Theme

The usage data behind the next round of product decisions should actually reach the database.

## Key Features

**📡 Analytics survives an expired session**
- Tracking calls now refresh the access token and retry once, instead of being discarded while the action they describe succeeds
- A failed refresh gives up quietly and never signs anyone out — analytics can't interrupt a working session
- Events fired as a page is closing keep their existing best-effort delivery

**💾 Analytics survives a deploy**
- Queued analytics work is now flushed on shutdown rather than dropped, so a release no longer discards whatever was waiting to be written
- Draining is capped at 20 seconds, so analytics can never delay a deploy

**🏷️ Catalog names match their filter chips**
- A Course / Program added to the catalog is now stored in the same form the Public Library filter renders, so a newly added program's chip finds its notes
- Existing catalog entries are untouched

## Polish & Fixes

- Repaired four tests that passed for the wrong reason, each verified to fail against the behaviour it is meant to protect
- Added coverage for a genuine plan recommendation still rendering where only the fallback pointer is suppressed
- Wrote the September measurement queries ahead of their due dates and confirmed every metric is computable

## Known Limitations

- The loss this release fixes was inferred from the code rather than measured, so a dated check is recorded to confirm delivery volume actually changed
- Roughly three days of one open measurement window ran on the old delivery behaviour, and that is noted where it will be read
- One test guard could not be meaningfully exercised, and that is recorded rather than covered by a test that would pass either way
- In-flight Study Pack generation is still lost on deploy; that needs a different fix from the one applied to analytics and is tracked separately
