# Release Notes: v0.100.0 — Domain Context Resolution

## Release Theme

Curators can now see which authoring domain a note will actually generate under, and the product stops deciding that from whoever happens to be logged in.

## Key Features

**🧭 The writing domain is shown, not guessed at**
- Curator authoring screens now state the outcome plainly — either the domain a note will be written in, or that it needs attention
- It is the same value the generator itself uses, read from the same place, so what you see and what the AI is told cannot drift apart
- It never explains *how* it got there: the answer is the point, not the chain of rules behind it

**✍️ The same note now writes the same way, whoever curates it**
- A canonical note with no domain of its own used to fall back to the curator's own account setting, so two curators could generate the same note and get different instructions
- That fallback is gone for curated material. Personal notes keep it, because for your own material your own context is the right answer
- The empty option now reads *"Automatic — use note context"*, which is only true because the fallback went with it

**📝 A note can be saved before it is ready to generate**
- Setting several programs on a note without saying which domain to write in used to be refused at save, mid-authoring, with work in progress
- It saves now. The question is asked when you generate, which is the moment it actually matters — and nothing is spent before you answer it
- Every generation path enforces it, so the answer cannot be skipped by a different route

**🌐 The public library build is unblocked**
- The catalog had grown past a hard caching limit, and past it every published page re-fetched the entire catalog during a build until the whole deploy failed
- Pages now ask for only the notes they need. The one place that genuinely needs everything reads it in pages
- This had been failing on every branch since 31 August, so nothing could ship until it was fixed

## Polish & Fixes

- Guidance for the Engineering Mathematics authoring domain now states the rule it was missing: it is for notes that *teach* a computational method, not every note that happens to use one
- The Applicable Programs helper text now says what those programs do and do not decide — they control where a note is found, not how it is written
- The admin Applicable Programs screen no longer claims that editing programs leaves a note's writing domain untouched; for a note relying on Automatic, the program *is* the writing domain
- Curator authoring choices are now recorded, so a September review can tell whether the automatic domain was accepted or overridden — a question that could not be answered afterwards from any existing data
- Four separate copies of the same "is this person a curator" check were consolidated into one, with the rule that nobody curates mid-signup preserved at every call site
- Every scheduled background job's timezone is now pinned by the build, not just its schedule, so a change cannot quietly move when a job runs
- A test whose name claimed to prove that pausing a connection never expires it was renamed to state what it actually checks; the stronger guarantee is proved elsewhere and stays proved
- A note's writing domain is now resolved from the note's owner rather than whoever is viewing it, so an administrator looking at someone else's note sees what that note will really generate
