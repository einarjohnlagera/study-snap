# Release Notes: v0.70.0 — Canonical Knowledge Completion

## Release Theme

Finish what `v0.69.0` started: make the canonical authoring axes correctable after a Study Pack exists, give course/programs a real catalog instead of free text, and stop a note's practice questions being thrown away because of who happens to be reading them.

## Key Features

**✏️ Authoring metadata is correctable after generation**
- Domain Context and Note Learner Level can now be fixed on a note that already has a Study Pack, from Note Detail's inline metadata panel — the only editing surface a generated note offers.
- Previously a mis-set axis was effectively permanent from the UI, which blocked the ADR-001 R4 verification outright.
- Corrections shape the *next* generation only and never touch the existing Study Pack; note content stays locked.
- The panel had been duplicating Subject, Course/Program, Audience and Tags while silently omitting both axes shipped in `v0.69.0`, so it read as a complete authoring surface while missing the two fields that matter most for generation.

**📚 A real course/program catalog**
- `course_programs` and `program_families` now hold 21 curator-approved programs and the `Engineering` family, seeded from a two-stage production vocabulary read rather than transcribed prose.
- Bare grade levels, study goals, subjects, and a program family were deliberately excluded — each with a recorded reason, so a future reader can tell a considered omission from an oversight.
- Nullable catalog references were added to notes and users alongside the existing text, and **no existing course/program value was changed, cleared, or rewritten**. Values with no catalog match simply keep their text.
- The Exam Hub's course/program names now come from the catalog instead of two hand-synced lists that had to be kept identical by hand, with the literal lists retained only as a fail-open fallback so an anonymous hub page can never render empty.

**🎯 Practice questions keep the depth they were written for**
- Question pools and the Challenge Quiz bank now key on the **note's** authored curriculum level rather than the reader's profile level.
- A College-level note's generated questions are no longer discarded the moment a Grade School learner opens it, and changing your own learner level no longer makes your banked questions unclaimable.
- Existing questions are preserved rather than regenerated: the one-time mismatch was measured at 57 of 1,244 ready pools and 5 of 6,235 bank rows, refilled lazily through normal traffic.
- The Redo Missed Questions availability check was threaded in the same change, so the count behind the button and the questions it actually claims can never disagree.

## Polish & Fixes

- A full pre-signoff pressure test (four inventory agents synthesised through an independent review) found four defects that per-PR review was structurally unable to see; all were fixed before shipping.
- Fixed a fail-open fallback that memoised itself permanently: one transient database failure — or a single request arriving before the migration applied — pinned the hardcoded Exam Hub lists for the lifetime of the process, making the new catalog invisible until redeploy.
- Fixed the note update path silently rewriting a note's Target Audience from the editor's current profile, which meant a title fix could quietly change a live Public Library filter value.
- Fixed silent data loss on the inline edit path: because the update endpoint is a full replace and the two authoring selects only render for Teachers and Admins, an ordinary owner saving a tag would have wiped a note's Domain Context.
- The catalog migration now rejects an invalid exam-goal value at write time and records its backfill counts in the deploy log, so a curator typo cannot land silently and a zero-match backfill leaves evidence.
- Fixed Note Detail's Domain Context helper text promising an invalidation that never happens — neither question pools nor the Challenge bank carry a domain column.
- Removed `Medical – Surgical Nursing` from the PNLE hub: it had been configured in two files under comments insisting course/program values must match production exactly, and it matched zero notes, users, and collections.
- Corrected `AGENTS.md` rules that were actively misdirecting work — including one stating that a generated note allows only four editable fields, which this release's own first feature had just made false.
- Recorded the exact program vocabulary in a tracked document. The earlier audit had captured its findings but not its output, so the seed list existed nowhere in the repository.

## Known limitations

- **Correcting a note's learner level strands that note's existing Challenge bank rows at the old level.** They are preserved rather than deleted, and refilled by fresh generation, but they are not re-stamped. The related write path is also not as failure-tolerant as its documentation claims: a duplicate-key collision surfaces at commit rather than being absorbed. Measured at 5 of 6,235 rows today; documented rather than fixed, because the fix belongs in the bank's write path rather than inside a re-keying change.
- **Unstamped pools and bank rows belonging to accounts with no saved learner level behave differently now**, and sat outside the original impact read. 40 ready pools cost one extra regeneration each and then match permanently; 15 bank rows stay unclaimable for their owners. Neither is destructive, and neither was judged to warrant a pre-stamping migration.
- **The R4 verification — whether a broader Domain Context degrades generated content — is still a checkpoint due 2026-08-18, not a completed check.** It requires the release live in production, which this deployment provides. **Bulk authoring must not begin until it passes.**
