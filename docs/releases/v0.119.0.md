# Release Notes: v0.119.0 — Curator Bulk Regeneration

## Release Theme
A curator can rebuild the content of a whole Review Set in one deliberate pass — seeing what it will cost and what it will change before anything is written, and getting an honest account of what happened afterwards.

## Key Features

**♻️ Regenerate many notes in one action**
- Pick notes in the Library and regenerate them together: **Study Pack only**, or **Note + Study Pack**. Up to 50 at a time.
- Each note is still handled as its own atomic operation, resolved from **its own** context — no batch-wide template is applied over your authored titles and tags.
- One note failing never stops the ones after it, and never rolls back the ones before it.
- Available to curator accounts. Teacher curators are metered normally against their own allowance.

**🔎 You see the cost and the consequences before you commit**
- A preflight says how many notes are ready, blocked, or not eligible — with the blocked ones and their reasons behind a disclosure.
- It shows what the batch will spend on **both** meters and what you have left, and warns when a shortfall will stop the batch part-way.
- For the combined scope it names what changes beyond your own library: how many public notes will be updated, and how many active shared quizzes will be turned off so nobody is graded against replaced material.
- A batch that cannot be paid for is refused up front, saying exactly how many notes to remove.

**📋 A receipt that survives the batch**
- Progress is a live count, and the work continues if you navigate away — the batch is server-side, and reopening returns you to it rather than to a fresh start.
- When it finishes you get a per-note account: regenerated, blocked, failed, or skipped, each with its reason.
- A batch stopped early by a restart says so plainly instead of showing progress that will never advance.

**🔁 Retry only what failed**
- Failed notes can be run again in one click, as a new batch.
- Notes that already regenerated are never re-run — that would spend your allowance again and replace good content. Blocked notes aren't retried either; fix what blocked them and re-select deliberately.

**🗂️ Filter your Library by Review Set**
- A new filter axis, so the notes in one Review Set can be selected as a set. Useful well beyond regeneration.
- The note checkbox now has a comfortable tap target for selecting dozens of notes on a phone.

**⚠️ Running out of allowance now says so**
- Regenerating a single note shows what you have left, not only what it costs, and declines a scope whose own meter is empty — Study-Pack-only still works when the topic-note allowance is gone.
- Running out mid-batch is reported as **blocked**, not as a failure, so a retry doesn't invite you to spend units you don't have.

## Polish & Fixes
- Fixed the admin allowance bypass, which did not actually bypass: a second, unconditional quota check ran deeper in the pipeline, so an admin with a full meter had every combined item fail with no reason given.
- Fixed a Review Set filter that matched nothing rendering the empty-library welcome screen, with the control that would clear the filter hidden inside the same screen.
- Fixed the subject filter chips counting across the whole library while the list showed a single Review Set.
- Fixed the regenerate dialog naming the wrong allowance when the Study Pack meter was the empty one.
- Applying a saved filter now clears the Review Set selection, so the restored view is the view that was saved.
- Fixed bulk regeneration being unable to send a single valid request — both calls omitted their content type. Every new endpoint now has a test that issues a real request.
- Diagnosed the earlier report of notes failing to regenerate: the cause was a monthly allowance running out, surfacing as an unexplained failure rather than as a quota message.
