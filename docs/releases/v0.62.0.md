# Release Notes: v0.62.0 — Knowledge Impact

## Release Theme

Give creators a passive, retrospective view of the real impact their published notes have had — "your notes helped N learners" — testing whether recognition can move a community-publish rate that's gone to zero.

## Key Features

**🎯 Knowledge Impact Dashboard**
- A private "Your Impact" section on the creator's own public profile, showing distinct learners helped — weighted toward downstream signal (a copy that led to a genuinely *completed* quiz session), never raw views or copies.
- Backed by a new authenticated, self-only `GET /creator-impact/me` endpoint — deliberately not an extension of the anonymous-servable public profile response, so this owner-private data can never end up in a response shape reachable without auth.
- Nothing comparative, ranked, real-time, or identifying across creators; no streaks, badges, or leaderboards.

**📬 Conditional-Rate Measurement + Opt-in Digest**
- New `KNOWLEDGE_IMPACT_DASHBOARD_VIEWED` and `PUBLIC_NOTE_PUBLISHED` analytics events make the release's own 2026-09-11 checkpoint (did a creator who viewed their impact publish again within 30 days) actually measurable, instead of re-running the original unreadable 3-creator raw count.
- Creators with at least one public note can opt into a monthly email digest reporting new learners helped in the trailing 30 days. Off by default; a zero-learner month sends nothing, avoiding a pity-metric email to a very small creator base.

## Polish & Fixes

- **Official-author predicate fix.** `PublicLibraryRepositoryImpl` and `OfficialChallengeQuizTemplateService` both checked admin-role only when classifying an "official" author, missing the email-based check `PublicProfileService` already used — a three-way inconsistency, not two. Confirmed a no-op against production data today; prevents future drift if a non-admin official-curation account is ever added.
- **Pre-signoff pressure test caught a real correctness bug before it shipped further:** all three "learners helped" queries counted a session as complete based on `completedAt` alone. Long Exam and Interview Practice both set `completedAt` on *forfeit*, not only on genuine completion — so an abandoned session could be counted as "helped," including in a real digest email. Fixed by requiring `status = COMPLETED` on every query.
- Settings now shows a retryable error instead of silently hiding the digest toggle when the underlying impact check fails, matching the dashboard's existing error handling.
- **Also fixed in this release, unrelated to Knowledge Impact:** production had legacy `PREMIUM_MONTHLY_CHALLENGE_QUIZ_LIMIT`/`PREMIUM_MONTHLY_ADAPTIVE_PRACTICE_LIMIT` environment variables still set from before the "Premium" tier was renamed "Pro," silently overriding the current correct Pro quota defaults (200 and 30) with stale ones (50 and 50) on the Settings and Dashboard usage widgets. Removed the legacy fallback layer entirely so an orphaned env var can no longer silently override current behavior.

## Known Limitations

- **The 2026-09-11 conditional-rate checkpoint hasn't run yet.** This release ships the measurement infrastructure, not the result — the actual read (and the kill criterion: a continued-zero or still-collapsed community-publish rate settles "can we create creators" for good) is still ahead.
- **Built and shipped against a 3-creator base**, proceeding despite the feature's own data gate failing. Absolute counts will read very small for a long time — a deliberate, ratified bet, not an oversight. See `docs/product/ROADMAP.md`'s Backlog Index "Knowledge Impact" row for the full reasoning.
