# Release Notes: v0.155.0 — Say What You Checked

## Release Theme

Fixes a real quiz-grading correctness defect a learner caught and reported, and ships the validator
that would have rejected it at generation time.

## Key Features

**✅ Answer/explanation internal-consistency validator (H4)**
- A generated MCQ's answer key can point at the wrong choice while its own explanation correctly
  derives and states a different one — the model gets the underlying value right but reports the wrong
  letter, and nothing previously checked the two agreed.
- A new shared-generation-boundary check catches this for any MCQ whose choices are all numeric/unit
  literals: it rejects the question if the keyed choice's text doesn't appear in the explanation while
  another choice's does, tolerating LaTeX formatting, rounding, and comma variance without misfiring on
  substring collisions (`"5%"` inside `"25%"`).
- A rejected question is retried once; if the retry is also inconsistent, it's omitted rather than
  failing the whole generation. Reachable from every quiz mode — Quick Review, Challenge Quiz, Adaptive
  Practice, Long Exam, Board Exam, and Teacher Generate Quiz.
- This is an internal-consistency check, not semantic verification — it proves the stored key agrees
  with the stored explanation, not that either is factually correct.

**🩹 Production data repair**
- A deterministic corpus scan across all 115,333 production questions found 30 confirmed defects, each
  independently hand-verified from the question's own stated inputs. Realized learner exposure was
  exactly one person, two sessions — every other instance sat in a never-served exam pool or the
  owner's own test account.
- The owner ran the full repair: 12 `study_packs` rows, 14 `exam_question_pool` rows, 10
  `challenge_quiz_question_bank` rows, and — as an explicit, separately-decided exception, not a silent
  side effect — a retroactive correction of the one affected learner's session score and progress
  record.

**🧹 Hardening**
- The LLM structured-output schema now constrains the answer field to a closed enum, matching the
  existing backend contract.
- Removed a dead, hazardous choice-shuffling utility that reordered answer choices without remapping
  the correct index.
- Removed an orphaned database entity/repository pair with zero production rows and zero live
  references.
- A MATCHING question block that escapes its group (an ungrouped singleton) now correctly demotes to a
  standard multiple-choice question instead of silently passing through malformed.

## Polish & Fixes

- Pre-commit audit mutation-verified two safety-critical pieces of the delivery rather than just
  reading them: the substring-collision guard (confirmed genuinely load-bearing) and the MATCHING
  singleton fix (confirmed as the actual new behavior, while a related case from the incident report
  turned out to already be covered by pre-existing code).
- A documentation error discovered mid-repair — the incident audit originally miscounted one pool's
  defect as a duplicate (31 confirmed defects, not 30) — was traced, verified against live production
  data, and corrected across every place it had been recorded.
- Three Backlog Index rows added for explicitly deferred follow-on work: relaxing the prompt rule that
  currently limits the validator's recall on prose-answer questions, replacing the letter-position
  answer contract with verbatim answer-text identity (gated on an architecture decision record not yet
  ratified), and a separate, harder semantic-verification tier this release does not attempt.
