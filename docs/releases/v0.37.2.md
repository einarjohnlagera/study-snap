# Release Notes: v0.37.2 — Plan Data Integrity Hotfix

## Release Theme

Stop a silent data-loss bug that wiped Study Plan metadata every time a subject plan was renamed.

## Key Features

**🛟 Rename-Safe Study Plan Metadata**
- Renaming a subject plan in the Goal Builder used to silently erase that plan's description, course/program, and estimated study hours — the rename sent only a title, and the backend overwrote every other field with an empty value.
- `updateMetadata` now follows true PATCH semantics: it writes only the fields actually included in the request and leaves the rest untouched, so a title-only rename can no longer destroy anything else.
- To intentionally clear a text field, the edit forms now send an explicit empty string; the same `persistCourseProgram` exposure that could wipe a description on a course/program save is closed by the same change.

## Polish & Fixes

- Audited the other metadata PATCH surfaces (note update, profile update) and confirmed they are structurally full-replace and were never exposed to this bug.
- Added regression tests: a title-only update preserves description, course/program, and estimated hours; an explicit empty string clears a text field.
- Investigated a report of an account seeing unexpected plans and found no defect — plan lists are strictly owner-scoped, public listings only ever return published plans, and copies are created only by an explicit adopt action; left unchanged pending a concrete reproduction.
