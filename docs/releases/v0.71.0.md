# Release Notes: v0.71.0 — Applicable Programs

## Release Theme

A note stops belonging to one program: an Algebra note authored once for Engineering Mathematics can now surface under every engineering program that needs it — and onboarding stops assuming every new learner wants to write a note.

## Key Features

**🔗 One note, many programs**
- Applicability is now a many-to-many fact rather than a single text field, so canonical material reaches every program it legitimately serves without being duplicated per program.
- Filters, facets, badges and Public Library program search all read the new relationship, falling back to a note's existing text only when it has none — so nothing that was findable before became unfindable.
- Facet counts can now sum above the note total. That is correct: a note genuinely appears under several programs.
- **No existing course/program value was changed, cleared, or rewritten.** A value the catalog deliberately excludes simply keeps its text and keeps working.

**🧭 Onboarding asks what you want to do first**
- Onboarding is no longer profile collection — it is a router that helps each learner reach the fastest successful study experience available to them.
- Two equal-weight doors, neither ever disabled: study with ready-made materials, or build from your own notes.
- Ready-made study is now open to every profile, not just board takers — a qualifying Review Set was previously unreachable for students even when one existed.
- When no set matches your program, you get a short honest line and a genuine alternative, never a dead end or a disabled button. If availability can't be determined, no claim is made at all — telling someone material doesn't exist when it does is the worse error.
- Your profile type and learning context now save as you enter them, instead of at the very end where a dropped write lost them silently.

**🎯 One program field instead of two**
- "Primary Course / Program" is gone. A single `Course / Program(s)` picker replaces the two-field model across the Note Editor, Note Detail, Create-from-topic and Bulk Generate.
- Learners keep one personal free-text program; teachers and admins pick one or many from the catalog. Which applies is decided by who is authoring, not by a setting anyone has to understand.
- Selecting a Program Family fills in all of its member programs as an explicit, editable selection — a typing shortcut, never a rule that decides applicability behind your back.

**🧮 Math renders as math**
- Quiz questions, answer choices and explanations now render mathematical notation instead of showing raw markup like `\frac{x^3 - 4x^2 + 5x}{x - 2}` mid-sentence.
- Coverage extends to flashcards, memorization, shared quizzes and the public preview an unauthenticated visitor sees.
- Fractions and large operators in a question stem render at full size rather than shrinking to script size against the surrounding words.
- Currency survives: `$10-$20` stays a price range instead of being silently rendered as a subtraction.

## Polish & Fixes

- Fixed an activation-blocking regression this release had introduced: new users on the create-note path were told to "choose at least one course or program" on a screen with no such field, and could not finish onboarding at all.
- Fixed onboarding being uncompletable for every admin account — a curator-role user was asked for catalog selections that no onboarding screen can supply. Nobody curates during onboarding; a completed account is a full curator, unchanged.
- Stopped Identification questions asking for answers that cannot be graded. One shipped asking for an algebraic expression while accepting only prose, so a learner typing the correct formula was marked wrong and echoing the question back was marked right. The rule now applies to every subject, backed by an automatic check on every generation path.
- Fixed the note editor claiming a note was "tailored for" a program while zero programs were selected, with the prompt to fix it hidden behind the same faulty signal — both said the field was done, and saving then failed on exactly that field.
- Fixed the intent router misreporting availability after a page refresh, which could tell a learner their program had no materials and then complete onboarding on that basis.
- Fixed a saved-draft correction where switching profile type silently cleared an exam date the user had already entered — the exact signal retention reporting reads.
- Fixed the "explore related public notes" link sending a value the library filter then dropped, so the destination showed no filter at all.
- A second whole-release pressure test, run by four independent reviewers against the final state, caught a migration that was preserving the very rows it existed to delete. No per-change review could have seen it.
- Corrected nine documents that were actively asserting things this release had made false — including the same rule stated wrongly in three separate places, and an exclusion claiming quiz content wasn't affected when it was.

## Known limitations

- **A learner's personal course/program is never turned into a catalog applicability row**, but an admin editing a learner's note can still create the same effect by hand, and a learner's own edit will not clear it. Closing that properly is an architectural change, not a patch.
- **A learner viewing a copied curated note sees programs they cannot edit**, and is asked for a course/program whose value then has no visible effect on discovery. This touches the ruling that Applicable Programs are a curator concern, so it needs a product decision rather than a quick fix.
- **Bulk Generate still uses the older curator check** corrected elsewhere in this release. Not reachable through the interface, but inconsistent.
- **Applying an AI metadata suggestion can dead-end** on a copy of a curated note for accounts with no saved program, because that surface has no field to correct it on.
- **A failed onboarding completion is not retried.** The user is let through rather than trapped, but the server-side marker stays unset and is masked by browser-local state. Analytics are unaffected.
- **Twenty further findings from the pre-signoff pressure test are carried, not dropped.** Each was re-verified against current code, and none is reachable-and-harmful enough to hold a release this size. Candidates for `v0.71.1`.
- **Two onboarding vocabulary findings remain open.** Onboarding offers programs the catalog does not carry, so a teacher can pick a discipline at signup and later find the note editor silently skipping it — the editor no longer contradicts itself about this, but still cannot explain the gap. Separately, the course/program question at signup reads identically for every profile type, so a teacher is asked for a personal field that does not apply to how they author.
