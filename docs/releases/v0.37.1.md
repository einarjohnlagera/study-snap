# Release Notes: v0.37.1 — Native Memory Hotfix

## Release Theme

Stop the backend's repeated silent restarts on Render by closing two distinct memory-pressure sources, and pick up a handful of Study Plan Builder polish items surfaced along the way.

## Key Features

**🧠 Native Memory Hardening**
- Root-caused repeated silent SIGKILLs (no JVM-level `OutOfMemoryError` ever logged, despite `-XX:+ExitOnOutOfMemoryError` already set) to glibc malloc-arena fragmentation on the `eclipse-temurin:21-jre` (Debian/glibc, not musl/Alpine) base image — native memory the JVM has zero visibility into, growing all day under multiple chatty thread pools.
- Added `MALLOC_ARENA_MAX=2` to the Dockerfile, capping arena count instead of letting it scale with thread count — zero code change, fully reversible via env var.
- Exposed the actuator `metrics` endpoint (heap vs. non-heap, GC pause, thread counts) so a future incident can be diagnosed from live metrics instead of inferred from the presence or absence of an OOM log line.

**🎯 Exam-Pool Kill-Switch**
- A second restart traced to a more direct trigger: `ExamQuestionPoolService.initiatePool()` fires automatically on every Study Pack generation — not on actual Long/Board Exam usage — fanning out to generate a 48-question Long Exam pool and a 24-question Board Exam pool via the same executor. The heaviest concurrent LLM operation in the app, running for zero benefit today since there are no Pro users to consume it.
- New `studysnap.pricing.exam-pool-prewarm-enabled` flag (default `false`) gates the single choke point used by both the eager and lazy-refill paths. A real Long/Board Exam start still works when disabled — it falls through to the existing live/on-demand generation path instead of serving from a pre-warmed pool.

**📋 Builder Polish**
- Subject Plan sections in the Goal Builder now collapse by default on first load, instead of all opening expanded — a plan with 7+ sections × 10+ notes each was unworkable to scan. UX-validated with an independent design review; later refreshes never reseed, so manual expand/collapse survives edits, and a newly created section still opens expanded.
- Added `Expand all`/`Collapse all` controls and a distinct "No notes yet" badge on empty sections, so collapsing never hides a problem the curator needs to notice.

## Polish & Fixes

- Fixed the Dashboard "Recommended Study Plan" card showing a misleading "N Subject plans · 0 notes" for Goal-type plans — a Goal never holds notes directly, so the note count is now omitted for Goal cards rather than shown as a confusing zero.
- Fixed Builder note-row "Move"/"Remove" controls sharing a row with the title on `sm:` breakpoints and up, truncating long titles — controls now always sit on their own row below the title.
- Fixed the "Build" action using the same `Pencil` icon as "Edit," causing visual confusion between two different actions — added a distinct `ListTree` icon.
- An independent review of the Builder collapse feature caught and fixed a real edge case: `loadBuilder`'s dependency on a profile-derived label re-fires a second time for Teacher profiles once auth resolves, which would have re-collapsed a section the curator had just expanded in that window. The seed guard is now keyed by plan ID rather than a plain one-time flag, closing the gap while still reseeding correctly on navigation to a different Goal plan.
