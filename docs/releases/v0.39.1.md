# Release Notes: v0.39.1 — Study Plan Builder Polish

## Release Theme

Fix subject-metadata gaps and improve cold-start adoption discoverability in the Study Plan Builder — surfaced from real usage rather than a planned feature push.

## Key Features

**📝 Description Field on Add Subject Plan**
- `AddSubjectModal` only collected a title before; it now has the same description textarea the top-level "New Review Set" modal already offers, threaded straight through to `createCollection`.
- Frontend-only — no backend or API change, since `description` was already accepted server-side.

**🔗 Course/Program Cascade Fix**
- `updateMetadata` now cascades a newly-set, non-blank `courseProgram` to every direct child collection whose own `courseProgram` is currently blank, without ever overwriting a child's intentionally-different value — the same conservative rule the v0.37.2 clobber-bug fix established.
- This closes a real bug: publishing a Goal already cascaded `visibility=PUBLIC` to its children, but never touched their `courseProgram`, leaving newly-published child Subject plans invisible to course/program-scoped public discovery.

**🧭 Cold-Start Adoption Discoverability**
- An audit of the adoption path found the mechanism worked fine end-to-end once found, but nothing in the actual cold-start path told a zero-notes learner it existed. Two concrete gaps, both fixed:
  - The Dashboard's "Recommended {plan}" card silently rendered nothing whenever a learner's course/program had no matching curated plan. It now shows the same "No curated plans yet, check back soon" guidance nudge `/collections` already had — but only for learners with zero notes, preserving the original anti-clutter behavior for everyone else.
  - The zero-notes empty state (`DashboardEmpty`) never mentioned adoption as an option at all, only "Import files" / "Create a note". It now links to `/collections/published` ("Or start from a ready-made plan instead") for STUDENT, BOARD_EXAM, and PROFESSIONAL profiles.
- `/onboarding`'s locked flow (Profile Type → Study Goal → Input Method → Study Pack Generation → Completion) was intentionally left untouched; the fix lives entirely on Dashboard surfaces every cold-start learner reaches regardless of how they got there.

## Polish & Fixes

- All three changes verified against a real backend and Postgres instance (not mocks) before shipping — including catching a stale-build false alarm where an already-running dev backend predated the cascade fix and briefly looked broken until rebuilt.
- Standalone adoption of a single child Subject plan remains parked: the value it would add is already served by copying individual public notes, and there's an unresolved interaction where `adoptGoal`'s idempotency check would silently re-parent a previously standalone-adopted child into a newly-adopted Goal with no user confirmation.
