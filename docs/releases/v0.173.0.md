# Release Notes: v0.173.0 — Cached Catalog

## Release Theme

Explore's discovery sections stop re-ranking the whole public catalog on every page view, which takes
repeat load off a production database that has been running at its memory ceiling.

## Key Features

**🗂️ Explore discovery rankings cached for five minutes**
- Featured, Most Popular and Recently Added are ranked once and reused as one snapshot for
  300 seconds. Before, every page view re-scored about 2,000 public notes.
- Card counts and your liked state are still read live on every request. A note made private still
  disappears straight away; its section shows one card fewer until the snapshot refreshes.
- Publishing, copying, liking or viewing a note does not refresh the snapshot early, so a section's
  membership and order can lag by up to five minutes. This was a deliberate product decision.
- When many people open Explore at once, they share a single ranking, and while they wait none of
  them holds a database connection.

**🛡️ A stalled ranking can no longer freeze Explore**
- The ranking query is cancelled by the database after 50 seconds, with a 55-second backstop on
  the request side. A failed ranking is not cached, so the next visitor's request retries.
- Before this fix, which landed before the release shipped, one stuck ranking could have held every
  Explore request until the server restarted.
- If the ranking worker's queue is full, requests fail at once instead of piling up.

## Polish & Fixes
- Four Study Pack quiz questions with wrong answer keys (audit detection risk, labor efficiency variance, weighted average cost and straight-line depreciation) were corrected in production across 6 Study Packs. Question order and learners' Quick Review progress were left untouched.
- An independent pre-signoff review tried to disprove the cache's design claims; its stall, test-gap and accounting findings were fixed before release and the rest are recorded as known limitations.
- New tests run the cache against a real PostgreSQL lock and real HTTP requests, including an authenticated one, and fail if waiting requests start holding database connections again.
- The cache logs one line per computed ranking (time taken, hits, misses, failures), which a follow-up check will read after deploy.
- This release ships to production only after the 2026-10-22 database memory-kill read for the previous release, so the two changes can be measured separately.
