# Release Notes: v0.167.0 — Study Journey Purpose

## Release Theme

An architecture discovery about what a Study Journey is for, resolved by the owner and partly implemented — Study Journeys now show exam-specific terminology based on what they actually are, and a learner can finally pick and switch their own exam goal.

## Key Features

**🎓 Exam-aware Study Journey terminology**
- A Study Journey (Study Plan / Review Set / Lesson Plan) that is a recognized licensure Review Set now shows exam-specific terminology — "PNLE Review Set," "ALE Review Set," and so on — derived from the Journey's own catalog program, not only from the viewer's profile type.
- A Student who adopts an official PNLE Review Set now sees it correctly, instead of it being relabeled as a generic Study Plan.
- Library navigation, empty states, and the "new" action stay keyed to the viewer's own profile as before — only the terminology describing a specific Journey changed.
- The terminal exam-mode action (Long Exam vs. Board Exam) was deliberately left untouched: it's a locked, profile-gated contract, and a Journey's own nature correctly does not override it.

**🧭 A real way to pick your exam goal**
- Profile's Study Focus section now has a constrained picker listing every recognized exam, letting a learner deliberately set or switch their exam goal for the first time — previously the only paths were a single auto-suggestion banner or clearing it entirely.
- Picking an exam clears any saved subject focus in the same action, preserving the existing one-goal-at-a-time design.

**🏗️ Civil Engineering joins the recognized exams**
- The Civil Engineering Licensure Examination (CELE) is now a recognized exam goal alongside ALE, PNLE, LET, and CPALE — closing a gap where Civil Engineering's own Review Set existed in the catalog but couldn't be picked as a goal or show exam-specific terminology.

## Polish & Fixes
- Worked all 12 open questions from the "Study Journey Purpose / Learner Goal" architecture discovery into a resolved decision, correcting a stale premise in the original brief along the way (a crude version of both concepts already existed at the profile/catalog grain).
- Verified before implementing that the two shipped fixes are both smaller and better-evidenced than the discovery's own early sizing: the labeling fix needed no new persistence, and true multi-goal support stays explicitly deferred since only 2 production accounts show a pattern it would serve.
- Found and fixed a privacy gap during pre-commit audit: the public collection page was resolving exam terminology by walking to a collection's parent with no visibility check, which could leak a private collection's classification to anonymous visitors. Fixed before it ever shipped.
- Found and fixed an inefficient per-row database lookup during the same audit, batching it into one query per page load instead.
- Read all 6 checkpoint rows left over from the prior session's Render outage, closing 2, partially advancing 1, and marking the remaining 3 as genuinely blocked rather than guessed at.
