# Release Notes: v0.69.0 — Canonical Knowledge Foundation

## Release Theme

Stop the library from being forced to duplicate shared knowledge: one canonical note can now be authored for a body of knowledge that many programs share — an Algebra note written once for Engineering Mathematics, rather than eleven near-identical copies, one per engineering program.

## Key Features

**🧭 Domain Context — a single authoring domain, separate from the program**
- New curated, closed eight-value axis (`Engineering Mathematics`, `Engineering Sciences`, `Civil Engineering`, `Professional Practice & Regulation`, `General Education`, `Professional Education`, `Nursing`, `Accountancy`) that replaces course/program as the LLM's authoritative academic domain.
- Fixes an instruction that was logically unsatisfiable: the model was told to "treat the course/program above as the authoritative academic domain… do not blend in material from unrelated disciplines," which cannot hold once a note applies to eleven programs.
- Adding a value is an architecture decision, not routine authoring — the closed enum makes that a property of the system rather than a rule someone can quietly ignore.
- Normal learners never see it. Their notes resolve through the fallback chain `domain_context` → note `courseProgram` → profile `courseProgram`.

**📐 Note Learner Level — how deep a note is authored, independent of who reads it**
- Notes now carry their own learner level, outranking the reader's profile level.
- Static content (note body, summary, key concepts, flashcards) takes the note's authored depth and **never** falls back to the reader — a Grade School reader can no longer lower a College note.
- Quizzes and exams treat it as the curriculum **floor**: a lower reader level may soften wording and add scaffolding, but cannot lower curriculum, terminology, or difficulty; a higher reader level never raises it.

**✍️ Canonical authoring surfaces for Teachers and Admins**
- Both axes are settable in the note editor, for an entire Bulk Generate batch, and in topic-first generation.
- Bulk Generate matters most here — it is the surface where per-program duplication would otherwise be industrialised at speed.
- An inline advisory warns when a note's Subject exactly matches its Domain Context, since that usually means the subject is too broad to work as a library shelf. Advisory only: it never blocks a save.

**🧹 Legacy level-in-program cleanup**
- 49 notes held a K-12 grade level in the program field, feeding a grade level straight into the authoritative-academic-domain prompt line.
- The 27 unambiguous ones (`Grade School`, `Junior High`) were classified mechanically. The ambiguous `High School` notes were classified **per note from actual content** — six of ten turned out not to be K-12 curriculum notes at all and were deliberately left unclassified rather than guessed at.
- Senior High strand notes gained a level but deliberately **no** Domain Context, because production held Physics notes under both ABM and STEM whose prompts would have become identical.
- No note's existing course/program was cleared, and no published note was withdrawn.

## Polish & Fixes

- Pre-signoff pressure test (two agents plus an independent review) found five defects and all were fixed before shipping — two were blockers that per-PR review was structurally unable to see.
- Fixed silent, permanent data loss: "Edit details" on the note detail page wiped a note's Domain Context and Learner Level, because the update endpoint is a full replace and both payloads omitted the fields. The request type now makes omission a compile error rather than a runtime wipe.
- Fixed the reader's learner level leaking into static content through subject-suggestion guidance, which made two learners generating from byte-identical notes receive different guidance.
- Fixed a static calibration line that referenced a curriculum level the prompt had never emitted.
- Restored the "teacher never chose a Target Level" state, which had been flattened to College and caused the Generate Quiz modal to pre-fill a level nobody selected.
- Fixed `Create from topic` intermittently rejecting valid formula content: a 240-character schema bound and a 28-word validator disagreed, and the prompt stated neither. Quick Recall is now bounded by characters, and the prompt states the bound.
- Fixed the note editor silently submitting the editing author's own profile course/program onto a note that had none, while showing an empty field. Profile values now pre-fill on create only.
- Refreshed the Open Graph share image to the current positioning, re-rendered at the correct 1200×630 ratio, and versioned the filename so cached social previews actually refresh.
- Corrected `AGENTS.md` rules that contradicted ADR-001 and would have misled the next session or Codex prompt.

## Known limitations

- **The `course_programs` catalog + `program_families`, and the question pool/bank re-keying, were deferred to `v0.70.0`.** Both are blocked on production reads the release branch could not perform; the queries are written and verified.
- **The R4 verification — whether a broader Domain Context degrades generated content — is a post-deploy checkpoint due 2026-08-18, not a completed check.** It requires the new columns live in production, which only this release's deployment provides. **Bulk authoring must not begin until it passes.**
- Study Packs generated before this release carry no learner-level signal. That closes only by regeneration, which stays explicitly user-confirmed.
