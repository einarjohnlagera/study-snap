# Release Notes: v0.61.0 — Challenge Quiz Quota Increase

## Release Theme

Raise Challenge Quiz's monthly quota substantially so a learner rarely thinks about running out, and start capturing real LLM spend on that path for the first time so the increase's cost effect is observable rather than blind.

## Key Features

**📈 Challenge Quiz Monthly Quota Increase**
- Monthly limits go from FREE 5 / PLUS 25 / PRO 50 to FREE 20 / PLUS 100 / PRO 200 — a uniform 4x across all three tiers, preserving the existing 1:5:10 ratio.
- A daily-reset model was explicitly considered and rejected: real study behavior is bursty around exams, and a daily cap would force the product to dictate a learner's study schedule.
- Reuses the existing rolling-billing-period tracking as-is — no new quota infrastructure.

**📊 Challenge Quiz LLM Usage Telemetry**
- Challenge Quiz's two real-LLM shortfall paths (session start, "+5 More") now extract and persist model/token usage onto each session, accumulating across a session's full lifetime rather than resetting on each "+5".
- Bank/template-served sessions (an increasingly large share of Challenge Quiz volume since Official template sharing shipped) correctly stay null — no LLM call, no usage to record.
- A usage-extraction failure is caught and logged; it never blocks quiz generation.

## Polish & Fixes

- **`ONBOARDING_V2_ABANDONED` instrumentation fix**, found and fixed while investigating this release's own onboarding funnel data: the event was firing on nearly every onboarding step transition (not just true page-leave) and also leaking with no matching `ONBOARDING_V2_STARTED` on several early-return redirect paths. Both bugs are fixed with a single shared invariant rather than patched site-by-site.
- Quota numbers updated everywhere they were hardcoded, not just the two primary sources of truth — `README.md`, the welcome email templates, and four product/feature docs.

## Known Limitations

- **The new telemetry has no reader yet.** The columns are live, but there's no baseline, threshold, or query against them — nobody is reading this data yet. By design, the columns stay null for bank/template-served sessions, likely a large share of volume; a naive "mostly null" read could be mistaken for "spend is low" rather than "most sessions never call the LLM." Next step: a read of these columns roughly 30 days post-deploy, with that caveat stated up front.
- **Board Exam Mode's own dedicated cap is unchanged, but it shares the counter this release raised.** Board Exam sessions draw from both their own 10-source-note-unit cap and the shared Challenge Quiz counter. The dedicated cap remains the binding constraint in every realistic path (10 units vs. a 200-quiz PRO ceiling), so this release strictly improves Board Exam's effective headroom — not a regression, but worth naming since the two counters interact.
