# Release Notes: v0.31.2 — Analytics Integrity & Funnel Visibility

## Release Theme
The funnel and admin dashboards already existed and the core loop was healthy — so this release fixed the data integrity gaps that were silently distorting analytics and added the retention and monetization visibility needed to see where growth actually leaks. Additive, mostly backend; no new product surface for users.

## Key Features

**🔧 Honest Signup Funnel Data**
- Analytics now persist only after the surrounding transaction commits (via an `AFTER_COMMIT` event listener dispatched off-request), so signup lifecycle telemetry is no longer dropped by referential timing and rolled-back flows never create phantom events.
- Removed the hard foreign key from `analytics_events.user_id` to `users(id)` (telemetry should never fail or drop on referential timing), keeping the column nullable and indexed for reporting.
- Net effect: `SIGNUP`, `SIGNUP_COMPLETED`, and `EMAIL_VERIFICATION_SENT` stop undercounting, so signup-based funnel metrics are trustworthy again.

**🔎 Analytics Event Audit**
- Audited every `AnalyticsEventType` value against its actual fire site (including the `eventType=` / `analyticsEvent=` prop and onboarding tracking patterns) and the admin funnel/summary queries.
- Fixed the one live drop: the share-link events (`QUIZ_SHARE_LINK_CREATED` / `_OPENED` / `_TOGGLED`) were fired by the live feature but missing from the backend enum, so each event was rejected with HTTP 400 and lost — they are now recorded.
- Removed the never-fired `ONBOARDING_V2_GOAL_SELECTED`; the audited event set is now consistent across the frontend union and backend enum, and every admin-referenced event is live.

**📈 Retention & Checkout-Conversion Visibility**
- Admin Funnel now shows a W1→W2 retention cohort (first Study Pack activation, then any activity in the completed week-2 window) with an 8-week cohort breakdown — the first cross-week retention signal in the dashboard.
- A new upgrade → checkout → paid conversion view exposes where upgrade intent dies, backed by a new `CHECKOUT_INITIATED` event fired when a hosted Xendit checkout URL is created or reused (metadata limited to plan type and billing cycle).

## Polish & Fixes
- The checkout-conversion step metric is forward-looking from deploy; checkout arrivals before `CHECKOUT_INITIATED` existed are not backfilled.
- Admin funnel metrics reuse the existing rate/percentage and distinct-user query patterns — no new reporting storage and no migration (the new event is an enum value only).
