# Release Notes: v0.27.0 — Material Import & Collections

## Release Theme
Lower the cold-start barrier for getting existing material *into* NoteLib and let any learner group notes into a reusable, ordered **Study Plan** — one universal spine with profile-aware framing, where the teacher payoff (a combined exam packet) is an added terminal action, not a separate system.

## Key Features

**📥 Bulk Material Import**
- New `POST /notes/import-batch` accepts multiple files in one request and creates one reviewable `DRAFT` note per file, reusing the existing per-file extraction pipeline — profile-agnostic, no new quota
- Per-file isolation: one bad file never rolls back the notes already created; failures are reported per file with friendly messages, and a configurable cap (default 20) guards the batch
- A guarded `/notes/import` uploader (reached from the Create-note flow's *Import notes* panel) shows per-file created/failed results and low-confidence warnings, preserves the selection on a failed request, and can drop the new drafts straight into a Study Plan
- Never auto-generates Study Packs or auto-assigns collections — import creates drafts only, preserving the explicit-generation rule

**🗂️ Note Collections (Study Plans / Lesson Plans / Review Sets)**
- New owner-private `NoteCollection` entity + ordered item join table with full CRUD under `/collections` — a *playlist over existing notes*, not a new content type, with no collection-level AI, generation, or quota
- A note can belong to many collections; deleting a collection never deletes its notes; dedupe, reorder, and per-item labels (week/topic) are all supported
- Profile-aware presentation through one resolver (`lib/collection-labels.ts`): the same entity reads as a **Study Plan** (student), **Review Set** (board exam), **Lesson Plan** (teacher), or **Collection** (professional) — never forked per profile
- `/collections` list + `/collections/[id]` detail with drag-reorder (plus Move up/down fallback), an in-detail note picker, per-item labels, and per-note Study Pack readiness; `COLLECTION_CREATED` analytics fire server-side on create

**🎓 Teacher Lesson Plan → Exam Builder**
- A teacher's Lesson Plan flows into Exam Builder via `collectionId`, **pre-seeding editable exam sections from the collection's item labels** — one section per distinct label in collection order, unlabeled notes in a trailing default section, empty sections skipped
- Quiz-ready filtering, partial-readiness hints, and a disabled empty state when no notes are quiz-ready; DOCX export and shareable quiz links stay Teacher/Admin only — universal import and collections do not widen those gates

**🚀 Profile-Aware First-Run Activation**
- The zero-notes dashboard empty state now teaches the loop per profile (teacher: import → generate → group into a Lesson Plan to export/share; student/board/professional: import or create → generate → study/quiz)
- Every variant surfaces both the `Import files` and `Create a note` entry points, with the collection term resolved through the shared label resolver — no new tips framework

**🧭 Library Create Split-Button**
- The Library header is now one split button: primary **New Note** (one click) plus a caret menu (`Note` / `Import files` / `{Study Plan}`)
- `{Study Plan}` enters Library selection mode — *pick notes with the full filter suite, then create the plan* (empty plans allowed) — and teachers reach **Build exam** from the same selection; the Study Plan detail's "Add notes" picker still handles adding to an existing plan

## Polish & Fixes

- Send Feedback is locked to the header on every page (matching production); removed the route-split that had it floating on non-learning routes, and auto-hidden only in distraction-free exam focus where the header itself is hidden
- Slimmed the Library `New Note` split button to the compact size to match the app's other CTAs
- Progress goal card clarity: the subject-focus header reads `Study Focus` (was `FOCUS Goal`) and the edit affordance is explicit (`Edit in Profile`, was `Change goal`) — Profile remains the single Study Focus/Goal editor
- Documented that Study Plans (durable organizer) and saved library filters (transient quick lens) are distinct and both intentionally kept
- Cleaned up a backlog of stale frontend test failures on the release base (react-markdown ESM transform, incomplete API mocks, a stale long-exam quota mock, and copy-drift snapshots) so the suite runs green
