# Release Notes: v0.33.3 — Recursive Goal Adopt

## Release Theme
Close the curated-plan adoption gap: learners can now adopt a multi-Subject Goal plan as a single unit, receiving the full Goal → Subject hierarchy and all notes as personal editable copies in one action.

## Key Features

**Recursive Goal Adopt**
- New `POST /collections/{id}/adopt-goal` endpoint creates a personal Goal collection and recursively copies every child Subject plan and its notes into the learner's library
- Adopted notes are the learner's own copies — freely editable and removable immediately, consistent with the Study Pack copy-and-edit principle
- Adopting the same Goal twice is idempotent: returns the existing personal Goal with `alreadyAdopted: true`
- Collision handling: a child Subject already adopted as a standalone plan is re-parented under the new personal Goal; a child already nested under another personal Goal is skipped rather than duplicated
- `AdoptGoalResponse` carries `goalCollectionId`, `adoptedSubjectCount`, `skippedSubjectCount`, `totalNotesCopied`, `totalNotesSkipped`, and `alreadyAdopted`
- `PublicStudyPlanCard` and `DashboardStudyPlanSection` detect Goal vs leaf via `childCount > 0` and route to `adoptGoal()` with Goal-aware CTA labels ("Start this Goal" / "Continue this Goal")

**Goal Publish & Discovery Rules**
- Publishing a Goal now validates that every child Subject plan has at least one public note; Goals with zero children or an empty/all-private child are rejected with a specific error
- Publish cascades to all child Subject plans (sets them to PUBLIC); unpublish does not cascade — children retain their visibility
- Public plan listing (`/collections/published`) is now root-only: child Subject plans no longer appear as standalone cards after a Goal publish cascade

**Goal Adopt Analytics**
- `STUDY_GOAL_ADOPTED` added to the backend `AnalyticsEventType` enum and frontend union type before firing
- Event payload carries adopted/skipped Subject counts, copied/skipped note counts, and source Goal id

## Polish & Fixes

- `validatePublishable` refactored to detect Goals via `countByParentCollectionId > 0` and route to child-by-child validation; leaf path is unchanged
- `NoteCollectionRepository` gains two root-only Spring Data derived-query methods with `parentCollectionId IS NULL` for public listing
- `publishChildCollections` helper batch-saves child visibility update via `saveAll` in a single call
- `persistAdoptedGoal` mirrors `persistAdoptedPlan`: `saveAndFlush` inside `collectionTransactionOperations.execute()` with `DataIntegrityViolationException` race recovery
- 18 new backend service tests covering Goal adopt (happy path, idempotency, collision, race recovery, private/leaf source rejection) and Goal publish (cascade, no-cascade unpublish, validation guards)
