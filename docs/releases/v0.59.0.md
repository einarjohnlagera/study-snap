# Release Notes: v0.59.0 — Dashboard & Progress Reorg

## Release Theme

Reorganize Dashboard and Progress around the learner's Primary Review Set now that quiz content has something stable to point at — Challenge Quiz and Board/Long Exam stopped regenerating every session in v0.58.0, so Progress and Dashboard can both give the Primary Review Set a first-class, persistent presence instead of treating it as an afterthought.

## Key Features

**🎯 Primary Review Set Dashboard Hero**
- Dashboard now resolves the learner's `primaryCollectionId` and, when one is set, places a condensed card above all existing sections: identity, current step, one `Continue Studying` action, and overall readiness percentage — reusing the existing v0.41.1 Review-Set-detail hierarchy at summary depth.
- Shows a purpose-built skeleton while the read is pending, and falls back to the existing goal-prompt flow if the read fails or resolves nothing. No `primaryCollectionId` set → completely unchanged existing behavior.
- Purely additive: no existing Dashboard section, link, or route was removed, reordered, or repointed.

**↩️ Progress Promoted to a First-Class Destination**
- Turned out to be mostly already shipped: `/progress` and `/collections` ("My Reviews") were already unconditional primary-nav entries for every profile type. The real gap was page-level — `ProgressHeader` still carried a leftover unconditional "← Dashboard" back link from when Progress was documented as a sub-page.
- Fixed: the default back link is removed; the contextual "reached via a specific plan's `Check readiness` deep-link" back link is unchanged. `navigation.md` corrected to list Progress among the main pages.

**🔁 Adopt-Sets-Primary Default**
- A learner with no Primary Review Set who adopts a plan or Goal now has that adoption set as Primary — even if they already own other top-level collections. Previously this only happened by coincidence, when the adopt happened to leave the user with exactly one top-level collection total.
- Scoped strictly to the adopt/adopt-goal paths; the shared invariant's behavior at its other call sites (collection delete, parent-reparenting) is untouched. Never overwrites an existing primary; Goal adoption always targets the top-level Goal, never a child Subject plan.

## Polish & Fixes

- Fixed a cross-cutting bug caught during the pre-signoff pass: `GET /collections/{id}/goal` reported 0% readiness and 0 concepts for a childless top-level collection (a standalone adopted plan with no child Subject plans), since its totals were computed only by summing over children. Adopt-sets-Primary made a childless plan a routine Primary, and the new Dashboard hero surfaced the resulting misleading "0% ready" card prominently. Fixed by deriving totals from the collection's own direct items when it has no children, reusing the same computation `GET /collections/{id}/readiness` already uses — Goals with children are completely unaffected, and both the Dashboard hero and Progress's existing primary-default view now show accurate readiness with no frontend change needed.
- Corrected a stale scope assumption from the original design doc: Dashboard never had a subject-by-subject stats block to relocate to Progress — that rollup has only ever lived on Progress, fed by a separate endpoint. The Dashboard hero work was purely additive as a result.
