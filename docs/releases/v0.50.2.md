# Release Notes: v0.50.2 — Note Card Content Consistency

## Release Theme

Every note card across the app — public and private — now shows one honest preview excerpt instead of an inconsistent mix of layouts, and the "back to Public Library" link now remembers where you were browsing from.

## Key Features

**📇 Consistent Note Cards Everywhere**
- All seven surfaces that show note-card previews (private Library, Public Library, Dashboard, public profile, public note detail's two related-notes sections, the subject-landing page, the Exam Hub, and the post-quiz "More from" suggestions) now follow one shared rule: show the note's own preview when it's substantial, otherwise a clearly labeled Study Pack summary — never both stacked.
- Retired three independently hand-rolled card layouts that had drifted out of sync with each other over time, including one that showed the summary in place of the note even when the note preview was perfectly good.

**🔗 Filter-Aware "Back to Public Library"**
- Opening a note from a related-notes suggestion, a subject page, or an Exam Hub page and then tapping "← Public Library" now returns you to that same filtered view instead of resetting to the full unfiltered list.

## Polish & Fixes

- Public note detail's two related-notes sections now link out with consistent wording ("See all in {Subject/Course}").
- Corrected a leftover doc description of the retired two-preview card layout.
- Added direct test coverage for the shared note-card preview logic, which previously had none of its own despite being used everywhere.

## Known limitations

- A "Browse {Hub} hub" link can appear twice in a row on a public note detail page for course/programs that map to a board-exam hub (once in a callout banner, once in the related-notes section below it) — cosmetic duplication, not fixed this release.
- Origin-aware card treatment (showing a note differently depending on whether it was hand-written or AI-generated) was considered and explicitly rejected as a future direction, not deferred for lack of time — see the Backlog Index for the reasoning.
