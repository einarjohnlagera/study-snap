# Release Notes: v0.64.0 — Add to Review Set

## Release Theme

Close a genuine capability gap surfaced while wrapping up v0.63.0's Companion signoff: a learner reading a Note who wants it organized into a Review Set had no way to do that without leaving the page.

## Key Features

**📥 Add to Review Set from Note Detail**
- A new "Add to {Review Set}" action in Note Detail's overflow menu lets a learner add the note they're viewing to an existing or brand-new Review Set without leaving the page.
- Reuses the same add/create flow Bulk Import already shipped, now extracted into a shared component so both surfaces stay in sync as that flow evolves.
- User-initiated only — no recommendation, nudge, or coverage claim attached; it does nothing until a learner opens the menu and chooses it.

## Polish & Fixes

- Corrected `docs/features/companion.md`'s framing: Companion content is admin-authored-Official-collection-scoped (every write path is `assertAdmin`-gated), not "Review-Set-scoped" — a structural fact about who can author it, not a permanent stance on where it can appear. Recorded the three-layer guidance model (content explanation / diagnostic guidance / editorial guidance) alongside it.
- Folded "what does a no-Review-Set learner's guidance surface look like" into the existing, still-open Primary-Review-Set-vs-Study/Exam-Focus roadmap question rather than opening an uncoordinated second answer to it.
- A single pre-signoff `advisor()` check (this release's size didn't warrant the full multi-agent pressure test — one PR, frontend-only, no shared-method collisions) found that the extracted modal's `itemNoun` copy prop defaulted to Bulk Import's wording, which a future third caller could silently inherit by omission. Made the prop required instead, with no default, before signoff.
- A separate, larger architectural question arrived mid-release — whether "Ask Companion" should evolve into a cross-cutting "Companion" guidance system spanning Dashboard, Review Set, Progress, and Readiness. Pressure-tested with Opus against the real codebase and resolved as considered-and-narrowed: the underlying taxonomy ("one learning responsibility per feature," "one question per surface") is adopted as authoring doctrine, but the literal system merge and rename are rejected — "Companion" today names three structurally different things, and merging the name would create real user-facing confusion rather than coherence. No code shipped from this; recorded as its own phased, gated future item in the roadmap, confirmed orthogonal to everything else in this release.

## Known Limitations

- None.
