# Release Notes: v0.138.0 — Stated and Enforced

## Release Theme
Four notes could not be regenerated no matter how many times you retried, because the AI was being judged against a rule nobody ever told it — and the failure log never said what went wrong.

## Key Features

**🎯 The title rule the AI is judged by is now a rule it can actually read**
- Note generation rejected any AI-written title over 12 words, while the instructions it was given mentioned no word limit at all — only a character cap and "be concise and specific"
- The limit is now stated in the prompt, alongside the two limits that were already published there
- The limit itself was **not** raised: 12 words stands. The model is simply told the number it is measured against
- Four board-exam notes had failed seven times between them, and retrying was not a workaround — the same three failed identically on a retry batch

**🔍 A rejected generation now says what it rejected**
- The old log recorded only that generation failed. It never recorded the offending text, its length, or which rule broke — so four notes failed seven times and produced no evidence of what was wrong
- Failures now name the field, which check failed, the measured word count, the limits, and the offending value (truncated)
- This applies to every generated field, not just the title, so the next unexplained failure is resolvable in one read instead of an investigation

**📋 The backlog was checked against the code for the first time**
- Four entries claimed work was still outstanding when it had already shipped — one of them for 41 releases, and it had been offered up as a candidate for the *previous* release
- Two of the four were catchable for free: the entry contradicted itself, with one column saying "shipped" beside another saying "not shipped"
- Nineteen entries were missing a column entirely, which meant the review ritual could never have reached them

## Polish & Fixes
- Published the title limit as a template value, so it can never drift from the number the code enforces
- Every surviving backlog entry now points at the specific file and line that backs its claim; entries that cannot be checked from code say so, with the reason
- Recorded that a stale backlog entry costs a whole release, because the backlog is what release scope is chosen from
- Added a standing rule that claims about shipped code go stale exactly as fast as claims about production, and must be re-read before they are repeated
- Flagged the four failed notes as still needing a re-run — the fix targets the probable cause, and only that re-run can confirm it
