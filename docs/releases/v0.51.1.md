# Release Notes: v0.51.1 — Dashboard Stage-1 Limit Wiring

## Release Theme

Close the last unbounded read-path left over from `v0.51.0 - Read-Path Performance Pass II`: Dashboard's Stage-1 note fetch now uses the bounded `limit` param F2 already built, on the app's single highest-traffic page.

## Key Features

**⚡ Dashboard Stage-1 Bounded Fetch**
- Dashboard now requests only the 20 most-recently-updated owned notes via the existing `GET /notes?limit=` path, instead of loading every owned note on every visit.
- Three behaviors that previously required the full unbounded array now come from the existing `GET /dashboard/overview` response instead — no new endpoint: the exact total owned-note count (Recent Notes totals, empty states), an owner-scoped "has any note with a generated quiz" signal (first-time vs. returning user card ordering), and the id of the most-recently-updated note with a ready Study Pack (Challenge Quiz / Start Board Exam fallback routing, so a ready note outside the bounded page still gets found).
- Recent Notes, Teacher's Ready-to-Export and Generated-Quiz sections, and Continue Studying are unaffected — they were already only ever reading the top few most-recently-updated notes, which the bounded fetch still contains.

## Polish & Fixes

- If `GET /dashboard/overview` fails to load, the three new signals degrade to their old bounded-array equivalents rather than crashing or showing an incorrect empty state.
- Extracted a quiz-question-count SQL expression that existed independently in both the Private and Public Library repositories into one shared utility, used by the new Dashboard signal as well — no behavior change to either Library.
