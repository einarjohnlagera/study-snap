# Release Notes: v0.98.0 — Connection Consistency

## Release Theme

One property, one bar, everywhere — and a connection list that tells the truth about its own history.

## Key Features

**🔑 Accepting an email invitation now requires a finished account setup**
- Invitation links already required it; accepting an emailed invitation did not, even though both create exactly the same connection
- If you arrive mid-setup, you are taken to finish it and your invitation is still waiting when you return

**🧹 Ended connections stop cluttering your list**
- Revoked and expired connections stay visible for a while, then drop out on their own
- Nothing is deleted, and a request that is still awaiting confirmation is never hidden — only the sweep can end one

**🔒 Ending a connection now ends its sharing everywhere, including historically**
- Connections ended before the previous release could still show as sharing, even though no one could actually see anything
- Pausing a connection to re-confirm a guardian's permission deliberately keeps sharing intact, so it resumes when the connection does

**🗑️ A declared birth year is no longer kept once it is no longer needed**
- Someone who redeemed two invitations before either was confirmed kept the second declared year on file after the first was confirmed
- All of them are now cleared the moment the year is recorded on the account

## Polish & Fixes

- The connection request sweep is bounded, so a large backlog is processed steadily rather than all at once, and it can now be configured or paused without a deploy
- A learner deleted while the sweep is running is handled quietly instead of being logged as a failure
- Every scheduled background job can now be disabled during tests, removing the last of an intermittent build failure
- The data model documentation for connections was five releases out of date — it described three connection states where there are four, said that accepting a connection grants access when it has not since `v0.93.0`, and omitted four tables entirely
- A long-standing test that detected a real defect only about one run in five now detects it every time
- An open question from `v0.75.0` about whether it owed a follow-up measurement was answered and recorded rather than left silent
