# Release Notes: v0.93.0 — Progress Refinement

## Release Theme

A supporter can no longer see a learner's progress just because the two of them are connected — the learner decides, per scope and per direction, and can change their mind at any moment.

## Key Features

**🔐 Progress sharing is now an explicit choice, not a side effect of connecting**

- Accepting a connection grants nothing. A supporter sees progress only while the learner keeps a live permission open for them.
- Only the learner can share progress, and it runs learner → supporter. Study activity stays shareable in either direction.
- Turning sharing off cuts access on the very next request — no cache, no grace period. Ending the connection, or a birth-year correction that pauses it, does the same.
- The permission survives a pause, so a learner can always switch their own sharing **off** even while a connection is temporarily inactive — the moment it matters most.

**🎛️ One panel, both directions, honest about each**

- Each connection shows what you share and what the other person shares with you, as separate controls.
- *View progress* now appears only when the learner has actually shared it — on the connections page and on the dashboard.
- A failed change never displays as if it saved: the control returns to the last value the server confirmed.
- A paused connection explains the pause instead of silently hiding the controls.

**🐘 Database queries are now tested against the real database — and it immediately found two live bugs**

- Every hand-written SQL query in the product is now checked against a real PostgreSQL 16 database running the full migration history, on every build.
- On its first run it found **two defects that had been live in production since 19 July**: filtering the Public Library by a tag failed outright, and combining a depth filter with a tag filter mangled the query. Both are fixed.
- These only ever failed on the real database — the previous test setup accepted them, which is how they shipped and stayed hidden for roughly 40 days.

**💬 Meters that explain themselves**

- The *AI quizzes* allowance now says what it covers — Challenge Quiz sessions **and** quizzes you make for someone — in Settings as well as on the dashboard, so it is clear what a quiz for someone else actually spends.

## Polish & Fixes

- Public Library tag filtering works again on PostgreSQL; combining a depth filter with a tag filter no longer breaks the query.
- The connections page no longer claims someone withholds their study activity when it is visible through shared progress.
- The Help Center documents progress sharing, including that only the learner can grant it and that it can be withdrawn during a pause.
- Sharing state is read fresh on every request, so a revoked permission stops working immediately rather than after a refresh.
- A supporter's *View progress* action no longer appears where the underlying request would fail.
- The sharing panel is reachable on a paused connection, so withdrawing consent never depends on the other person's cooperation.
- Added the first test that actually executes the permission-granting database write, after a pre-release review found the whole suite passed with that statement deliberately broken.
- Removed a concurrency test that simulated its own conclusion and proved nothing, rather than leaving it in place as false assurance.
- Added assertions to the PostgreSQL-only library filters, which previously ran without checking their results.
- Tightened the query-verification sweep so it cannot silently cover fewer queries than the product actually has.
- Corrected several internal documentation claims that the release itself had made untrue.
