### Known, owner-accepted limitation (decision E, 2026-11-11)

Between the frontend deployment and the environment save (at least 24 hours) the backend still auto-applies the live `INTRO-PH-*` vouchers at checkout to new Philippine subscribers (`PaymentService.java:102-108` passes no voucher code), so the homepage's plain base (₱179 Plus, ₱249 Pro) is higher than a new subscriber is charged (₱149, ₱199). It favours the customer, ends when the environment save makes the vouchers inert, and was accepted by the owner in place of showing the intro to anonymous visitors, who may be returning subscribers. The pre-existing case remains too: on `/pricing` the backend treats every anonymous visitor as eligible for the intro, so a signed-out returning subscriber can see an intro they will not be charged. Both end at the environment save.

Related, found by the 2026-11-12 cold review and accepted by the owner (D2): a returning subscriber whose access token is expired or invalid is treated as anonymous by the auth filter (`JwtAuthenticationFilter.java:52-77`), so the same intro can also appear on the paywall and in Settings, not only on `/pricing`. The label path was identical on `main`, so this is pre-existing, and it also ends at the environment save.

## v0.180.0 - Public Page Reliability and Privacy

**Status: Deployed 2026-11-11 (T0 10:59:58Z); stabilization pending: the +24 h read is due 2026-11-12T10:59:58Z and the +72 h read 2026-11-14T10:59:58Z; this section says Released only after the +72 h read (code sign-off 2026-11-10).** Kicked off 2026-11-10 on `releases/v0.180.0`, **cut from `main` at `2cf895f6`** after `v0.179.0` was signed off, merged (#1573) and tagged, and `v0.176.0` and `v0.177.0` merged (#1547); **frontend only, one merge, one separately approved deploy; not deployed as of the 2026-11-10 sign-off commit.** The scope below is BUILT and VERIFIED and was merged into this branch as #1574 (`847c30d8`, 2026-11-10T11:58Z). Theme: creator and profile pages stop serving a withdrawn note, an edited bio or a profile switched to private for longer than two minutes, fail closed instead of showing old data, and show a calm, safe state when they cannot load; the exam hub keeps its notes when only its review sets fail.

### Planned Scope (owner and Product UX decisions 2026-11-08 and 2026-11-09)

- **Creator and profile reads bounded at 120 s (frontend).** Both requests leave the 300 s Next data cache for a separately bounded `profile` partition of the in-process hard-TTL cache: 120 s maximum, single flight, 15 s failure backoff, 15 s deadline, `ok` and `private` cached, `not_found` never cached, no stale value after expiry or failure, its own 512-key bound and failure map so it cannot evict a catalog entry; both routes `force-dynamic`.
- **A calm failure state (frontend).** A route-level `error.tsx` on `/public/creator/[username]` and `/public/profile/[userId]` (heading "We couldn't load this profile", "Try again" = `router.refresh()` plus `reset()`), and a static `Profile temporarily unavailable | NoteLib` head with `noindex` when the read fails. Client-side boundary only: the HTTP status stays 200 and no crawler-visible error handling is claimed.
- **Exam hub degradation (frontend).** When only the review-sets request fails the hub keeps its notes and shows "Official review sets are temporarily unavailable" (no Retry).
- **Dot-segment guard and a comment fix (frontend).** `.` and `..` usernames return not-found without a request (URL normalization would rewrite the backend path); the stale subject-page comment is corrected.
